Tópico 12 · Simulação com stencil

Boa parte das simulações científicas (calor, ondas, escoamento de fluidos, eletrostática) resolve equações diferenciais em uma malha. Cada ponto atualiza seu valor a partir dos vizinhos: esse padrão é um stencil. É um dos kernels mais comuns em HPC e um ótimo caso para GPU, porque é simples, paralelo e limitado pela memória.

Da equação à malha

A equação do calor em duas dimensões, ∂u/∂t = α(∂²u/∂x² + ∂²u/∂y²), descreve como a temperatura se espalha em uma placa. Discretizando o tempo com passo Δt e o espaço com malha de passo Δx, a derivada segunda é aproximada por diferenças finitas. Com Δx = 1 e α absorvendo Δt, o passo explícito vira:

unew(i,j) = u(i,j) + α · (u(i−1,j) + u(i+1,j) + u(i,j−1) + u(i,j+1) − 4 · u(i,j))

Cada ponto interior depende de cinco valores: ele mesmo e os quatro vizinhos. Esse é o stencil de 5 pontos. Para o método explícito ser estável, α deve ser no máximo 1/4 em duas dimensões. O exemplo usa α = 0,2.

Kernel e esquema ping-pong

Cada thread atualiza um ponto. Como o valor novo de um ponto depende dos valores antigos dos vizinhos, o passo não pode ser feito no lugar: uma thread poderia ler um vizinho já atualizado. A solução é o esquema ping-pong: dois buffers, um lido e outro escrito, trocados a cada passo. O resultado de um passo vira a entrada do próximo, sem cópias. 

__global__ void passo_calor(const float *u, float *v, int n, float alfa) {
    int x = blockIdx.x * blockDim.x + threadIdx.x;
    int y = blockIdx.y * blockDim.y + threadIdx.y;
    if (x <= 0 || y <= 0 || x >= n - 1 || y >= n - 1) return;   /* bordas fixas */
    int i = y * n + x;
    v[i] = u[i] + alfa * (u[i - 1] + u[i + 1] + u[i - n] + u[i + n] - 4.0f * u[i]);
}

for (int p = 0; p < passos; p++) {
    passo_calor<<<grade, bloco>>>(da, db, n, alfa);
    std::swap(da, db);            /* a saída vira a entrada do próximo passo */
}

Dois detalhes. Com o índice i = y * n + x, o x é o índice que varia mais rápido, então o acesso é coalescido, como no tópico 8. E as bordas precisam ter o mesmo valor nos dois buffers, senão a borda de um deles seria zero durante todo o cálculo. O exemplo copia o estado inicial para os dois.

Verificação: a GPU concorda com a CPU?

Antes de confiar em um kernel de simulação, compare com uma implementação de referência na CPU que faz exatamente a mesma conta. O exemplo faz isso com a mesma condição inicial e o mesmo número de passos, e reporta a maior diferença entre os dois resultados. Diferenças de arredondamento em float são esperadas; diferenças grandes indicam erro de índice, de borda ou de troca de buffers.

Uma verificação mais forte, usada em pesquisa, é comparar com uma solução analítica quando ela existe. Para a placa com temperatura inicial uniforme e bordas frias, o decaimento segue a série de Fourier, e a comparação mostra também o erro de discretização, não só o erro de implementação.

Arquivo: 12-calor-2d.cu. Malha de 512 × 512, 2000 passos, comparação com a CPU ao final.

Desafio para casa: reescreva o kernel usando memória compartilhada com halo: cada bloco carrega um retângulo com uma borda extra de vizinhos, calcula o interior e escreve. Meça antes e depois com o roteiro do tópico 14 e veja se a economia de leituras compensa a sincronização extra.

Nota: o exemplo não foi executado em GPU neste material. Verificamos apenas a sintaxe e os tipos.

Teste seus conhecimentos

Por que o passo do stencil usa dois buffers em vez de atualizar a malha no lugar?

Correto. A dependência entre vizinhos exige que todos os valores lidos sejam do passo anterior, o que o ping-pong garante.

Por que o α do método explícito precisa ser pequeno (no máximo 1/4 em 2D)?

Correto. O critério de estabilidade limita o passo de tempo em função do espaçamento da malha.
