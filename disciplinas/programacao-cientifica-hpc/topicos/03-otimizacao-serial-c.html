Tópico 3 · Otimização serial em C

Antes de criar threads ou usar GPUs, esgote o que a versão serial pode dar. Um programa serial bem escrito costuma ser 10 a 100 vezes mais rápido que um ingênuo, e isso multiplica qualquer ganho de paralelismo que venha depois. A ordem recomendada é: medir, entender o gargalo, mudar o layout de dados, depois mudar os laços, depois vetorizar. Sem medir, não se sabe o que mudar.

Layout: array de estruturas ou estrutura de arrays

Suponha que cada partícula tenha posição, velocidade e massa. A forma natural em C é um vetor de struct (AoS). Mas, se o laço só usa a posição, cada iteração carrega também velocidade e massa, que ocupam a linha de cache sem serem usadas. A alternativa, uma estrutura de arrays (SoA), mantém cada campo contíguo: 

/* AoS: uma linha de cache traz partículas inteiras */
typedef struct { double x, y, z, vx, vy, vz, massa; } Particula;
Particula p[N];

/* SoA: o laço de posições só toca em memória de posições */
typedef struct { double *x, *y, *z, *vx, *vy, *vz, *massa; } Particulas;

A regra prática: se um laço usa poucos campos de muitos registros, prefira SoA. Se usa todos os campos de cada registro, AoS pode ser melhor. O layout deve seguir o padrão de acesso, não a elegância do modelo. Esse é o mesmo raciocínio que volta na GPU, onde a coalescência depende do layout (tópico 8).

Ordem dos laços e blocking

A multiplicação de matrizes C = A × B faz N³ multiplicações. A ordem clássica ijk percorre B por colunas no laço interno. Trocar para ikj faz o laço interno andar em linha em B e em C, sem mudar o resultado. Já o blocking divide as matrizes em sub-blocos de B × B elementos, escolhidos para caber no cache, e reutiliza cada bloco o máximo possível antes de descartá-lo.

Arquivo: 03-matmul-blocking.c

/* ikj: o laço interno é contíguo em B e em C */
for (size_t i = 0; i < N; i++)
    for (size_t k = 0; k < N; k++) {
        double a = A[i * N + k];
        for (size_t j = 0; j < N; j++)
            C[i * N + j] += a * B[k * N + j];
    }

Saída real (N = 512, bloco = 64, Apple clang -O2)

versao      tempo (s)      GFLOP/s   erro max
ijk            0.2808         0.96       ref.
ikj            0.0578         4.65   0.00e+00
bloco          0.0561         4.79   0.00e+00

Dois resultados importantes. Primeiro, a troca de ijk para ikj já dá cerca de 5×, sem nenhuma técnica avançada: a maior parte do ganho é de localidade. Segundo, com N = 512 o blocking praticamente empata com ikj, porque as três matrizes ainda cabem bem na hierarquia de cache e o compilador já faz boa parte do trabalho.

O blocking compensa quando as matrizes são grandes o bastante para não caberem no cache. Experimente N = 2048 no código e veja a diferença crescer. Medir em mais de um tamanho é a única forma de saber se a técnica vale a pena para o seu caso.

Vetorização: deixar o compilador trabalhar

Três cuidados fazem o compilador vetorizar o laço interno:

  • Sem dependência entre iterações que impeça a execução paralela. Um acumulador simples costuma ser reconhecido como redução.
  • Ponteiros que não se sobrepõem: declare restrict quando for verdade, para o compilador não temer aliasing.
  • Laço com contador simples e limite conhecido, sem break no meio.
void soma_vetores(double *restrict c, const double *restrict a,
                  const double *restrict b, size_t n) {
    for (size_t i = 0; i < n; i++)     /* vetorizável: sem dependência entre i */
        c[i] = a[i] + b[i];
}

Verifique com gcc -O3 -fopt-info-vec-optimized ou clang -O3 -Rpass=loop-vectorize. Se o compilador disser que não vetorizou, ele está informando o motivo: quase sempre aliasing ou uma dependência real.

Teste seus conhecimentos

Um laço usa só a coordenada x de milhões de partículas, que estão em um array de estruturas. Qual layout tende a ser melhor?

Correto. Com SoA, as linhas de cache trazem só x, e não também velocidades e massas que o laço não usa.

Por que o blocking pode não ajudar em matrizes pequenas?

Correto. O benefício do blocking é reduzir a transferência entre memória e cache. Se tudo já cabe no cache, essa redução não aparece.
