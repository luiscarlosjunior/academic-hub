Tópico 2 · Arquitetura para HPC

Um núcleo moderno consegue executar várias operações de ponto flutuante por ciclo. Já a memória principal leva centenas de ciclos para responder a uma leitura. Se o programa esperar pela memória a cada operação, o processador passa a maior parte do tempo ocioso. Em HPC, a pergunta quase sempre é "o dado está perto do processador quando ele precisa?", e não "quantas operações eu faço?".

Este tópico descreve a hierarquia que responde a essa pergunta e as regras de programação que a usam a seu favor. O tópico 3 aplica essas regras em código, e o tópico 8 mostra a mesma lógica dentro da GPU.

A hierarquia: rápido e pequeno versus lento e grande

Cada nível é maior e mais lento que o anterior. Os números abaixo são ordens de grandeza típicas e variam de máquina para máquina.

NívelTamanho típicoLatência aproximada
Registradorescentenas de bytes< 1 ciclo
Cache L132–64 KB por núcleo~4 ciclos
Cache L2256 KB–2 MB por núcleo~12 ciclos
Cache L3dezenas de MB (compartilhada)~40 ciclos
Memória principal (DRAM)GB~200–300 ciclos
Disco / redeTBde microssegundos a milissegundos

Dois conceitos sustentam a hierarquia. O cache trabalha com linhas (tipicamente 64 bytes): ao buscar um elemento, o hardware traz a linha inteira. Por isso ler um double isolado custa quase o mesmo que ler sete vizinhos. E a hierarquia só funciona porque os programas têm localidade.

  • Localidade espacial: quem acessa um endereço logo acessa endereços próximos (um vetor lido em ordem).
  • Localidade temporal: quem acessa um dado tende a acessá-lo de novo logo depois (um acumulador dentro de um laço).

Mesma soma, dois percursos

Uma matriz de 4096 × 4096 doubles é armazenada em C por linhas: elementos consecutivos de uma linha estão lado a lado na memória. Somar os elementos seguindo essa ordem aproveita cada linha de cache inteira. Somar por colunas faz cada acesso pular 32 KB, quase sempre um miss no cache.

Arquivo: 02-localidade.c

/* por linhas: acesso contíguo */
for (size_t i = 0; i < N; i++)
    for (size_t j = 0; j < N; j++)
        s += m[i * N + j];

/* por colunas: salto de N * 8 bytes a cada passo */
for (size_t j = 0; j < N; j++)
    for (size_t i = 0; i < N; i++)
        s += m[i * N + j];

Saída real (executado neste ambiente, duas execuções)

soma igual nos dois percursos: sim (50331645)
por linhas:  0.0302 s
por colunas: 0.3130 s
razao colunas/linhas: 10.38

soma igual nos dois percursos: sim (50331645)
por linhas:  0.0316 s
por colunas: 0.3255 s
razao colunas/linhas: 10.31

A soma é idêntica e o trabalho é o mesmo. A diferença de cerca de 10× vem só da ordem de acesso. Isso é o que significa "o cache decide".

Paralelismo de dados: SIMD

Além de vários núcleos, cada núcleo tem unidades SIMD (single instruction, multiple data): uma instrução soma, por exemplo, quatro ou oito doubles de uma vez (AVX, AVX-512 e, em ARM, NEON e SVE). Para aproveitar isso, os dados precisam estar alinhados e contíguos, e o laço não pode ter dependências entre iterações que impeçam a execução simultânea.

O compilador com -O2 ou -O3 tenta vetorizar sozinho. Você verifica o que aconteceu com relatórios do compilador (-fopt-info-vec no GCC, -Rpass=loop-vectorize no Clang) e ajuda com restrict, alinhamento e laços simples.

Teste seus conhecimentos

Em C, uma matriz é armazenada por linhas. Qual percurso tende a ter melhor desempenho?

Correto. Os elementos da linha estão contíguos na memória, então cada linha de cache é aproveitada por completo.

O que é localidade temporal?

Correto. A reutilização próxima no tempo mantém o dado no cache. A espacial é a outra metade: endereços vizinhos.
