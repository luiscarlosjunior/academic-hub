Por que um agente precisa de lógica?

Um agente de busca sabe onde está. Um agente lógico sabe coisas — e consegue deduzir fatos novos que ninguém lhe contou. Essa é a diferença entre tropeçar no mundo e raciocinar sobre ele.

A arquitetura é sempre a mesma: uma base de conhecimento (KB) com sentenças que acreditamos verdadeiras, e um mecanismo de inferência que responde à pergunta “a KB implica α?”. Escrevemos KB ⊨ α.

Sintaxe

Quais cadeias de símbolos são sentenças válidas. P ∧ Q é; P ∧ ∧ Q não é.

Semântica

O que cada sentença significa em cada mundo possível (modelo). É ela que define verdadeiro e falso.

Consequência lógica

KB ⊨ α: em todo modelo onde a KB é verdadeira, α também é.

Conectivos e tabela-verdade

Escreva uma fórmula usando P Q R e os conectivos abaixo. A tabela é calculada na hora, e cada linha é um mundo possível.

Resolução: provar por absurdo

Tabelas-verdade explodem: n símbolos geram 2n linhas. A resolução é o algoritmo que os provadores automáticos realmente usam. A ideia: para mostrar que KB ⊨ α, adicione ¬α à base e derive uma contradição (cláusula vazia □).

Problema

  • Se chove, a rua fica molhada. C → M
  • Se a rua está molhada, há trânsito. M → T
  • Está chovendo. C

Provar: há trânsito (T).

Passo 1 — converter para FNC

// C → M vira ¬C ∨ M
(1) ¬C ∨ M
(2) ¬M ∨ T
(3) C
// negamos a conclusão
(4) ¬T

Derivação

A resolução é completa por refutação: se KB ⊨ α, o algoritmo sempre acha a cláusula vazia. É o motor do Prolog e dos provadores de teoremas.

O salto para a Lógica de Primeira Ordem

Na lógica proposicional, “Sócrates é mortal” é um símbolo atômico opaco: S. Não há como dizer “todo homem é mortal” sem escrever uma sentença para cada homem do universo. A lógica de primeira ordem (LPO) resolve isso ao quebrar o átomo em objetos, predicados e funções, e ao acrescentar quantificadores.

Proposicional 
HomemSocrates → MortalSocrates
HomemPlatao   → MortalPlatao
… uma regra por indivíduo (não escala)
Primeira ordem 
∀x (Homem(x) → Mortal(x))
Homem(Socrates)
⊢ Mortal(Socrates)

Erro clássico: o ∀ anda com → e o ∃ anda com ∧. Escrever ∀x (Quadrado(x) ∧ Azul(x)) afirma que tudo no universo é um quadrado azul; o que se quer dizer é ∀x (Quadrado(x) → Azul(x)).

Compare as duas últimas linhas: trocar a ordem dos quantificadores muda o significado. ∀x∃y permite um orientador diferente para cada aluno; ∃y∀x exige um único orientador para todos.

Um exemplo resolvido: provar por refutação

Vamos provar um argumento simples usando resolução. A técnica é: suponha que a conclusão é falsa e mostre que isso gera uma contradição.

Premissas: (1) se chove, a rua fica molhada (P → Q); (2) está chovendo (P). Conclusão: a rua está molhada (Q).

Passo 1 — traduza para cláusulas (forma normal conjuntiva). P → Q vira (¬P ∨ Q). As premissas ficam: {¬P, Q} e {P}.

Passo 2 — negue a conclusão e acrescente ao conjunto. Adicionamos {¬Q}. Se o conjunto de cláusulas é contraditório, a conclusão original é válida.

Passo 3 — resolva. Da cláusula {¬P, Q} e de {¬Q} obtemos {¬P} (o Q se cancela). Com {¬P} e {P} obtemos a cláusula vazia, que representa a contradição.

Como chegou à cláusula vazia, a suposição “a rua não está molhada” é falsa, e o argumento é válido.

O mesmo raciocínio em lógica de primeira ordem

Agora use predicados. Premissas: Todo humano é mortal ∀x (Humano(x) → Mortal(x)) e Sócrates é humano (Humano(Sócrates)). Conclusão: Sócrates é mortal. O quantificador universal é instanciado com x = Sócrates, o que nos devolve o caso proposicional do exemplo anterior. Essa é a ponte entre as duas lógicas: a primeira ordem permite falar de objetos e de todos os elementos de um conjunto, a proposicional não.

Um detalhe prático: a validade de um argumento não depende de as premissas serem verdadeiras no mundo real. Ela depende apenas de a conclusão se seguir delas. Um argumento válido com premissa falsa é válido, mas não é sólido.

Traduzir um problema real para a lógica

Quase todo erro em lógica começa na tradução. Estes passos ajudam a transformar uma frase em uma fórmula que possa ser verificada.

  1. 1. Identifique as proposições atômicas

    Escolha frases que são verdadeiras ou falsas e dê a cada uma uma letra. “Pagamento aprovado” pode ser A; “Estoque disponível” pode ser B.

  2. 2. Traduza os conectivos com cuidado

    E (∧), OU (∨), NÃO (¬) e SE…ENTÃO (→). Atenção: “ou” na linguagem comum costuma ser exclusivo. “Café ou chá” geralmente significa um ou outro, não ambos.

  3. 3. Use quantificadores quando houver “todo” ou “algum”

    Em “todo cliente com cadastro tem CPF”, use ∀x (Cliente(x) ∧ Cadastro(x) → TemCPF(x)).

  4. 4. Verifique com tabela-verdade quando for proposicional

    Monte a tabela com todas as combinações. Se a conclusão for verdadeira em todas as linhas em que as premissas são verdadeiras, o argumento é válido.

  5. 5. Use resolução para problemas maiores

    Quando a tabela crescer demais (com n letras, são 2ⁿ linhas), negue a conclusão e aplique resolução até obter a cláusula vazia ou esgotar as possibilidades.

Um erro clássico

“Se estudo, passo na prova. Passei na prova, logo estudei.” Este argumento é inválido (é a falácia da afirmação do consequente). Passar na prova pode ter outras causas. A tabela-verdade mostra a linha em que as premissas são verdadeiras e a conclusão é falsa: estudo = F, passa = T. Sempre que você encontrar uma linha assim, o argumento não se sustenta.

Lógica no dia a dia

A lógica aparece em regras de negócio, em programação e até em contratos. Reconhecê-la evita decisões baseadas em raciocínios furados.

Todo if de código é uma fórmula lógica. Uma condição como idade ≥ 18 and (possui_responsavel or cadastro_completo) é uma proposição composta. Muitos bugs são simplesmente conectivos trocados, como usar or onde era and. Você pode verificar uma regra como essa com um pequeno script, que testa todas as combinações:

from itertools import product

def regra(idade, responsavel, cadastro):
    return idade >= 18 and (responsavel or cadastro)

# lista todas as combinações possíveis de verdadeiro/falso
for responsavel, cadastro in product([True, False], repeat=2):
    print(responsavel, cadastro, regra(20, responsavel, cadastro))

Use o mesmo pensamento para ler contratos, políticas e termos de uso: procure por “e”, “ou”, “exceto” e “somente se”. Essas palavras mudam o significado da regra inteira. Por fim, ao avaliar um argumento de alguém (inclusive um de chatbot), pergunte: a conclusão decorre das premissas, ou só parece decorrer?

Teste seu entendimento

Confirme se os conceitos ficaram no lugar.

1. Uma fórmula cuja tabela-verdade só tem V na última coluna é:

Válida/tautologia = verdadeira em todo modelo. Satisfatível = verdadeira em algum modelo. Insatisfatível/contradição = falsa em todos. Note que KB ⊨ α ⟺ KB ∧ ¬α é insatisfatível — é exatamente esse fato que a resolução por refutação explora.

2. Por que a resolução começa negando a conclusão?

É o teorema da dedução em ação. Derivar a cláusula vazia □ significa que a base com a conclusão negada se contradiz — logo, a conclusão original é consequência lógica da KB.

3. “Todo pássaro voa” em LPO é:

A segunda opção diz que tudo no universo é um pássaro que voa — inclusive pedras. A terceira é quase sempre trivialmente verdadeira: basta existir um objeto que não seja pássaro para a implicação ser satisfeita.
