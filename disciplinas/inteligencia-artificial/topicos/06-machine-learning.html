Programar regras × aprender regras

Na programação tradicional, você escreve as regras e o computador produz respostas. No aprendizado de máquina, você fornece exemplos de respostas e o computador produz as regras. É a mesma inversão que separa um sistema especialista de um classificador treinado.

Programação clássica
regras + dados  →  PROGRAMA  →  respostas
Aprendizado de máquina
dados + respostas  →  TREINAMENTO  →  modelo (as regras)

O que acontece durante o treinamento

Treinar é descer uma ladeira. O modelo começa com parâmetros aleatórios, mede o erro, calcula para que lado o erro diminui (o gradiente) e dá um passo nessa direção. Repita milhares de vezes. Clique no gráfico para adicionar pontos e veja a reta perseguir os dados.

Gradiente descendente

repita:
  ŷ ← w·x + b
  erro ← média((ŷ − y)²)
  ∂w ← 2·média((ŷ − y)·x)
  ∂b ← 2·média(ŷ − y)
  w ← w − α·∂w
  b ← b − α·∂b
Experimente puxar a taxa de aprendizado para o máximo. A reta oscila cada vez mais longe e o erro explode: o passo é grande demais e o algoritmo “pula” o fundo do vale. Muito baixa, e o treino nunca termina. Escolher α é a primeira decisão prática de todo projeto de ML.

O erro que todo iniciante comete

Um modelo que acerta 100% no treino pode ser péssimo na vida real: ele decorou o ruído em vez de aprender o padrão. Mova o grau do polinômio e compare o erro nos pontos de treino com o erro nos pontos de teste — que o modelo nunca viu.

Como combater o overfitting

  • • Mais dados de treino
  • • Modelo mais simples (menos parâmetros)
  • • Regularização (L1 / L2, dropout)
  • • Validação cruzada para escolher hiperparâmetros
  • • Parada antecipada (early stopping)
Regra de ouro: o conjunto de teste só pode ser usado uma vez, no fim. Se você ajustar hiperparâmetros olhando o teste, ele vira treino disfarçado — use um conjunto de validação separado, ou validação cruzada k-fold.

Teste seu entendimento

Quatro perguntas sobre a prática de ML.

1. Erro de treino baixíssimo e erro de teste alto. Isso é:

É a assinatura clássica do overfitting: alta variância. Mova o grau do polinômio para 12 na animação acima e veja a curva passar por todos os pontos de treino enquanto despenca entre eles.

2. Detecção de fraude: 0,1% das transações são fraudulentas. Qual métrica não serve como principal?

Prever “nunca é fraude” já dá 99,9% de acurácia. Em bases desbalanceadas, use precisão, recall, F1 ou AUC. Experimente na matriz acima: zere VP e FP e veja a acurácia continuar altíssima.

3. Você testou 20 configurações e escolheu a melhor pelo conjunto de teste. O problema é:

Cada olhada no teste vaza informação para dentro da sua decisão. Separe treino / validação / teste, ou use validação cruzada no treino e guarde o teste para a medição final, feita uma única vez.

4. Um robô aprende a andar recebendo recompensa por distância percorrida. Esse é um caso de:

Não há resposta correta rotulada para cada instante — só um sinal de recompensa atrasado. O agente precisa descobrir sozinho quais ações levaram ao resultado (o problema da atribuição de crédito).
