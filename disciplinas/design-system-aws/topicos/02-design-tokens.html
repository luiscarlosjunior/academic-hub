Tópico 2 · Design tokens

Um design token é um valor de design dado a um nome: uma cor, um espaçamento, uma fonte, uma sombra. Tokens são a menor fonte única de verdade do sistema. Em vez de escrever #2563eb em cem arquivos, o componente pede cor.acao.primaria, e o valor vem de um lugar só. Isso torna temas, marcas e plataformas (web, iOS, Android) gerados a partir da mesma fonte.

Objetivos desta página. Ao final, você deve conseguir:

  • separar tokens primitivos de tokens semânticos e explicar o ganho dessa separação;
  • escrever tokens no formato de design tokens do W3C (DTCG), com $value e $type;
  • gerar variáveis CSS, Swift e XML a partir do mesmo arquivo com Style Dictionary;
  • implementar um tema escuro trocando apenas a camada semântica.

Teoria: primitivos, semânticos e de componente

Primitivos são valores brutos, sem intenção: azul.600 = #2563eb. Eles descrevem a paleta da marca. Semânticos dão intenção ao valor: cor.acao.primaria aponta para azul.600. Um componente nunca usa primitivos diretamente; ele usa semânticos. Por fim, tokens de componente podem existir para casos específicos, como botao.primario.fundo, que aponta para um semântico.

A separação compensa de duas formas. Primeiro, mudar a marca é trocar primitivos. Segundo, criar um tema é trocar o mapeamento semântico, mantendo os mesmos nomes. O componente continua pedindo cor.fundo, e o tema decide o que isso significa. Essa ideia aparece na documentação de todos os grandes sistemas listados no tópico 1.

O formato de referência é o rascunho do Design Tokens Format Module, produzido pelo W3C Design Tokens Community Group. Cada token tem $value, $type e, opcionalmente, $description. Referências usam chaves duplas: {'{'}color.blue.600{'}'}.

Operação 1 · Escrever tokens no formato DTCG

O arquivo abaixo tem duas camadas. A primitiva define o valor; a semântica só aponta para ela. Note que a referência {'{'}color.blue.600{'}'} é resolvida pelo build, não pelo componente.

Em JSON · exemplos/tokens.json

{
  "color": {
    "blue": {
      "600": { "$value": "#2563eb", "$type": "color" }
    },
    "gray": {
      "900": { "$value": "#0f172a", "$type": "color" },
      "50":  { "$value": "#f8fafc", "$type": "color" }
    }
  },
  "color-semantic": {
    "action": {
      "primary": { "$value": "{color.blue.600}", "$type": "color",
                   "$description": "Ação principal: botão de confirmar" }
    },
    "surface": { "$value": "{color.gray.50}", "$type": "color" },
    "text":    { "$value": "{color.gray.900}", "$type": "color" }
  },
  "space": {
    "4": { "$value": "16px", "$type": "dimension" }
  }
}

Operação 2 · Resolver referências e gerar saídas

O Style Dictionary, mantido originalmente pela Amazon, lê os tokens, resolve as referências, aplica transforms (converter unidades, nomes, cores) e escreve formatos para cada plataforma. O mesmo passo gera o CSS, o Swift e o XML. A animação mostra o fluxo.

Animação: do tokens.json às plataformas

Avance para ver cada saída sendo produzida. No último quadro, o tema escuro sai do mesmo arquivo, com outra camada semântica.

Em JavaScript (Node) · style-dictionary.config.mjs · v4

import StyleDictionary from 'style-dictionary';

const sd = new StyleDictionary({
  source: ['tokens/**/*.json'],
  platforms: {
    css: {
      transformGroup: 'css',
      buildPath: 'dist/css/',
      files: [{ destination: 'variables.css', format: 'css/variables' }]
    },
    ios: {
      transformGroup: 'ios-swift',
      buildPath: 'dist/ios/',
      files: [{ destination: 'Tokens.swift', format: 'ios-swift/class.swift', className: 'Tokens' }]
    }
  }
});

await sd.buildAllPlatforms();

Saída gerada em CSS · dist/css/variables.css

:root {
  --color-blue-600: #2563eb;
  --color-action-primary: #2563eb;
  --color-surface: #f8fafc;
  --color-text: #0f172a;
  --space-4: 16px;
}

Operação 3 · Tema escuro pela camada semântica

Para o tema escuro, não se duplica componente nem CSS. Cria-se um segundo arquivo semântico que aponta para outros primitivos e sai com um seletor próprio. O componente continua usando --color-surface e --color-text; a página decide o tema com um atributo no elemento raiz.

Em JSON · tokens/semantic.dark.json

{
  "color-semantic": {
    "surface": { "$value": "{color.gray.900}", "$type": "color" },
    "text":    { "$value": "{color.gray.50}",  "$type": "color" }
  }
}

Em CSS · uso no navegador

[data-theme="dark"] {
  --color-surface: #0f172a;
  --color-text: #f8fafc;
}

/* o componente não muda: */
.card { background: var(--color-surface); color: var(--color-text); }

Programa completo

Os dois arquivos completos estão em disciplinas/design-system-aws/exemplos/: tokens.json com primitivos e semânticos, e style-dictionary.config.mjs com as plataformas. Rode npm i style-dictionary e depois node style-dictionary.config.mjs para gerar a pasta dist/.

Exercícios resolvidos

1. Um componente usa blue.600 diretamente no CSS. Por que isso é um problema para o tema escuro?

Ver resposta

Resposta: o primitivo não carrega intenção. Se o tema escuro precisar de outro azul para a ação, o componente não sabe se deve mudar. A referência correta é semântica (color.action.primary), que o tema pode apontar para outro valor sem alterar o componente.

2. Quantas vezes você precisa escrever #2563eb se usa Style Dictionary com as três plataformas?

Ver resposta

Resposta: uma vez, no tokens.json. O build escreve o valor no CSS, no Swift e no XML. Isso elimina divergência entre plataformas, que é um dos principais motivos para adotar tokens.

Exercícios propostos

  1. Adicione uma escala de espaçamento (4, 8, 12, 16, 24, 32) como primitivos e crie dois semânticos: space.inset.sm e space.inset.md.
  2. Crie um token de raio de borda ($type: dimension) e gere a saída CSS. Confirme que o valor aparece em :root.
  3. Escreva um teste automatizado que falha se algum componente usar um hexadecimal fora de tokens/.

Ponte para a certificação AWS

Tokens não são cobrados pela AWS, mas o modelo de “fonte única + build + publicação” é o mesmo que a prova DVA-C03 explora em automação e implantação: o artefato gerado é versionado e publicado sem edição manual. Esse raciocínio volta nos tópicos 5 a 7.

Teste seus conhecimentos

Qual token um componente deve usar para cor de ação?

Correto. O semântico expressa a intenção e permite trocar o valor por tema ou por marca sem tocar no componente.

Em um arquivo DTCG, qual propriedade guarda o valor de um token?

Correto. O formato DTCG usa $value, com $type para descrever o tipo.

Qual é a forma mais limpa de criar um tema escuro num sistema com tokens?

Correto. Os componentes não mudam; o tema é uma troca de referências na camada semântica.

O que levar desta página

  • Tokens são fonte única: primitivos guardam valores, semânticos guardam intenção.
  • Use o formato DTCG ($value, $type) e referências entre chaves.
  • Style Dictionary gera CSS, Swift e XML a partir do mesmo arquivo.
  • Temas trocam a camada semântica; componentes não mudam.
