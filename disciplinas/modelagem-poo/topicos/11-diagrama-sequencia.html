Quem chama quem, e em que ordem

O diagrama de sequência mostra a colaboração entre objetos para realizar um cenário. O tempo corre de cima para baixo; cada objeto tem uma linha de vida vertical; e cada seta é uma mensagem — na prática, uma chamada de método.

É o diagrama que mais ajuda a distribuir responsabilidades: ao desenhá-lo, você é obrigado a decidir qual classe faz cada coisa. Se uma linha de vida concentra todas as setas, é sinal de má distribuição de responsabilidades.

Fragmentos combinados: condição e repetição

  

    Um diagrama de sequência sozinho mostra um caminho reto. Os fragmentos combinados —
    retângulos com um rótulo no canto superior esquerdo — acrescentam estruturas de controle.
  

  







  
A mesma cena, outro enquadramento

  

    O diagrama de comunicação mostra exatamente a mesma interação, mas organiza os objetos
    no espaço em vez do tempo. A ordem é recuperada pela numeração das mensagens.
    Os dois são ditos isomórficos: dá para converter um no outro sem perder informação.
  


  

    

      
    

    

      

        
Quando preferir cada um

        
    
          
  • Sequência: quando a ordem temporal é o que importa — o caso mais comum. Fica óbvio o que acontece antes e depois.
    • 
          
  • Comunicação: quando interessa quem está ligado a quem. Bom para enxergar acoplamento e objetos centrais demais.
    • 
        

      

      

        
        
Na prática, quase todo mundo usa o de sequência. O de comunicação aparece mais em provas e em
        análises de acoplamento — mas saber ler os dois é exigência da disciplina.

      

    

  








  
Linhas de vida, ativação e tipos de mensagem

  

    

      O diagrama de sequência mostra interações: como objetos trocam mensagens ao longo do tempo. O eixo
      vertical é o tempo, que cresce para baixo. Cada participante tem uma linha de vida (linha tracejada) e,
      quando está executando uma operação, uma barra de ativação (retângulo estreito sobre a linha).
    

  

  

    

      
MensagemNotaçãoSignificado

      
        
Síncronaseta cheiaO emissor espera até a resposta; corresponde a uma chamada de operação

        
Assíncronaseta de ponta abertaO emissor segue sem esperar (envio de evento ou fila)

        
Retornoseta tracejada de voltaValor devolvido pela chamada anterior

        
Criaçãoseta apontando para o retângulo do objetoO objeto nasce naquele momento

        
Destruiçãoum X ao fim da linhaO objeto deixa de existir

        
Auto-mensagemseta que sai e volta ao mesmo objetoChamada interna de outra operação

      
    

  

  

    
    

      Pilha de chamadas: as barras de ativação aninhadas representam a pilha de execução. Uma barra dentro
      de outra é uma chamada feita durante a execução da primeira. É a forma visual de mostrar recursão e de explicar
      quem está esperando quem.
    

  






  
Exemplo: a renovação mensal da assinatura

  

    Um sistema de cobrança recorrente, com um caminho feliz e um caminho de falha. Os fragmentos combinados ajudam a mostrar
    as duas situações no mesmo diagrama.
  

  

    
sequenceDiagram
    participant Agenda as Agendador
    participant Pl as PlataformaStreaming
    participant As as Assinatura
    participant Cb as ContaBancaria
    participant Ou as Ouvinte
    Agenda->>Pl: renovarTodas()
    loop para cada assinatura ativa
        Pl->>As: cobrar(conta)
        As->>Cb: debitar(19.90)
        alt saldo suficiente
            Cb-->>As: sucesso
            As-->>Pl: true
            Pl->>Ou: recibo enviado
        else saldo insuficiente
            Cb-->>As: falha
            As-->>Pl: false
            Pl->>As: suspender()
        end
    end
    

  

  
O loop repete a cobrança para cada assinatura; o alt separa o caminho feliz da suspensão, que implementa a regra R3.






  
Fragmentos combinados: controle dentro da sequência

  

    Um fragmento combinado é uma moldura com um operador que controla as mensagens dentro dela. Os principais são:
  

  

    

      
OperadorSignificadoQuando usar

      
        
altAlternativas: executa uma das áreas, conforme a guardaSe/senão, caminhos de sucesso e falha

        
optOpcional: executa só se a guarda for verdadeiraUm passo que pode não acontecer

        
loopRepetição, com limites opcionaisCobrança para cada assinatura

        
parParalelo: as áreas podem intercalar suas mensagensEnviar recibo e atualizar histórico

        
breakInterrompe o fluxo quando a guarda valeTratamento de erro que encerra a interação

        
refReferencia outra interação já modeladaReaproveitar um cenário, como a autenticação

        
negInteração inválida: não deve acontecerMostrar uma sequência proibida, como cobrar cancelada

      
    

  

  

    
    

      Cuidado com opt e alt: se o passo é obrigatório, não use opt. Um diagrama
      que tem um opt para tudo esconde regras: o leitor não sabe o que é essencial.
    

  






  
Quando a mensagem é assíncrona

  

    

      Em uma chamada síncrona, o emissor fica bloqueado até a resposta. Em uma assíncrona, ele envia e segue. Essa diferença
      muda a arquitetura: se a cobrança for assíncrona, a plataforma não sabe, naquele instante, se o débito funcionou. A
      sequência precisa então de um passo posterior de confirmação, como um evento “pagamento confirmado”.
    

  






  
Cada mensagem é uma operação


public class PlataformaStreaming {
    public void renovarTodas() {
        for (Assinatura a : assinaturasAtivas()) {       // loop
            if (a.cobrar(a.getConta())) {                   // alt: saldo suficiente
                enviarRecibo(a.getOuvinte());
            } else {                                          // alt: saldo insuficiente
                a.suspender();                                       // R3: suspende, não cancela
            }
        }
    }
}

  

    

      Esse é o ponto da sequência: cada seta vira uma chamada, cada fragmento vira um if, for ou
      while. A sequência é um roteiro do método que está prestes a ser escrito.
    

  






  
Exercícios

  

    

      1. Um ouvinte pede para ver suas playlists. Antes, o sistema precisa autenticá-lo, que é o mesmo cenário em outras telas. Como modelar sem repetir a sequência?
      
Gabarito: criar uma interação “Autenticar” e referenciá-la com um fragmento ref na sequência de “Ver playlists”. Assim o cenário de autenticação existe em um lugar só.

    

    

      2. Na sequência do exemplo, o que aconteceria se o loop fosse substituído por um opt?
      
Gabarito: a cobrança rodaria no máximo uma vez, e só se a guarda fosse verdadeira. Para renovar todas as assinaturas, é preciso repetir: o loop expressa isso, e o opt não.

    

    

      3. Por que uma auto-mensagem em Assinatura pode ser útil no diagrama?
      
Gabarito: ela mostra uma chamada interna de uma operação para outra, por exemplo cobrar() chamando validarStatus(). Revela a lógica privada que não aparece na interface pública, o que ajuda a explicar a regra.
