Testar não basta: verificar todo o espaço

Testes exploram alguns caminhos. Um model checker explora todos os estados alcançáveis de um modelo finito e verifica uma propriedade em cada um. Se a propriedade falha, devolve um contraexemplo: a sequência de ações que leva ao problema.

Edmund Clarke, E. Allen Emerson e Joseph Sifakis receberam o Prêmio Turing de 2007 por essa técnica, desenvolvida a partir do trabalho de 1981 sobre lógica temporal de árvore de computação (CTL).

Segurança e vivacidade

Propriedades se dividem em duas classes:

  • Segurança (safety): “nada ruim acontece”. Ex.: o saldo nunca fica negativo. Um estado proibido é alcançado? Se sim, há um contraexemplo finito.
  • Vivacidade (liveness): “algo bom acontece eventualmente”. Ex.: toda assinatura suspensa é regularizada ou cancelada. Exige analisar caminhos infinitos.

O projeto verifica segurança: a busca em largura (BFS) explora os estados e, se acha uma violação, o caminho encontrado é o mais curto possível, porque a BFS visita por distância.

O modelo verificado

stateDiagram-v2
    [*] --> ATIVA
    ATIVA --> SUSPENSA : cobrança sem saldo
    SUSPENSA --> ATIVA : regularizar
    ATIVA --> CANCELADA : cancelar
    SUSPENSA --> CANCELADA : cancelar
    CANCELADA --> [*]

O modelo do exemplo acrescenta o saldo como variável de estado (0 a 2 unidades). O checker verifica duas propriedades: saldo dentro dos limites, e CANCELADA como estado final (regra R4).

Contexto do exemplo

O projeto explora o espaço de estados com BFS e verifica os invariantes. No modelo correto, as duas propriedades valem em todos os 9 estados alcançáveis. No modelo com o defeito de reativação, o checker encontra a violação com o caminho depositar, cancelar, que é o mais curto possível.

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.HashSet;
import java.util.List;
import java.util.Optional;
import java.util.Set;

/**
 * Verificação de modelos por exploração explícita de estados (model checking, BFS).
 * Modelamos a assinatura como um sistema de transições e verificamos invariantes em TODOS
 * os estados alcançáveis. Se uma propriedade falha, o checker devolve um contraexemplo.
 */
public class Main {

    enum Status { ATIVA, SUSPENSA, CANCELADA }

    /** Estado abstrato: status + saldo em "unidades de cobrança" (0..2). */
    record Estado(Status status, int saldo) {}

    /** Um passo do sistema: nome da ação e o estado resultante. */
    record Passo(String acao, Estado para) {}

    /** Transições. O parâmetro 'bugReativacao' liga um defeito deliberado para o checker encontrar. */
    static List<Passo> sucessores(Estado e, boolean bugReativacao) {
        List<Passo> out = new ArrayList<>();
        // cobrança mensal: se houver saldo, cobra; se não, suspende (R3)
        if (e.status() != Status.CANCELADA) {
            if (e.saldo() >= 1) out.add(new Passo("cobrar", new Estado(Status.ATIVA, e.saldo() - 1)));
            else                out.add(new Passo("cobrar", new Estado(Status.SUSPENSA, e.saldo())));
        }
        // depósito: até 2 unidades
        if (e.saldo() < 2) out.add(new Passo("depositar", new Estado(e.status(), e.saldo() + 1)));
        // regularizar pagamento: suspensa volta a ativa (com saldo)
        if (e.status() == Status.SUSPENSA && e.saldo() >= 1)
            out.add(new Passo("regularizar", new Estado(Status.ATIVA, e.saldo())));
        // cancelar: a partir de ATIVA ou SUSPENSA
        if (e.status() != Status.CANCELADA)
            out.add(new Passo("cancelar", new Estado(Status.CANCELADA, e.saldo())));
        // BUG deliberado: reativar uma cancelada (R4 violada)
        if (bugReativacao && e.status() == Status.CANCELADA && e.saldo() >= 1)
            out.add(new Passo("reativar(bug)", new Estado(Status.ATIVA, e.saldo())));
        return out;
    }

    /** Resultado: invariante violado com o caminho até ele, ou vazio se vale em todo o espaço. */
    record Violacao(Estado estado, List<String> caminho) {}

    interface Invariante { boolean vale(Estado e); }

    static Optional<Violacao> verificar(Estado inicial, boolean bug, Invariante inv, String nome) {
        Set<Estado> visitados = new HashSet<>();
        // a fila guarda (estado, caminho até ele): BFS garante o contraexemplo mais curto
        ArrayDeque<Object[]> fila = new ArrayDeque<>();
        fila.add(new Object[]{inicial, new ArrayList<String>()});
        visitados.add(inicial);
        while (!fila.isEmpty()) {
            Object[] item = fila.poll();
            Estado atual = (Estado) item[0];
            @SuppressWarnings("unchecked") List<String> caminho = (List<String>) item[1];
            if (!inv.vale(atual)) return Optional.of(new Violacao(atual, caminho));
            for (Passo p : sucessores(atual, bug)) {
                if (visitados.add(p.para())) {
                    List<String> novo = new ArrayList<>(caminho);
                    novo.add(p.acao());
                    fila.add(new Object[]{p.para(), novo});
                }
            }
        }
        System.out.println("  [" + nome + "] estados alcançáveis: " + visitados.size());
        return Optional.empty();
    }

    public static void main(String[] args) {
        Estado inicio = new Estado(Status.ATIVA, 0);

        Invariante saldoNaoNegativo = e -> e.saldo() >= 0 && e.saldo() <= 2;
        Invariante canceladaEhFinal = e -> e.status() != Status.CANCELADA || sucessores(e, false).stream()
                .allMatch(p -> p.para().status() == Status.CANCELADA);   // nada sai de CANCELADA

        System.out.println("=== Modelo correto ===");
        System.out.println(verificar(inicio, false, saldoNaoNegativo, "saldo entre 0 e 2")
                .map(v -> "VIOLADO " + v).orElse("OK: saldo entre 0 e 2 em todo estado"));
        System.out.println(verificar(inicio, false, canceladaEhFinal, "cancelada é final")
                .map(v -> "VIOLADO " + v).orElse("OK: cancelada é final em todo estado"));

        System.out.println("\n=== Modelo com defeito (reativação de cancelada) ===");
        // Para o defeito, a propriedade é checada sobre os sucessores do modelo buggy
        Invariante canceladaEhFinalBug = e -> e.status() != Status.CANCELADA
                || sucessores(e, true).stream().allMatch(p -> p.para().status() == Status.CANCELADA);
        System.out.println(verificar(inicio, true, canceladaEhFinalBug, "cancelada é final")
                .map(v -> "VIOLADO em " + v.estado() + " após " + v.caminho())
                .orElse("OK"));
    }
}

Ferramentas da indústria

Modelos reais usam linguagens dedicadas: TLA+ (Lamport), usado para desenhar protocolos de sistemas distribuídos; Alloy (Jackson), para modelos relacionais; SPIN (Holzmann), para protocolos concorrentes. Newcombe et al. (2015) relatam o uso de métodos formais pela Amazon Web Services para encontrar falhas de projeto em serviços críticos antes de chegarem à produção. A lição para a modelagem: um modelo precisa de propriedades escritas explicitamente, senão não há o que verificar.

Limites: explosão de estados

O número de estados cresce exponencialmente com o número de variáveis. Por isso, o checker explícito deste exemplo serve para modelos pequenos, e ferramentas reais usam técnicas como abstração, redução por simetria e representações simbólicas (BDDs). Um modelo bem abstraído é o que torna a verificação viável: a arte está em escolher o que modelar.

Cenário real: cobrança recorrente com retentativas

Cenário ilustrativo. Os casos a seguir são composições didáticas inspiradas em problemas comuns de plataformas de comércio, pagamentos e reservas. Não descrevem a arquitetura de nenhuma empresa específica.

Contexto

Um serviço de assinatura cobra o cliente mensalmente por meio de um gateway externo. Quando a resposta demora demais, o sistema reenvia a cobrança. O gateway pode ter processado a primeira tentativa mesmo sem responder.

O defeito que o modelo encontra

O checker explora todas as combinações de respostas: aprovação, recusa e timeout, nessa ordem e em qualquer ordem possível. O caminho mínimo que viola a regra “nunca cobrar duas vezes” é enviar, recusar, enviar (o modelo supõe que o gateway registra a primeira tentativa mesmo quando a resposta não chega ao sistema; o caso real mais comum é o timeout, que segue o mesmo caminho). Esse é o tipo de defeito que testes de caminho feliz não encontram.

A correção: idempotência

Cada cobrança recebe uma chave de idempotência gerada uma vez. As retentativas reenviam a mesma chave, e o gateway devolve o resultado da primeira em vez de cobrar de novo. No modelo, isso corresponde a reutilizar a mesma cobrança. O checker verifica que, com a correção, nenhum estado alcançável tem duas cobranças.

Como usar

  1. Modele os estados e as respostas possíveis do sistema externo, inclusive as que você não controla.
  2. Escreva as propriedades de segurança (“nunca duas cobranças”) explicitamente, antes de implementar.
  3. Rode o checker sobre o modelo a cada mudança de fluxo, e use o caminho mínimo como caso de teste de regressão.

Armadilha comum

Modelar só o caminho feliz. Um modelo que não tem timeout nunca vai encontrar o defeito, porque o timeout é exatamente a situação em que o sistema não sabe o que aconteceu.

Trade-offs

Ferramentas como TLA+ e Alloy exigem um investimento de aprendizado. O checker deste exemplo serve para modelos pequenos. Em sistemas grandes, o valor está em modelar a parte crítica (pagamento, estoque, identidade), e não o sistema inteiro.

import java.util.*;

/**
 * CENÁRIO: cobrança de assinatura com retentativas.
 * Uma requisição pode dar timeout DEPOIS de o gateway já ter cobrado. Sem chave de idempotência,
 * a retentativa cobra de novo: o cliente paga duas vezes. Este checker encontra o caminho
 * que leva a essa situação, e verifica a versão com idempotência.
 */
public class Main {

    enum Status { NOVO, PROCESSANDO, APROVADO, RECUSADO, TIMEOUT }

    /** cobrancas = quantas cobranças reais o gateway registrou (limitado a 2 para tornar o espaço finito). */
    record Estado(Status status, int cobrancas) {}
    record Passo(String acao, Estado para) {}

    static List<Passo> sucessores(Estado e, boolean comIdempotencia) {
        List<Passo> out = new ArrayList<>();
        // Enviar: novo envio ou retentativa após timeout/recusa
        if (e.status() == Status.NOVO || e.status() == Status.TIMEOUT || e.status() == Status.RECUSADO) {
            int cob = comIdempotencia ? Math.max(1, e.cobrancas()) : Math.min(e.cobrancas() + 1, 2);
            out.add(new Passo("enviar", new Estado(Status.PROCESSANDO, cob)));
        }
        if (e.status() == Status.PROCESSANDO) {
            out.add(new Passo("aprovar", new Estado(Status.APROVADO, e.cobrancas())));
            out.add(new Passo("recusar", new Estado(Status.RECUSADO, e.cobrancas())));
            out.add(new Passo("timeout", new Estado(Status.TIMEOUT, e.cobrancas())));
        }
        return out;
    }

    /** Verifica um invariante em todo estado alcançável (BFS). Devolve o caminho até a violação. */
    static Optional<List<String>> verificar(boolean comIdempotencia, java.util.function.Predicate<Estado> inv) {
        Estado inicio = new Estado(Status.NOVO, 0);
        Set<Estado> visitados = new HashSet<>(Set.of(inicio));
        ArrayDeque<Map.Entry<Estado, List<String>>> fila = new ArrayDeque<>();
        fila.add(Map.entry(inicio, List.of()));
        while (!fila.isEmpty()) {
            var item = fila.poll();
            if (!inv.test(item.getKey())) return Optional.of(item.getValue());
            for (Passo p : sucessores(item.getKey(), comIdempotencia)) {
                if (visitados.add(p.para())) {
                    List<String> caminho = new ArrayList<>(item.getValue());
                    caminho.add(p.acao());
                    fila.add(Map.entry(p.para(), caminho));
                }
            }
        }
        System.out.println("  estados alcançáveis: " + visitados.size());
        return Optional.empty();
    }

    public static void main(String[] args) {
        java.util.Locale.setDefault(java.util.Locale.ROOT);   // saída reprodutível em qualquer máquina
        // Propriedade de segurança: nunca cobrar o cliente duas vezes pelo mesmo pedido
        java.util.function.Predicate<Estado> cobradoUmaVez = e -> e.cobrancas() <= 1;

        System.out.println("=== Sem chave de idempotência ===");
        verificar(false, cobradoUmaVez).ifPresentOrElse(
                caminho -> System.out.println("VIOLADO. Caminho mínimo: " + caminho),
                () -> System.out.println("OK"));

        System.out.println("\n=== Com chave de idempotência (retentativas reutilizam a mesma cobrança) ===");
        verificar(true, cobradoUmaVez).ifPresentOrElse(
                caminho -> System.out.println("VIOLADO: " + caminho),
                () -> System.out.println("OK: nenhuma cobrança duplicada em todo o espaço de estados"));
    }
}

Exercícios

1. Adicione a propriedade “o saldo nunca passa de 2”. Ela já é garantida pelo modelo? Como provar?

Gabarito: sim, pela guarda do depósito (saldo < 2). O checker confirma: a propriedade é verificada em todos os estados alcançáveis. Escreva o invariante explicitamente no código, para que mudanças futuras no modelo a derrubem.

2. Mostre por que “toda assinatura suspensa eventualmente volta a ativa” é uma propriedade de vivacidade, e não de segurança.

Gabarito: ela fala de um futuro indefinido (“eventualmente”). Um estado não basta como evidência, porque a violação seria um ciclo infinito de suspensão sem saída. Verificá-la exige análise de caminhos infinitos (por exemplo, com lógica temporal LTL), não de uma busca finita.
