Duas formas de dizer “toda classe daqui faz isto”

Às vezes você quer garantir que um conjunto de classes ofereça certas operações, sem se importar com como cada uma as implementa. Existem dois mecanismos para isso, e a diferença entre eles é a pergunta mais frequente em prova.

A interface é um contrato puro: só diz o que precisa existir. A classe abstrata é um esqueleto parcialmente pronto: traz implementação compartilhada e deixa buracos para as subclasses preencherem.

«interface»

Interface

public interface Pagavel {
    double calcularValor();   // sem corpo
    void registrarPagamento();
}

class Fatura implements Pagavel { … }
class Salario implements Pagavel { … }
  • • Uma classe pode implementar quantas quiser
  • • Não tem estado (só constantes)
  • • Define capacidade: “é capaz de ser pago”
  • • Classes sem parentesco algum podem compartilhá-la
ClasseAbstrata

Classe abstrata

public abstract class Conta {
    protected double saldo;        // tem estado

    public void depositar(double v) {  // já pronto
        saldo += v;
    }
    public abstract double taxaMensal();  // buraco
}

class Poupanca extends Conta { … }
  • • Uma classe estende apenas uma
  • • Tem atributos, construtor e código pronto
  • • Define identidade: “é um tipo de conta”
  • • Não pode ser instanciada diretamente
Regra de bolso: se as classes compartilham estado e código e pertencem à mesma família conceitual, classe abstrata. Se compartilham apenas uma habilidade e podem vir de famílias diferentes, interface. Na dúvida, comece pela interface: ela acopla menos.

Por que Java proíbe herança múltipla de classes

  

    

      Se D herdasse de B e C, e ambas tivessem implementações diferentes
      de um mesmo método herdado de A, qual delas D usaria? Essa ambiguidade é o
      problema do diamante — e a razão de Java permitir apenas uma superclasse.
    

  


  

    

      
    

    

      

        
A solução de Java

        
    
          
  • Classes: herança simples. Só existe uma cadeia de implementação, logo não há ambiguidade de estado nem de código.
    • 
          
  • Interfaces: herança múltipla permitida — como eram apenas assinaturas, não havia conflito de implementação.
    • 
          
  • Desde o Java 8: interfaces podem ter métodos default com corpo. O diamante voltou… e a linguagem passou a exigir que você resolva o conflito explicitamente.
    • 
        

      

      

        
Desempate explícito

        
interface B { default String falar() { return "oi"; } }
interface C { default String falar() { return "olá"; } }

class D implements B, C {
    @Override
    public String falar() {
        return B.super.falar();  // você escolhe
    }
}

        
Sem esse override, o código não compila.

      

    

  








  
Notação: classe abstrata e interface

  

    

      Uma classe abstrata é uma classe que não pode ser instanciada e pode ter operações sem implementação.
      Uma interface é um contrato puro: declara operações que um classificador deve oferecer, sem dizer
      como. Na UML, a classe abstrata tem nome em itálico ou o estereótipo «abstract»; a interface
      usa «interface».

Dois tipos de relação com a mesma aparência de “seta com triângulo”: generalização é linha sólida (herança de classe); realização é linha tracejada (implementação de interface).

      Regra de bolso: pergunte se as classes compartilham código e estado. Se sim, use classe

      Um mesmo objeto pode ter várias capacidades, mas só uma superclasse concreta.
    

  






  
Classe abstrata em ação: o padrão Template Method

  

    Quando várias subclasses seguem o mesmo roteiro com passos diferentes, a classe abstrata define o roteiro (método
    concreto) e deixa os passos variáveis como operações abstratas. Esse é o padrão Template Method do Gang of Four.
  


public abstract class Cobranca {
    // roteiro fixo (método final: a sequência não muda)
    public final void executar(double valor) {
        if (!validar(valor)) throw new IllegalArgumentException("valor inválido");
        double total = calcularComTaxa(valor);   // passo variável
        registrar(total);                                 // passo comum, já implementado
    }
    protected boolean validar(double v) { return v > 0; }
    protected abstract double calcularComTaxa(double v);  // cada meio define
    private void registrar(double t) { /* grava no extrato */ }
}

public class CobrancaCartao extends Cobranca {
    @Override protected double calcularComTaxa(double v) { return v * 1.03; }
}

  

    
    

      Na modelagem: a operação abstrata aparece em itálico no diagrama (ou com *, como no
      Mermaid deste tópico), e o método concreto que a chama é o “roteiro” que você quer proteger.
    

  






  
O problema do diamante

  

    

      Linguagens como C++ permitem herança múltipla de classes. Se duas superclasses herdam de uma terceira, e a subclasse
      herda das duas, surge o problema do diamante: qual cópia do estado e de qual método prevalece? Java
      evita o problema proibindo herança múltipla de classes, mas permite implementar várias interfaces, e isso pode
      gerar um conflito parecido quando dois default têm a mesma assinatura. Nesse caso, a classe é obrigada a
      escolher explicitamente.

Diamante: ContaFamilia herda id() por dois caminhos. Em Java, com interfaces com default, o compilador exige que você resolva o conflito.






  
Exercícios

  

    

      1. A Melodia precisa que “Playlist”, “Album” e “Podcast” possam ser exportados em CSV. Classe abstrata ou interface?
      
Gabarito: interface Exportavel. A capacidade é o que é compartilhado (exportar), e as três classes não têm estado comum a herdar. Uma playlist ainda pode ser Reproduzivel e Exportavel ao mesmo tempo.

    

    

      2. Por que o método executar do exemplo é final?
      
Gabarito: para impedir que subclasses alterem o roteiro (ordem dos passos e a regra de registro). Só os passos variáveis podem ser sobrescritos. Isso preserva o invariante de que toda cobrança passa por validação e registro.

    

    

      3. Desenhe, em UML, uma classe abstrata Usuario com a operação abstrata tipoDePerfil, e mostre que Artista também implementa a interface Publicavel.
      
Gabarito: Usuario com nome em itálico ou «abstract» e tipoDePerfil() em itálico; Artista herda de Usuario (seta sólida com triângulo vazio) e realiza Publicavel (seta tracejada com triângulo vazio). A resposta correta distingue as duas linhas.

Experimente

    
Crie class Video implements Reproduzivel, implementando descricao() e duracaoSegundos(), mas não duracaoFormatada(). Por quê? Como mudar o formato só para o vídeo?

    

      Ver gabarito
      
duracaoFormatada() é um default, então o vídeo herda a implementação. Para mudar o formato, basta sobrescrever o default em Video. A interface define o contrato obrigatório (métodos abstratos) e pode oferecer comportamento padrão (defaults) que a classe aceita ou sobrescreve.

Três perguntas sobre contratos e esqueletos.


  

    

      
1. Você precisa que Documento, Pedido e Relatorio — classes sem nenhum parentesco — possam ser exportadas para PDF. O melhor mecanismo é:

      
      
      
      

        As três já pertencem a hierarquias próprias e não têm nada em comum além dessa capacidade.
        Forçar uma superclasse comum criaria uma família artificial e queimaria o único extends
        disponível de cada uma.
      

    


    

      
2. Uma classe abstrata pode ter métodos concretos (com corpo)?

      
      
      
      

        Uma classe abstrata com todos os métodos abstratos e sem atributos é, na prática, uma interface
        mais restritiva — e nesse caso a interface é a escolha melhor. O valor da classe abstrata está no
        código que ela já traz pronto.
      

    


    

      
3. Em UML, a linha tracejada com ponta triangular vazada representa:

      
      
      
      

        Mesma ponta, traço diferente: sólida = generalização (extends);
        tracejada = realização (implements). Tracejada com ponta de seta aberta
        já é outra coisa: dependência.
