Abstração: decidir o que não modelar

Uma pessoa real tem milhares de características. Nenhum sistema precisa de todas. Abstrair é escolher o subconjunto relevante para aquele propósito e descartar o resto com consciência.

Por isso não existe “o modelo correto de Pessoa”: existe o modelo adequado ao contexto. Escolha o sistema abaixo e veja a mesma entidade do mundo real virar três classes diferentes.

Pergunta que guia toda abstração: “o sistema precisa fazer alguma coisa com esse dado?”. Se a resposta for não, ele não entra no modelo — mesmo existindo no mundo real.

Encapsulamento: o objeto defende o próprio estado

Duas contas bancárias com a mesma finalidade e implementações opostas. Execute as operações nas duas e compare — especialmente as que violam a regra de negócio.

Sem encapsulamento

atributo público 
public class ContaAberta {
    public double saldo;   // exposto
}
saldo
R$ 1.000,00

Com encapsulamento

atributo privado 
public class ContaSegura {
    private double saldo;  // protegido

    public void depositar(double v) {
        if (v <= 0) throw new ValorInvalido();
        saldo += v;
    }
    public void sacar(double v) {
        if (v > saldo) throw new SaldoInsuficiente();
        saldo -= v;
    }
    public double getSaldo() { return saldo; }
}
getSaldo()
R$ 1.000,00
O ponto não é “usar private”. É que a regra de negócio precisa viver em um único lugar. Uma classe com private + getter e setter para tudo continua completamente aberta — só que com mais linhas. Encapsular é não expor o que não precisa ser exposto.

O teste definitivo: trocar o interior sem quebrar ninguém

  

    

      Encapsular bem significa poder reescrever o interior da classe sem que nenhum código cliente perceba.
      Veja duas implementações completamente diferentes de Temperatura — e repare que o cliente
      continua idêntico.
    

  


  

    

      versão 1 — guarda em Celsius
      
class Temperatura {
    private double celsius;

    public double getCelsius() {
        return celsius;
    }
    public double getFahrenheit() {
        return celsius * 1.8 + 32;
    }
}

    

    

      versão 2 — guarda em Kelvin
      
class Temperatura {
    private double kelvin;  // mudou!

    public double getCelsius() {
        return kelvin - 273.15;
    }
    public double getFahrenheit() {
        return (kelvin - 273.15) * 1.8 + 32;
    }
}

    

    

      o cliente — inalterado
      
Temperatura t = sensor.ler();

println(t.getCelsius());
println(t.getFahrenheit());

// Nenhuma linha mudou.
// O cliente nunca soube — e
// nunca precisou saber — em
// que unidade o valor era
// guardado internamente.

1. Uma classe com todos os atributos private e um par getter/setter público para cada um está:

      
      
      
      

        É o “encapsulamento de fachada”. conta.setSaldo(-5000) passa igual. O correto é expor
        operações de negócio (depositar, sacar) e não acesso bruto aos campos.
      

    


    

      
2. Em UML, o símbolo # antes de um membro significa:

      
      
      
      

        + público, − privado, # protegido, ~ de pacote.
        Membros static aparecem sublinhados, não com símbolo próprio.
      

    


    

      
3. Abstração, no contexto da modelagem, é:

      
      
      
      

        Cuidado com a ambiguidade do termo: classe abstrata é um recurso da linguagem (assunto do
        tópico 05);
        abstração é o princípio de modelagem. Esconder detalhes é encapsulamento — parente próximo,
        mas coisa distinta.
