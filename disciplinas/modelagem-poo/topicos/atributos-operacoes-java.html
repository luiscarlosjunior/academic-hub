Atributo é a propriedade que o objeto guarda

Um atributo é um dado nomeado que todo objeto de uma classe guarda. Se a operação é o verbo do objeto, o atributo é o substantivo dele. Na UML, a sintaxe completa é [visibilidade] nome : tipo [= valorPadrão] [{propriedades}], e em Java ela se traduz diretamente. 

// UML                               →  Java
// - saldo : double = 0.0            →  private double saldo = 0.0;
// - titulo : String                 →  private String titulo;
// - duracaoSegundos : int {>= 0}     →  private int duracaoSegundos;  // validado no construtor
// - status : StatusAssinatura = ATIVA → private StatusAssinatura status = StatusAssinatura.ATIVA;

Três níveis de acesso no mesmo diagrama: - esconde o saldo, + expõe as operações e # libera a subclasse.

Regra de ouro: atributos quase sempre são private. O acesso vem por operações que validam. É isso que torna um invariante possível: se o saldo fosse public, qualquer código poderia escrever conta.saldo = -999 e quebrar a regra R1.

O saldo protegido, passo a passo

A mesma conta, duas formas de implementar. Compare o que acontece quando alguém tenta quebrar a regra R1.

// ❌ Atributo público: qualquer um escreve no saldo
public class ContaFragil {
    public double saldo = 0;
}
ContaFragil c = new ContaFragil();
c.saldo = -5000;              // compila e quebra a regra R1 silenciosamente

// ✅ Atributo privado: a única porta de entrada valida
public class ContaBancaria {
    private double saldo;

    public double sacar(double valor) {
        if (valor <= 0)
            throw new IllegalArgumentException("valor deve ser positivo");
        if (valor > saldo)
            throw new IllegalStateException("saldo insuficiente (regra R1)");
        saldo -= valor;
        return saldo;
    }

    public double getSaldo() {          // só leitura: não há setSaldo
        return saldo;
    }
}
ContaBancaria cb = new ContaBancaria();
cb.sacar(100);                // lança IllegalStateException: o invariante se mantém
Cuidado com getSaldo() sem setSaldo(): a ausência do setter é o que protege a regra. Gerar getters e setters automaticamente para todos os campos (o chamado modelo anêmico) derruba essa proteção, mesmo com os campos privados.

Atributos de instância, de classe e derivados

De instância

Cada objeto tem o seu. Cada conta tem o próprio saldo.

private double saldo;

De classe (static)

Um só para todos os objetos. Na UML aparece sublinhado.

static final double ROYALTY = 0.004;

Derivado (/)

Calculado quando pedido, não guardado. Evita dados inconsistentes.

duracaoTotal() { ... }

public class Playlist {
    // de classe: uma taxa única para todas as reproduções do sistema
    public static final double ROYALTY_POR_REPRODUCAO = 0.004;

    // de instância: cada playlist tem as suas músicas
    private final List<Musica> musicas = new ArrayList<>();

    // derivado: não existe campo "duracaoTotal" — calculamos quando pedem
    public int duracaoTotalSegundos() {
        return musicas.stream().mapToInt(Musica::getDuracaoSegundos).sum();
    }
}
Por que derivado e não campo? Se você guardar a duração total e alguém adicionar uma música sem atualizar o total, os dois ficam diferentes. Calcular na hora elimina esse risco. Guarde o dado primário; calcule o derivado.

Operação é o contrato; método é a implementação

Uma operação é a declaração: nome, parâmetros e retorno (a assinatura). É o o quê. Um método é a implementação concreta, com o corpo do código. É o como.

Em Java, uma operação declarada como abstract na superclasse é um contrato, e cada subclasse fornece seu método. É a base do polimorfismo, tema do tópico de herança. 

public abstract class Usuario {
    // operação (contrato): toda subclasse PRECISA ter este método
    public abstract String tipoDePerfil();
}

public class Ouvinte extends Usuario {
    // método (implementação) da operação para o ouvinte
    @Override
    public String tipoDePerfil() { return "Ouvinte"; }
}

public class Artista extends Usuario {
    @Override
    public String tipoDePerfil() { return "Artista"; }
}

Comando ou consulta: não misture

Um bom método faz uma dessas duas coisas: muda o estado (comando) ou responde uma pergunta (consulta). Quando faz as duas, o efeito colateral fica escondido e o código fica difícil de entender e de testar.

Comando — muda estado

void depositar(double valor)

Não retorna o saldo. Quem quiser ver o saldo chama getSaldo().

Consulta — só lê

double getSaldo()

Não altera nada. Pode ser chamada quantas vezes for preciso sem efeito colateral.

Efeito colateral escondido é uma das maiores fontes de bugs. Um método chamado getSaldo() que, por acidente, registra um log ou cobra uma taxa surpreende quem só queria ler. Nomes honestos evitam isso.

Nomes contam uma história de negócio

Compare duas operações que mexem no mesmo saldo. Os nomes dizem a intenção.

// Nome vago: não se sabe o porquê da movimentação
public void processar(double v) { ... }

// Nome de domínio: a intenção aparece no código e no extrato
public void debitarAssinatura(double valor, String descricao) { ... }
public void sacar(double valor) { ... }

Quando um método precisa de muitos parâmetros (quatro ou mais), é sinal de que falta um objeto que os agrupe. Esse agrupador se chama parameter object: 

// ⚠️ Muitos parâmetros soltos, fácil de trocar a ordem
public void reproduzir(String musicaId, String qualidade, String dispositivo, String regiao) { ... }

// ✅ Um objeto que nomeia o contexto
public record ContextoDeReproducao(String musicaId, String qualidade, String dispositivo, String regiao) {}
public void reproduzir(ContextoDeReproducao ctx) { ... }

Na indústria

Em sistemas financeiros, dinheiro nunca é double. Use BigDecimal, porque double acumula erros de arredondamento. O Melodia usa double apenas por didática.

Tipos ricos também evitam bugs: em vez de um int status com códigos mágicos, um enum como StatusAssinatura só aceita valores válidos, e o compilador reclama de valores errados. 

public enum StatusAssinatura { ATIVA, SUSPENSA, CANCELADA }

// O compilador impede o valor inválido "ATIVADA" ou "1"
private StatusAssinatura status = StatusAssinatura.ATIVA;

final: o atributo que não muda após a construção

Um atributo final recebe valor uma única vez, normalmente no construtor. Na modelagem, ele corresponde a um atributo somente leitura ({readOnly} na UML, ou {frozen} em algumas ferramentas). Mudanças de estado ficam restritas a operações explicitamente projetadas.

Cuidado: final protege a referência, não o objeto. Um final List continua aceitando add. Para proteger o conteúdo, é preciso uma lista imutável ou uma cópia defensiva. 

public class Playlist {
    private final String nome;                 // nunca muda após a criação
    private final List<Musica> musicas = new ArrayList<>();  // referência fixa, conteúdo muda

    public Playlist(String nome) { this.nome = nome; }

    public List<Musica> getMusicas() {
        return new ArrayList<>(musicas);        // cópia defensiva: o chamador não altera a playlist
    }
}
Objeto de valor: quando um conceito é definido só pelos seus valores (um dinheiro, um intervalo de datas, uma duração), faça-o imutável. Ele pode ser compartilhado sem risco, e é o caso natural do record do Java.

static: da constante à fábrica

Um membro static pertence à classe. Dois usos são comuns. O primeiro é a constante (static final), como a taxa de royalty. O segundo é o método de fábrica, que cria objetos com um nome que expressa a intenção, em vez de um construtor genérico. 

public class Plano {
    public static final Plano FREE    = new Plano("Free", 0, true);
    public static final Plano PREMIUM = new Plano("Premium", 19.90, false);

    private final String nome;
    private final double precoMensal;
    private final boolean comAnuncios;

    private Plano(String nome, double preco, boolean anuncios) {
        this.nome = nome; this.precoMensal = preco; this.comAnuncios = anuncios;
    }

    // fábrica: o nome expressa a intenção
    public static Plano familia(int membros) {
        if (membros < 2 || membros > 6) throw new IllegalArgumentException("família: 2 a 6 contas");
        return new Plano("Família", 29.90, false);
    }
}
Por que construtor privado: impede que alguém crie um plano “Premium” com preço errado. Os planos válidos existem como constantes ou fábricas, e o modelo declara isso como um enum ou uma classe com instâncias fixas.

Atributo derivado: quando calcular e quando guardar

O atributo derivado (/ na UML) é calculado a partir de outros. A regra geral é calcular, para evitar inconsistência. Há uma exceção legítima: quando o cálculo é caro e o dado de origem muda raramente. Nesse caso, guarda-se o valor em cache e invalida-se o cache em cada operação que altera a origem. A invalidação é o que torna o dado derivado seguro. 

public class Album {
    private final List<Musica> faixas = new ArrayList<>();
    private Integer duracaoCache;              // derivado guardado: pode ser nulo

    public Musica adicionarFaixa(String titulo, int d) {
        duracaoCache = null;                       // invalida o cache a cada mudança
        Musica m = new Musica(titulo, artista, d);
        faixas.add(m);
        return m;
    }

    public int duracaoTotal() {
        if (duracaoCache == null)
            duracaoCache = faixas.stream().mapToInt(Musica::getDuracaoSegundos).sum();
        return duracaoCache;
    }
}

Diga ao objeto o que fazer, não pergunte e decida por ele

O princípio Tell, Don't Ask (Hunt e Thomas, O Programador Pragmático) recomenda que o cliente mande o objeto agir, em vez de buscar os dados dele para decidir por ele. A decisão fica perto do dado que ela usa. 

// ❌ Ask: o cliente lê o saldo e decide. A regra fica espalhada.
if (conta.getSaldo() >= valor) {
    conta.setSaldo(conta.getSaldo() - valor);
}

// ✅ Tell: a conta decide e protege seu próprio invariante
conta.sacar(valor);
O cheiro do modelo anêmico: quando todo método é apenas “leia e decida fora”, a classe virou um saco de dados com getters e setters. A regra existe, mas está no lugar errado.

Exercícios

1. Um atributo final List<Musica> é suficiente para proteger a playlist de alterações externas?

Gabarito: não. O final impede trocar a lista, mas qualquer código que obtenha a referência pode chamar add. É preciso retornar uma cópia (cópia defensiva) ou uma visão imutável.

2. Reescreva o trecho “Ask” do exemplo como uma operação “Tell” em Assinatura, que cobra de uma conta.

Gabarito: assinatura.cobrar(conta), com cobrar verificando o status da assinatura e chamando conta.sacar(valor). A regra de cobrança fica na assinatura, e a conta protege o saldo.

3. Por que o construtor de Plano é privado no exemplo?

Gabarito: para que apenas os planos válidos existam (as constantes e as fábricas). Um construtor público permitiria criar um plano com preço ou regra inventados, contornando o modelo.

Experimente

Adicione em ContaBancaria um método transferir(ContaBancaria destino, double valor). Ele saca desta conta e deposita na outra. Que invariante corre risco se o saque funcionar e o depósito falhar?

Ver gabarito

O dinheiro pode sumir: a conta de origem já perdeu o valor. A solução é validar antes de mexer (saldo suficiente) e, se possível, desfazer o saque em caso de falha (rollback). Pela regra R5, cada lado também deveria registrar sua transação no extrato.

Teste seus conhecimentos

Qual método segue o princípio “comando × consulta”?

Correto. getSaldo() só responde uma pergunta, sem efeito colateral. O sacar da primeira opção mistura comando e consulta, e o processar tem nome vago.

Um atributo duracaoTotal é guardado e atualizado a cada música adicionada. Qual é o problema principal?

Correto. Se alguém esquecer de atualizar o total, ele mente. Como a duração pode ser calculada a partir das músicas, é melhor derivá-la no método do que guardá-la.

O que levar deste tópico

  • Atributos são o estado do objeto. Quase sempre private, para proteger os invariantes.
  • static é de classe (um para todos). Dado derivado é calculado, não guardado.
  • Operação é o contrato; método é a implementação. Subclasses implementam o mesmo contrato de jeitos diferentes.
  • Separe comando (muda estado) de consulta (lê). Use nomes do domínio e agrupe parâmetros demais.
