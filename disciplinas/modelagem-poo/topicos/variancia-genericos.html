Por que genéricos são invariantes

Em Java, Musica é subtipo de Reproduzivel. Mesmo assim, List<Musica> não é subtipo de List<Reproduzivel>. Isso parece contraintuitivo, e é a pergunta central deste tópico.

A razão é a segurança de escrita. Se List<Musica> fosse aceito como List<Reproduzivel>, o código abaixo compilaria, e falharia em tempo de execução:

List<Musica> musicas = new ArrayList<>();
List<Reproduzivel> alias = musicas;   // suposição: isto compilaria
alias.add(new Podcast("P", 600));       // aceito como Reproduzivel...
Musica m = musicas.get(0);              // ...mas aqui seria um Podcast dentro de List<Musica>!

Genéricos são invariantes justamente para impedir esse caso. Os wildcards existem para recuperar flexibilidade sem perder a segurança.

Definição formal: subtipagem e variância

Seja S <: T a relação “S é subtipo de T”. Um construtor de tipo F é:

  • covariante se S <: T implica F<S> <: F<T> (ex.: produtores, como leitura de uma coleção);
  • contravariante se S <: T implica F<T> <: F<S> (ex.: consumidores, como um Comparator);
  • invariante quando nenhuma das duas vale (o padrão de List<T> em Java).

Em Java, a variância pode ser declarada no uso, com ? extends T (covariância de leitura) e ? super T (contravariância de escrita). Linguagens como Kotlin (out/in) e C# (out/in em interfaces) declaram a variância na definição do tipo.

A relação de subtipagem usada em projeto é mais forte que a sintática. Liskov e Wing (1994) exigem subtipagem comportamental: o subtipo deve preservar as pré e pós-condições e os invariantes do tipo base. Um compilador verifica só a assinatura; a teoria exige também o comportamento.

PECS: Producer Extends, Consumer Super. Se a coleção produz valores para você, use ? extends. Se ela consome valores que você fornece, use ? super (Bloch, Effective Java, item 31).

import java.util.ArrayList;
import java.util.List;

/**
 * Variância e substituição de tipos genéricos.
 * Pergunta central: se Musica é um Reproduzivel, List<Musica> é um List<Reproduzivel>?
 */
public class Main {

    interface Reproduzivel { int duracao(); }
    record Musica(String titulo, int duracao) implements Reproduzivel {}
    record Podcast(String titulo, int duracao) implements Reproduzivel {}

    // Produtor (só lê): ? extends T  -> covariância segura para leitura
    static int somarDuracoes(List<? extends Reproduzivel> itens) {
        int total = 0;
        for (Reproduzivel r : itens) total += r.duracao();   // leitura: seguro
        return total;
    }

    // Consumidor (só escreve): ? super T  -> contravariância segura para escrita
    static void adicionarMusicas(List<? super Musica> destino, int n) {
        for (int i = 1; i <= n; i++) destino.add(new Musica("faixa " + i, 180));  // escrita: seguro
    }

    // PECS: Producer Extends, Consumer Super (Joshua Bloch, Effective Java)
    static <T> void copiar(List<? super T> destino, List<? extends T> origem) {
        destino.addAll(origem);
    }

    // F-bounded polymorphism: o tipo se compara consigo mesmo
    static abstract class Entidade<T extends Entidade<T>> implements Comparable<T> {
        abstract int chave();
        @Override public int compareTo(T outra) { return Integer.compare(chave(), outra.chave()); }
    }
    static final class Faixa extends Entidade<Faixa> {
        private final int ordem;
        Faixa(int ordem) { this.ordem = ordem; }
        @Override int chave() { return ordem; }
        @Override public String toString() { return "faixa#" + ordem; }
    }

    public static void main(String[] args) {
        System.out.println("=== 1. Covariância de leitura (? extends) ===");
        List<Musica> musicas = new ArrayList<>(List.of(new Musica("A", 200), new Musica("B", 150)));
        // List<Musica> NÃO é um List<Reproduzivel> (invariância), mas ? extends aceita as duas:
        List<Reproduzivel> mistos = new ArrayList<>(musicas);
        mistos.add(new Podcast("P", 600));
        System.out.println("soma (Musica): " + somarDuracoes(musicas));
        System.out.println("soma (misto):  " + somarDuracoes(mistos));

        System.out.println("\n=== 2. Contravariância de escrita (? super) ===");
        List<Object> destino = new ArrayList<>();
        adicionarMusicas(destino, 2);
        System.out.println("destino: " + destino);

        System.out.println("\n=== 3. PECS em um método genérico ===");
        List<Reproduzivel> fila = new ArrayList<>();
        copiar(fila, musicas);
        System.out.println("fila após copiar: " + fila.size() + " itens");

        System.out.println("\n=== 4. Armadilha da covariância de arrays (por que genéricos são invariantes) ===");
        Object[] arr = new String[1];          // arrays SÃO covariantes em Java
        try {
            arr[0] = Integer.valueOf(42);      // compila, mas falha em execução
        } catch (ArrayStoreException e) {
            System.out.println("ArrayStoreException: " + e.getMessage());
        }
        // List<Object> lista = new ArrayList<String>();  // NÃO compila: genéricos são invariantes

        System.out.println("\n=== 5. F-bounded: ordenação de tipos que se comparam a si mesmos ===");
        List<Faixa> ordem = new ArrayList<>(List.of(new Faixa(3), new Faixa(1), new Faixa(2)));
        java.util.Collections.sort(ordem);
        System.out.println(ordem);
    }
}

Armadilhas clássicas

  • Covariância de arrays: arrays em Java são covariantes, por isso a falha só aparece em execução (ArrayStoreException, caso 4 do exemplo). Genéricos foram projetados para evitar exatamente isso.
  • Tipos brutos (raw types): List sem parâmetro desliga a verificação. Compile sempre com -Xlint:unchecked.
  • Captura de wildcard: um método que recebe List<?> não pode adicionar nada (exceto null). A saída é um método auxiliar genérico, como o copiar do exemplo.

Exercícios

1. Por que Comparator<? super T> é a assinatura correta de sort?

Gabarito: o método consome elementos (compara-os). Um comparador de Reproduzivel serve para ordenar Musica, então precisamos de ? super Musica: o comparador aceita o tipo ou um supertipo.

2. Declare, em Kotlin ou C#, uma interface Fonte<out T>. O que o compilador impede?

Gabarito: impede que T apareça em posição de entrada (parâmetro de método). Assim Fonte<Musica> é seguro como Fonte<Reproduzivel>. É a variância verificada na definição, não no uso.
