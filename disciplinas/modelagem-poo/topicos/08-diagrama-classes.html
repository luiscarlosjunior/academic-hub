Três compartimentos, nessa ordem

O diagrama de classes é o mais usado de toda a UML — e o único que costuma sobreviver ao projeto, porque mapeia quase um para um no código. Cada classe é uma caixa com nome, atributos e operações.

Sintaxe de um atributo

visibilidade nome: tipo [multiplicidade] = valorPadrão

Exemplo: − itens: Item [1..*] · + ativo: boolean = true

Sintaxe de uma operação

visibilidade nome(param: tipo, …): tipoRetorno

Exemplo: + sacar(v: double): boolean

Convenções que valem lembrar

  • • Membros sublinhados são static (da classe, não da instância)
  • • Nome e métodos em itálico indicam abstract
  • • Compartimentos vazios podem ser omitidos
  • • Na fase de análise, mostre só o essencial — nada de getters e setters

De onde saem as classes?

  

    A técnica mais antiga e ainda a mais útil: sublinhe os substantivos da descrição do
    problema (candidatos a classe) e os verbos (candidatos a operação). Depois filtre.
  


  

    
Enunciado

    

    

      
      
      
    

  


  

    

      
Viram classes

      

        ClientePedido
        ProdutoItemPedido
      

      
Têm identidade, estado e comportamento próprios — e o sistema precisa guardá-los.

    

    

      
Viram atributos

      

        nomepreço
        quantidadedata
      

      
São valores simples que descrevem outra coisa; não existem sozinhos nem têm comportamento.

    

    

      
São descartados

      

        sistematela
        informaçãocadastro
      

      
Vagos, redundantes ou relativos à interface — não pertencem ao modelo de domínio.

    

  


  

    
    

      Três perguntas para filtrar um candidato: ele tem identidade própria (dois exemplares
      são distinguíveis)? Tem mais de um dado associado? O sistema faz alguma coisa com ele?
      Três “sim” → é classe. Um “não” → provavelmente é atributo.

Três perguntas sobre diagrama de classes.


  

    

      
1. Um membro sublinhado na caixa de classe indica:

      
      
      
      

        Abstrato é indicado por itálico; privado, pelo símbolo −. Sublinhado = estático,
        compartilhado por todas as instâncias.
      

    


    

      
2. “Endereço” deve ser classe ou atributo de Cliente?

      
      
      
      

        Se o sistema só imprime o endereço numa etiqueta, uma String basta. Se precisa filtrar por cidade,
        validar CEP ou guardar vários endereços por cliente, ele ganha identidade — e vira classe.
      

    


    

      
3. Na fase de análise, o diagrama de classes deve mostrar getters e setters?

      
      
      
      

        Getters e setters são detalhe de implementação, previsíveis a partir dos atributos. O que interessa no
        diagrama são as operações que revelam responsabilidade: calcularTotal(),
        aplicarDesconto().
