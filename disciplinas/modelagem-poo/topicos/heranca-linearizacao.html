O problema do diamante

Se D herda de B e C, e ambos herdam de A, qual implementação de um método definido em A e sobrescrito em B e C vence em D? A pergunta não tem resposta única sem uma regra. Essa regra é a ordem de resolução de métodos (MRO).

O algoritmo C3

O C3, proposto por Barrett et al. (1996) para o Dylan e adotado pelo Python 2.3 em diante, calcula a MRO de forma monotônica: a ordem relativa das superclasses é preservada em toda subclasse. Definição recursiva:

MRO(C) = C + merge( MRO(B1), ..., MRO(Bn), [B1, ..., Bn] )

A função merge pega, em ordem, a primeira cabeça de uma lista que não aparece na cauda de nenhuma outra. Se não houver candidato, a hierarquia é inconsistente e o C3 falha, o que é uma propriedade desejável: a ordem não existe.

Como Java resolve isso

Java proíbe herança múltipla de classes, mas permite várias interfaces com métodos default. Se duas interfaces definem o mesmo default, a classe é obrigada a sobrescrever e escolher explicitamente (Esquerda.super.m()). É uma escolha mais conservadora que a MRO: Java não aplica uma ordem automática, e falha em tempo de compilação quando a ambiguidade existe (JLS 9.4.1.3).

Contexto do exemplo

O código implementa o C3 em Java para um dicionário de bases e calcula a MRO do diamante. Também mostra a resolução explícita de conflito entre interfaces.

import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

/**
 * Herança múltipla e linearização (algoritmo C3, usado por Python e Dylan).
 * Em Java, classes têm uma superclasse, mas interfaces com default criam o mesmo problema
 * de ordem de resolução. Aqui calculamos a MRO (Method Resolution Order) do diamante.
 */
public class Main {

    /** C3: a MRO de C é C seguido da mesclagem das MROs das bases, preservando a ordem local. */
    static List<String> c3(String classe, Map<String, List<String>> bases) {
        List<String> basesDaClasse = bases.getOrDefault(classe, List.of());
        if (basesDaClasse.isEmpty()) return new ArrayList<>(List.of(classe));

        List<List<String>> seqs = new ArrayList<>();
        for (String b : basesDaClasse) seqs.add(c3(b, bases));
        seqs.add(new ArrayList<>(basesDaClasse));          // a lista das bases, na ordem declarada

        List<String> resultado = new ArrayList<>();
        resultado.add(classe);
        while (true) {
            seqs.removeIf(List::isEmpty);
            if (seqs.isEmpty()) return resultado;
            String candidato = null;
            for (List<String> s : seqs) {
                String cabeca = s.get(0);
                boolean naCauda = seqs.stream().anyMatch(t -> t.indexOf(cabeca) > 0);
                if (!naCauda) { candidato = cabeca; break; }
            }
            if (candidato == null) throw new IllegalStateException("hierarquia inconsistente");
            resultado.add(candidato);
            final String c = candidato;
            seqs.forEach(s -> s.remove(c));
        }
    }

    public static void main(String[] args) {
        // Diamante:      A
        //               / \
        //              B   C
        //               \ /
        //                D
        Map<String, List<String>> bases = new LinkedHashMap<>();
        bases.put("D", List.of("B", "C"));
        bases.put("B", List.of("A"));
        bases.put("C", List.of("A"));
        bases.put("A", List.of());

        System.out.println("MRO de D (C3): " + c3("D", bases));

        // Mesma situação em Java: duas interfaces com default de mesmo nome.
        System.out.println("\nJava exige resolver o conflito explicitamente:");
        System.out.println(new Dois().oi());
    }

    interface Esquerda { default String oi() { return "esquerda"; } }
    interface Direita  { default String oi() { return "direita"; } }
    static class Dois implements Esquerda, Direita {
        @Override public String oi() { return Esquerda.super.oi() + " + " + Direita.super.oi(); }
    }
}

Mixins e traits: composição de comportamento

Traits (Schärli et al., 2003) são unidades de comportamento que se compõem sem formar hierarquia. Um mixin é uma classe parametrizada pela superclasse. Os dois resolvem o problema de reuso sem o acoplamento da herança clássica. Em Java, o equivalente mais próximo é a composição com interfaces default; em Scala e Kotlin, traits e delegação (by) são usados no lugar de herança múltipla.

Exercícios

1. Calcule a MRO de D(C, B) com B(A) e C(A). A ordem das bases importa?

Gabarito: MRO = D, C, B, A. Sim, a ordem das bases importa: D prefere a primeira base declarada quando ambas oferecem o método.

2. Monte uma hierarquia para a qual o C3 falha. Por que a falha é desejável?

Gabarito: class X(A, B) e class Y(B, A), depois class Z(X, Y). As restrições pedem A antes de B e B antes de A: não há ordem. Falhar cedo é melhor que escolher uma ordem arbitrária em silêncio.
