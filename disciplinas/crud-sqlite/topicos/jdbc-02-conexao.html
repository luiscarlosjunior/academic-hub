JDBC e a conexão

JDBC é a API padrão do Java para bancos relacionais. O seu código conversa com as interfaces Connection, Statement e ResultSet, e o driver traduz as chamadas para o SQLite. Trocar de banco muda a URL e o driver, mas quase não muda o código.

String url = "jdbc:sqlite:biblioteca.db";
Connection con = DriverManager.getConnection(url);

A URL tem três partes: jdbc: (a API), sqlite: (o tipo de banco) e biblioteca.db (o arquivo). Um caminho relativo é resolvido a partir da pasta onde o programa roda, e não a partir da pasta do código. Por isso, pela IDE, o arquivo costuma aparecer na pasta do projeto.

Animação: o ciclo de vida da conexão

Acompanhe a conexão ser aberta, configurada, usada e fechada. A linha de estados mostra em que fase ela está em cada passo.

Passo a passo animado

O código abaixo é um trecho real do projeto. Avance com os botões ou use Animar: a linha em execução é destacada e a explicação acompanha.

public static void main(String[] args) throws Exception {
    Connection con = null;
    try {
        con = Conexao.abrir("demo02.db");
        System.out.println("conexão aberta: " + !con.isClosed());
        try (Statement st = con.createStatement();
             ResultSet rs = st.executeQuery("PRAGMA foreign_keys")) {
            rs.next();
            System.out.println("chave estrangeira ligada: " + (rs.getInt(1) == 1));
        }
    } finally {
        if (con != null) {
            con.close();
        }
    }
    System.out.println("conexão fechada: " + con.isClosed());
    new java.io.File("demo02.db").delete();
}

A chave estrangeira em cada conexão

O SQLite começa cada conexão com a verificação de chave estrangeira desligada. A classe Conexao executa PRAGMA foreign_keys = ON logo depois de abrir a conexão. Como a configuração vale só para aquela conexão, a regra é repetida em todas: ela fica num único método, Conexao.abrir, usado por toda a aplicação.

try-with-resources: fechar sempre

Uma conexão ocupa recursos do sistema operacional. O bloco try (...) declara os recursos entre parênteses, e o Java os fecha automaticamente ao sair do bloco, mesmo com exceção, na ordem inversa da declaração.

try (Connection con = Conexao.abrir("biblioteca.db");
     Statement st = con.createStatement()) {
    st.execute("CREATE TABLE IF NOT EXISTS teste (id INTEGER)");
}   // st e con são fechados aqui, nesta ordem

package demos;

import biblioteca.Conexao;
import java.sql.Connection;
import java.sql.ResultSet;
import java.sql.Statement;

/** Tópico 2: abrir, usar e fechar uma conexão com try-with-resources. */
public class Demo02Conexao {

    public static void main(String[] args) throws Exception {
        Connection con = null;
        try {
            con = Conexao.abrir("demo02.db");
            System.out.println("conexão aberta: " + !con.isClosed());
            try (Statement st = con.createStatement();
                 ResultSet rs = st.executeQuery("PRAGMA foreign_keys")) {
                rs.next();
                System.out.println("chave estrangeira ligada: " + (rs.getInt(1) == 1));
            }
        } finally {
            if (con != null) {
                con.close();
            }
        }
        System.out.println("conexão fechada: " + con.isClosed());
        new java.io.File("demo02.db").delete();
    }
}

Erros comuns

  • Esquecer a chave estrangeira: a aplicação aceita dados órfãos sem reclamar. Confirme com PRAGMA foreign_keys.
  • Conexão aberta e não fechada: em testes, o arquivo fica travado para outros processos.
  • URL com erro: jdbc:sqlite sem os dois pontos, ou outro prefixo, gera No suitable driver found.

Exercícios

1. Escreva um método que abre um arquivo, conta as tabelas e fecha tudo corretamente.

Gabarito: try (Connection con = Conexao.abrir(arq); Statement st = con.createStatement(); ResultSet rs = st.executeQuery("SELECT COUNT(*) FROM sqlite_master WHERE type='table'")) { rs.next(); return rs.getInt(1); }. Os três recursos são fechados automaticamente.

2. Por que o PRAGMA é executado dentro de Conexao.abrir, e não no código que chama o método?

Gabarito: para que nenhum ponto da aplicação esqueça a regra. Centralizar a configuração garante que toda conexão nasça com a chave estrangeira ligada.
