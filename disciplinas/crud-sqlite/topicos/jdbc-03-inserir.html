Statement ou PreparedStatement?

Statement executa um texto SQL pronto. PreparedStatement recebe o texto com marcas ?, e os valores são enviados separadamente. A diferença é de segurança e de clareza:

StatementPreparedStatement
Valores vindos do usuárioconcatenados no texto: vulnerável à injeção de SQLenviados separados: o banco nunca os interpreta como comando
Tipos dos valoresconvertidos no textosetters tipados (setString, setInt)
Uso típicoDDL fixo, como CREATE TABLEtudo que recebe valores
// ERRADO: o nome vira parte do comando
st.executeUpdate("INSERT INTO livro (titulo) VALUES ('" + titulo + "')");

// CERTO: o valor é enviado separado
PreparedStatement ps = con.prepareStatement("INSERT INTO livro (titulo) VALUES (?)");
ps.setString(1, titulo);
ps.executeUpdate();

Animação: inserir um livro e receber o id

Acompanhe o método inserir do projeto. O id não é enviado pelo programa: ele é gerado pelo banco e devolvido ao final.

Passo a passo animado

O código abaixo é um trecho real do projeto. Avance com os botões ou use Animar: a linha em execução é destacada e a explicação acompanha.

public long inserir(Livro livro) throws SQLException {
    String sql = "INSERT INTO livro (titulo, ano, preco, isbn) VALUES (?, ?, ?, ?)";
    try (PreparedStatement ps = con.prepareStatement(sql, Statement.RETURN_GENERATED_KEYS)) {
        ps.setString(1, livro.titulo().strip());
        ps.setInt(2, livro.ano());
        ps.setDouble(3, livro.preco());
        ps.setString(4, livro.isbn());
        ps.executeUpdate();
        try (ResultSet chaves = ps.getGeneratedKeys()) {
            chaves.next();
            return chaves.getLong(1);
        }
    }
}

Inserção em lote

addBatch() acumula um INSERT por livro, e executeBatch() envia tudo de uma vez. Combinado com transação (aula 6), o lote é tudo ou nada: se um livro falhar, nenhum entra. O projeto faz isso em inserirLote, com setAutoCommit(false) e commit() no sucesso.

A demonstração cria a tabela, insere um livro e recebe o id, insere três livros em lote e tenta um ISBN repetido, que o banco recusa com o código 19.

package demos;

import biblioteca.Conexao;
import biblioteca.Livro;
import biblioteca.LivroDao;
import java.sql.Connection;
import java.util.List;

/** Tópico 3: criar a tabela e inserir (C do CRUD), com id gerado e inserção em lote. */
public class Demo03Inserir {

    public static void main(String[] args) throws Exception {
        String arq = "demo03.db";
        new java.io.File(arq).delete();
        try (Connection con = Conexao.abrir(arq)) {
            Conexao.criarTabelas(con);
            LivroDao dao = new LivroDao(con);

            long id = dao.inserir(new Livro(null, "  Dom Casmurro ", 1899, 29.9, "978-1"));
            System.out.println("id gerado: " + id);

            int n = dao.inserirLote(List.of(
                    new Livro(null, "Vidas Secas", 1938, 24.5, "978-3"),
                    new Livro(null, "Capitães da Areia", 1937, 34.0, "978-4")));
            System.out.println("lote enviado: " + n + " comandos");
            System.out.println("total na tabela: " + dao.contar());

            try {
                dao.inserir(new Livro(null, "Repetido", 2000, 1, "978-1"));
            } catch (java.sql.SQLException e) {
                System.out.println("isbn repetido recusado: código " + e.getErrorCode());
            }
        }
        new java.io.File(arq).delete();
    }
}

Erros comuns

  • Ler o id com SELECT MAX(id): outro usuário pode inserir entre as duas consultas. Use getGeneratedKeys().
  • Esquecer next() nas chaves geradas: o cursor começa antes da primeira linha.
  • Preparar o comando dentro do laço: prepare uma vez e troque só os valores.

Exercícios

1. Escreva inserirAutor(String nome) que devolve o id gerado, sem concatenação.

Gabarito: PreparedStatement ps = con.prepareStatement("INSERT INTO autor (nome) VALUES (?)", Statement.RETURN_GENERATED_KEYS); ps.setString(1, nome); ps.executeUpdate(); try (ResultSet rs = ps.getGeneratedKeys()) { rs.next(); return rs.getLong(1); }.

2. Por que o lote usa transação, se cada INSERT já é atômico?

Gabarito: cada INSERT é atômico, mas o lote é um conjunto deles. Sem transação, os primeiros livros ficariam gravados antes da falha do quinto. A transação torna o conjunto atômico.
