A forma do DELETE e o WHERE

DELETE FROM livro WHERE id = 7;

Como no UPDATE, sem WHERE todas as linhas são removidas. E como não há lixeira, a remoção é permanente, a menos que exista backup ou uma transação aberta.

O que acontece com as linhas relacionadas

A chave estrangeira diz o que fazer quando a linha referenciada é apagada. As três ações mais usadas:

AçãoComportamentoUso típico
RESTRICT / sem açãorecusa a exclusão enquanto houver filhosempréstimo impede apagar o livro
CASCADEapaga as linhas dependentes juntovínculos de livro_autor ao apagar o livro
SET NULLzera a chave estrangeira dependentefuncionário sem departamento

A escolha entre as ações é uma decisão de negócio. CASCADE em vínculos (como a tabela de junção) costuma ser seguro. CASCADE em registros de histórico, como empréstimos, pode apagar informação que a empresa precisa guardar por lei.

Exclusão lógica

Em vez de apagar, marque a linha como excluída. Assim o histórico permanece, a auditoria continua possível, e a restauração é um UPDATE. O custo é que toda consulta precisa filtrar os excluídos (WHERE excluido = 0), e isso deve ser feito em um lugar só do código (ou em uma VIEW, tópico 12).

Exemplo executável: restrição, cascata e exclusão lógica

O script tenta apagar um livro que tem empréstimo (e é recusado), devolve e apaga o empréstimo, apaga o livro (e a cascata remove o vínculo com o autor, mas o autor continua existindo), e por fim faz uma exclusão lógica.

import sqlite3

con = sqlite3.connect(":memory:")
con.executescript(open("biblioteca_schema.sql", encoding="utf-8").read())
con.execute("INSERT INTO autor (id, nome) VALUES (1, 'Machado de Assis')")
con.execute("INSERT INTO livro (id, titulo, ano) VALUES (1, 'Dom Casmurro', 1899)")
con.execute("INSERT INTO livro_autor VALUES (1, 1)")
con.execute("INSERT INTO cliente (id, nome, email) VALUES (1, 'Ana', 'ana@x.com')")
con.execute("INSERT INTO emprestimo (livro_id, cliente_id, data_saida) VALUES (1, 1, '2026-10-01')")

# D de CRUD: DELETE. Sempre com WHERE, e conferir antes com SELECT.
print("candidatos:", con.execute("SELECT id, titulo FROM livro WHERE ano < 1900").fetchall())

# ON DELETE RESTRICT: livro com empréstimo não pode ser apagado
try:
    con.execute("DELETE FROM livro WHERE id = 1")
except sqlite3.IntegrityError as e:
    print("apagar livro emprestado:", "RECUSADO -", e)

# ON DELETE CASCADE: apagar o livro leva junto as linhas de livro_autor
con.execute("UPDATE emprestimo SET devolvido = 1")
con.execute("DELETE FROM emprestimo")
cur = con.execute("DELETE FROM livro WHERE id = 1")
print("livro apagado, linhas:", cur.rowcount)
print("vínculos restantes em livro_autor:", con.execute("SELECT count(*) FROM livro_autor").fetchone()[0])
print("autor continua existindo:", con.execute("SELECT nome FROM autor").fetchall())

# Exclusão lógica: marca em vez de apagar (preserva histórico e auditoria)
con.execute("ALTER TABLE autor ADD COLUMN excluido INTEGER NOT NULL DEFAULT 0")
con.execute("UPDATE autor SET excluido = 1 WHERE id = 1")
print("consulta normal depois da exclusão lógica:", con.execute("SELECT nome FROM autor WHERE excluido = 0").fetchall())

Erros comuns

  • DELETE sem WHERE: o banco executa sem reclamar.
  • Ignorar a pragma de chave estrangeira: sem ela, o DELETE apaga o pai e deixa filhos órfãos, sem nenhuma recusa.
  • Apagar em cascata sem pensar: um DELETE de cliente pode apagar todo o histórico de empréstimos. Modele a política antes.

Exercícios

1. Por que o autor continuou existindo depois que o livro foi apagado?

Gabarito: o CASCADE está na chave estrangeira de livro_autor, que aponta para livro. Ao apagar o livro, apagam-se as linhas de junção. A tabela autor não tem chave estrangeira para livro, então nada a afeta.

2. Escreva a exclusão lógica de um cliente e a consulta dos clientes ativos.

Gabarito: UPDATE cliente SET excluido = 1 WHERE id = ?; consulta: SELECT * FROM cliente WHERE excluido = 0.
