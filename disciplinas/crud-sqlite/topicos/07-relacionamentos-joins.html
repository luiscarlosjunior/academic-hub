Relações N:N não podem ser implementadas diretamente. Um livro com vários autores não cabe numa coluna autor_id sem perder informação. A solução é uma tabela intermediária, livro_autor, com uma linha para cada par.

A tabela de junção

CREATE TABLE livro_autor (
    livro_id INTEGER NOT NULL REFERENCES livro(id) ON DELETE CASCADE,
    autor_id INTEGER NOT NULL REFERENCES autor(id) ON DELETE CASCADE,
    PRIMARY KEY (livro_id, autor_id)
);

A chave primária composta impede que o mesmo par seja inserido duas vezes. Isso é a integridade de N:N: não existe como dizer duas vezes que o livro 1 é do autor 1.

INNER JOIN: só o que casa

O INNER JOIN devolve apenas as combinações em que a condição de junção é verdadeira nos dois lados. Um livro sem autor não aparece, e um autor sem livro também não.

SELECT l.titulo, a.nome
FROM livro l
JOIN livro_autor la ON la.livro_id = l.id
JOIN autor a        ON a.id = la.autor_id;

LEFT JOIN: tudo da esquerda

O LEFT JOIN mantém todas as linhas da tabela da esquerda, e preenche com NULL as colunas da direita quando não há par. É a forma de perguntar “quais livros não têm autor cadastrado?”, combinando LEFT JOIN com WHERE a.id IS NULL.

Exemplo executável: N:N e 1:N

O script mostra o INNER JOIN e o LEFT JOIN no relacionamento N:N, e uma agregação com LEFT JOIN no relacionamento 1:N, contando os empréstimos de cada cliente. Repare que o cliente sem empréstimo, se existisse, apareceria com zero.

Ver o código completo 
import sqlite3

con = sqlite3.connect(":memory:")
con.executescript(open("biblioteca_schema.sql", encoding="utf-8").read())
con.executemany("INSERT INTO autor (id, nome) VALUES (?,?)",
                [(1, "Machado de Assis"), (2, "Graciliano Ramos"), (3, "Autor sem livro")])
con.executemany("INSERT INTO livro (id, titulo, ano, preco) VALUES (?,?,?,?)",
                [(1, "Dom Casmurro", 1899, 29.9), (2, "Vidas Secas", 1938, 24.5), (3, "Livro sem autor", 2000, 10.0)])
# N:N: um livro pode ter vários autores, e um autor vários livros
con.executemany("INSERT INTO livro_autor (livro_id, autor_id) VALUES (?,?)",
                [(1, 1), (2, 2)])

print("INNER JOIN (só o que tem par nas duas tabelas):")
for r in con.execute("""SELECT l.titulo, a.nome FROM livro l
                        JOIN livro_autor la ON la.livro_id = l.id
                        JOIN autor a ON a.id = la.autor_id ORDER BY l.id"""):
    print("  ", r)

print("\nLEFT JOIN (todos os livros, com ou sem autor):")
for r in con.execute("""SELECT l.titulo, a.nome FROM livro l
                        LEFT JOIN livro_autor la ON la.livro_id = l.id
                        LEFT JOIN autor a ON a.id = la.autor_id ORDER BY l.id"""):
    print("  ", r)

print("\n1:N: cliente com seus empréstimos")
con.execute("INSERT INTO cliente (id, nome, email) VALUES (1, 'Ana', 'ana@x.com')")
con.executemany("INSERT INTO emprestimo (livro_id, cliente_id, data_saida) VALUES (?,?,?)",
                [(1, 1, "2026-10-01"), (2, 1, "2026-10-05")])
for r in con.execute("""SELECT c.nome, count(e.id) AS emprestimos FROM cliente c
                        LEFT JOIN emprestimo e ON e.cliente_id = c.id GROUP BY c.id"""):
    print("  ", r)

Do diagrama de classes à tabela

Um diagrama de classes da modelagem vira tabelas com regras simples. Uma associação 1:N vira uma chave estrangeira. Uma associação N:N vira uma tabela de junção. Uma composição (por exemplo, o livro com suas edições) costuma virar uma chave estrangeira com ON DELETE CASCADE, porque a parte não faz sentido sem o todo. Essa correspondência é o elo entre a disciplina de modelagem e este curso.

Erros comuns

  • Esquecer a condição do JOIN: sem ON, o resultado é o produto cartesiano, com todas as combinações possíveis.
  • Filtrar no WHERE uma tabela do LEFT JOIN: WHERE a.nome = 'X' transforma o LEFT JOIN em INNER JOIN. A condição sobre a tabela da direita deve ir no ON.
  • Relacionamento N:N como coluna com lista: autores = 'Ana,Bruno' viola a primeira forma normal e impede consultas por autor.

Exercícios

1. Escreva a consulta dos livros sem nenhum autor cadastrado.

Gabarito: SELECT l.titulo FROM livro l LEFT JOIN livro_autor la ON la.livro_id = l.id WHERE la.livro_id IS NULL. A condição IS NULL na coluna da junção identifica quem não tem par.

2. Por que a chave primária de livro_autor é composta e não existe uma coluna id própria?

Gabarito: a identidade do vínculo é o próprio par (livro, autor). Um id extra seria redundante e permitiria duplicar o mesmo par.
