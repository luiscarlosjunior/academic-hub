O que é um banco de dados e um SGBD

Um banco de dados é uma coleção organizada de informações persistentes. O programa que gerencia esse acervo, controlando leitura, escrita, concorrência e recuperação, é o SGBD (sistema gerenciador de banco de dados). Exemplos conhecidos são PostgreSQL, MySQL, Oracle e o SQLite, que é o objeto deste curso.

Sem um SGBD, cada programa precisaria inventar a própria forma de guardar dados em arquivos. Os problemas costumam ser os mesmos: dois programas escrevendo ao mesmo tempo corrompem o arquivo, uma falha de energia no meio de uma gravação deixa dados pela metade, e buscar um registro exige ler tudo. O SGBD resolve essas três questões com transações, controle de concorrência e índices.

O modelo relacional: tabelas, linhas e colunas

No modelo relacional, a informação é organizada em tabelas. Cada tabela tem colunas, que definem os atributos, e linhas, que são os registros. Todas as linhas de uma tabela têm as mesmas colunas, e cada coluna tem um tipo de dado.

O conceito mais importante é a chave primária: uma coluna (ou conjunto de colunas) cujo valor identifica uma única linha. Sem chave primária, não há como dizer, sem ambiguidade, qual registro estamos alterando.

Chaves: primária e estrangeira

A chave primária (PRIMARY KEY) é a identidade da linha. Não pode se repetir e não pode ser nula. No SQLite, uma coluna INTEGER PRIMARY KEY recebe automaticamente um número único a cada inserção.

A chave estrangeira (FOREIGN KEY) é uma coluna que aponta para a chave primária de outra tabela. Ela é o que transforma tabelas soltas em um modelo relacional: um empréstimo aponta para um livro e para um cliente, e o banco pode recusar um empréstimo que aponte para um livro inexistente. Esse tema é aprofundado no tópico de restrições.

As categorias da linguagem SQL

SQL (Structured Query Language) é a linguagem padrão para falar com bancos relacionais. Seus comandos se dividem em categorias, e é útil conhecê-las porque a documentação as usa:

CategoriaSiglaComandosPara que serve
Definição de dadosDDLCREATE, ALTER, DROPCriar e mudar a estrutura
Manipulação de dadosDMLINSERT, UPDATE, DELETEAlterar o conteúdo
Consulta de dadosDQLSELECTLer o conteúdo
Controle de transaçãoTCLBEGIN, COMMIT, ROLLBACK, SAVEPOINTAgrupar alterações

O CRUD, que dá nome a este curso, é a combinação das operações de manipulação e consulta: Create (INSERT), Read (SELECT), Update (UPDATE) e Delete (DELETE).

O que é o SQLite

O SQLite é um SGBD relacional embutido: não há servidor separado, e o banco inteiro é um único arquivo no disco. A biblioteca é linkada ao programa, e qualquer aplicação que a use já tem um banco completo. Isso o torna comum em celulares, navegadores, sistemas embarcados e em aplicações de porte pequeno a médio.

  • Serverless: não há processo servidor. A aplicação abre o arquivo diretamente.
  • Transacional (ACID): cada transação é atômica, consistente, isolada e durável (tópico 10).
  • Escritor único: em um dado momento, apenas uma conexão escreve. Leitores podem ler em paralelo, sobretudo com o modo WAL (tópico 15).
  • Tipagem dinâmica com afinidade: o tipo fica com o valor, e a coluna sugere um tipo (tópico 3).
Quando não usar: muitos servidores escrevendo ao mesmo tempo no mesmo banco, ou um volume de escrita concorrente muito alto. Nesses casos, um SGBD cliente-servidor como PostgreSQL costuma ser a escolha correta.

Exemplo executável: chave primária e categorias

O exemplo mostra uma linha identificada pela chave, a recusa de uma chave repetida e a listagem de tabelas pela tabela de sistema sqlite_master.

Exemplo executável

Este programa roda de ponta a ponta. A saída abaixo é a execução real, feita com Python 3.13 e SQLite 3.45.

import sqlite3

# Conceito 1: tabela = conjunto de linhas com as mesmas colunas
# Conceito 2: chave primária identifica uma linha de forma única
con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE autor (id INTEGER PRIMARY KEY, nome TEXT NOT NULL)")
con.execute("INSERT INTO autor (id, nome) VALUES (1, 'Clarice Lispector')")

print("linha com id 1 :", con.execute("SELECT * FROM autor WHERE id = 1").fetchone())
try:
    con.execute("INSERT INTO autor (id, nome) VALUES (1, 'Outro nome')")
except sqlite3.IntegrityError as e:
    print("chave repetida:", e)

# Conceito 3: linguagem SQL em categorias
#   DDL (definição): CREATE, ALTER, DROP
#   DML (manipulação): INSERT, UPDATE, DELETE
#   DQL (consulta): SELECT
#   TCL (transação): BEGIN, COMMIT, ROLLBACK, SAVEPOINT
#   DCL (controle): GRANT, REVOKE  -> o SQLite não tem usuários; o controle é o do arquivo
print("\ntabelas no banco:", [r[0] for r in con.execute("SELECT name FROM sqlite_master WHERE type='table'")])
print("arquivo de banco em memória?", con.execute("PRAGMA database_list").fetchone()[2] == "")

Erros comuns

  • Tratar o banco como uma planilha: dados que dependem uns dos outros precisam de chave estrangeira, e não de um texto com o nome da outra tabela.
  • Chave primária baseada em dado que muda: nome de pessoa ou título de livro podem mudar. Use um identificador estável.
  • Confundir o SGBD com o arquivo: copiar o arquivo com o programa aberto pode gerar uma cópia inconsistente. Veja o tópico de backup.

Exercícios

1. Uma tabela de empréstimos guarda o título do livro em texto, em vez de guardar o id. Quais problemas isso traz?

Gabarito: o título pode ser repetido (duas edições com o mesmo nome), pode ser corrigido em um lugar e não no outro, e não há como garantir que o livro exista. Usar livro_id como chave estrangeira resolve os três problemas.

2. Classifique os comandos: UPDATE, CREATE TABLE, SELECT, GRANT, COMMIT.

Gabarito: UPDATE é DML; CREATE TABLE é DDL; SELECT é DQL; GRANT é DCL; COMMIT é TCL.
