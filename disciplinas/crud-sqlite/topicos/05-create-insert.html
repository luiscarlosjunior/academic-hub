A forma do INSERT

INSERT INTO autor (nome) VALUES ('Machado de Assis');
INSERT INTO autor (nome) VALUES ('Clarice Lispector'), ('Graciliano Ramos');   -- lote

Nomeie as colunas. Um INSERT INTO autor VALUES (...) sem a lista de colunas depende da ordem exata das colunas no CREATE, e quebra silenciosamente quando alguém adiciona uma coluna no meio.

O id gerado e o lastrowid

Quando a chave primária é INTEGER PRIMARY KEY, o banco gera o valor sozinho. Para saber qual foi, o módulo Python oferece cursor.lastrowid, logo após o INSERT. Isso é essencial quando a linha inserida precisa ser ligada a outras (por exemplo, o autor recém-criado que vai para um livro).

RETURNING: devolver o que foi gravado

A partir do SQLite 3.35, a cláusula RETURNING devolve colunas da linha inserida, sem uma consulta extra. Isso evita a condição de corrida de “inserir e depois consultar”, que poderia pegar outra linha.

INSERT INTO livro (titulo, ano) VALUES ('Vidas Secas', 1938) RETURNING id, titulo;

Parâmetros: o antídoto contra injeção de SQL

Nunca monte SQL concatenando dados de usuário. Se o nome digitado for x'); DROP TABLE autor; --, a concatenação transforma a consulta em duas instruções, e a segunda apaga a tabela. Com parâmetros (?), o banco recebe o valor já separado do comando, e o texto é guardado literalmente.

# ERRADO: o valor vira parte do comando
con.execute(f"INSERT INTO autor (nome) VALUES ('{nome}')")

# CERTO: o valor é enviado separado do comando
con.execute("INSERT INTO autor (nome) VALUES (?)", (nome,))
Regra sem exceção: qualquer valor que venha de fora do programa (formulário, API, arquivo) entra por parâmetro. Nomes de tabela e coluna não podem ser parâmetros; se forem dinâmicos, valide contra uma lista fixa.

Inserção em lote

executemany executa o mesmo INSERT para uma lista de valores, dentro de uma única transação. Em uma importação de milhares de linhas, isso é ordens de grandeza mais rápido do que um INSERT por vez com commit em cada um.

Exemplo executável

O script insere um autor, um lote de dois, um livro com RETURNING e tenta gravar um nome malicioso. Repare que a tabela continua existindo e que o nome foi guardado como texto.

import sqlite3

con = sqlite3.connect(":memory:")
con.executescript(open("biblioteca_schema.sql", encoding="utf-8").read())

# C de CRUD: INSERT simples, com retorno do id gerado
cur = con.execute("INSERT INTO autor (nome) VALUES (?)", ("Machado de Assis",))
print("id gerado:", cur.lastrowid)

# Vários registros de uma vez
con.executemany("INSERT INTO autor (nome) VALUES (?)",
                [("Clarice Lispector",), ("Graciliano Ramos",)])

# RETURNING (SQLite 3.35+): devolve os dados inseridos, sem nova consulta
linha = con.execute(
    "INSERT INTO livro (titulo, ano, isbn, preco) VALUES (?, ?, ?, ?) RETURNING id, titulo",
    ("Memórias Póstumas", 1881, "978-2", 39.9)).fetchone()
print("RETURNING:", linha)

# Parametrização: nunca monte SQL com f-string a partir de dados do usuário
entrada_maliciosa = "x'); DROP TABLE autor; --"
con.execute("INSERT INTO autor (nome) VALUES (?)", (entrada_maliciosa,))
print("tabela autor ainda existe:", con.execute("SELECT count(*) FROM autor").fetchone()[0], "registros")
print("nome guardado literalmente:", con.execute("SELECT nome FROM autor WHERE id = last_insert_rowid()").fetchone()[0])
con.commit()

Erros comuns

  • f-string em SQL: é o caminho mais curto para a injeção de SQL.
  • Esquecer o commit: a inserção não é persistida. Com with con: o commit é automático.
  • Ler o id de outra consulta: SELECT max(id) pode trazer o id de outro usuário concorrente. Use lastrowid ou RETURNING.

Exercícios

1. Escreva uma função cadastrar_autor(con, nome) que devolva o id criado, de forma segura.

Gabarito: cur = con.execute("INSERT INTO autor (nome) VALUES (?)", (nome,)); con.commit(); return cur.lastrowid. Parâmetro para o nome, e lastrowid para o id.

2. Por que executemany é mais rápido que um laço de execute?

Gabarito: o laço com commit por linha força uma gravação em disco por linha; o lote reúne tudo numa transação e grava uma vez. O número de transações é o fator que mais pesa.
