CREATE TABLE: a forma geral

CREATE TABLE nome (
    coluna tipo restrições,
    ...
    restrições de tabela
);

Use CREATE TABLE IF NOT EXISTS em scripts de inicialização: a segunda execução não falha. Nomes de tabela e coluna são identificadores; prefira minúsculas, sem acentos e sem espaços, porque isso evita aspas em todas as consultas.

Os cinco tipos de armazenamento

O SQLite armazena cada valor com um de cinco tipos de armazenamento:

TipoO que guardaExemplo
INTEGERinteiros de até 8 bytes42, -7
REALponto flutuante de 8 bytes3.5
TEXTtexto em UTF-8, UTF-16 ou UTF-32'Dom Casmurro'
BLOBdados binários, exatamente como recebidosx'DEADBEEF'
NULLausência de valorNULL

Não existe tipo nativo para data, booleano ou dinheiro. Por convenção, datas são guardadas como TEXT no formato ISO 8601 ('2026-10-23'), que se ordena corretamente como texto; booleanos são INTEGER 0 ou 1; valores monetários podem ser INTEGER em centavos, o que evita erro de arredondamento de REAL.

Tipagem por afinidade

Diferente de bancos como PostgreSQL, o SQLite não impede que uma coluna receba um valor de outro tipo. Cada coluna tem uma afinidade, que é a conversão preferida. Se o valor puder ser convertido, ele é; se não, é guardado como veio.

O exemplo mostra o efeito: a coluna n (INTEGER) recebe o texto '42' e guarda o inteiro 42; já o texto 'texto livre' continua texto. Use typeof() para ver o tipo real de cada valor.

Cuidado: a afinidade não valida dados. Para garantir um formato, use CHECK (tópico 4) e, se possível, a aplicação deve validar antes de gravar.

ALTER TABLE: mudar a estrutura

ALTER TABLE livro ADD COLUMN editora TEXT;        -- nova coluna
ALTER TABLE livro RENAME COLUMN editora TO casa;   -- renomear (SQLite 3.25+)
ALTER TABLE livro DROP COLUMN casa;               -- remover (SQLite 3.35+)
ALTER TABLE livro RENAME TO obra;                 -- renomear a tabela

O SQLite tem menos suporte a ALTER que outros bancos: não é possível mudar o tipo de uma coluna nem alterar uma restrição existente. Nesses casos, o procedimento padrão é criar uma tabela nova, copiar os dados, apagar a antiga e renomear a nova. O tópico de migrações mostra esse padrão.

DROP TABLE: remover de vez

DROP TABLE remove a tabela, os dados, os índices e os gatilhos associados. Não há lixeira nem desfazer fora de uma transação. Por isso, em produção, faça backup antes (tópico 15).

DROP TABLE IF EXISTS tabela_antiga;   -- não falha se a tabela não existir

Exemplo executável: tipos, ALTER e DROP

O script cria uma tabela com cinco colunas de tipos diferentes, insere valores que testam a afinidade, mostra os tipos reais, altera a estrutura e remove a tabela.

Este programa roda de ponta a ponta. A saída abaixo é a execução real, feita com Python 3.13 e SQLite 3.45.

Ver o código completo 
import sqlite3

con = sqlite3.connect(":memory:")

# DDL: CREATE, ALTER, DROP. Aqui, a tabela de teste de tipos.
con.execute("CREATE TABLE tipos (id INTEGER PRIMARY KEY, n INTEGER, r REAL, t TEXT, b BLOB)")

# SQLite usa tipagem por afinidade: o valor é convertido se possível.
con.execute("INSERT INTO tipos (n, r, t, b) VALUES ('42', '3.5', 123, x'DEADBEEF')")
con.execute("INSERT INTO tipos (n, r, t, b) VALUES ('texto livre', 'x', 'ok', NULL)")

print("valores e tipos reais armazenados:")
for row in con.execute("SELECT id, n, typeof(n), r, typeof(r), t, typeof(t) FROM tipos"):
    print("  ", row)

# ALTER TABLE: adicionar, renomear e remover colunas
con.execute("ALTER TABLE tipos ADD COLUMN ativo INTEGER NOT NULL DEFAULT 1")
con.execute("ALTER TABLE tipos RENAME COLUMN t TO descricao")
con.execute("ALTER TABLE tipos DROP COLUMN b")
print("\ncolunas após ALTER:", [c[1] for c in con.execute("PRAGMA table_info(tipos)")])

# DROP TABLE remove a tabela e os dados. Não há lixeira.
con.execute("DROP TABLE tipos")
print("tabelas após DROP:", con.execute("SELECT count(*) FROM sqlite_master WHERE type='table'").fetchone()[0])

Erros comuns

  • Usar REAL para dinheiro: 0.1 + 0.2 não é exatamente 0,3 em ponto flutuante. Guarde centavos em INTEGER.
  • Guardar data como número sem padrão: 10/10/26 e 2026-10-10 não se ordenam juntos. Use ISO 8601.
  • DROP sem WHERE na mente: DROP TABLE não pede confirmação. Revise o nome antes de executar.

Exercícios

1. Escreva o CREATE TABLE de uma tabela produto com id, nome, preço em centavos e data de cadastro.

Gabarito: CREATE TABLE produto (id INTEGER PRIMARY KEY, nome TEXT NOT NULL, preco_centavos INTEGER NOT NULL, cadastrado_em TEXT NOT NULL). Preço em centavos evita arredondamento; data em TEXT ISO 8601.

2. Por que o SQLite aceitou o texto '42' numa coluna INTEGER?

Gabarito: a afinidade INTEGER converte o texto para inteiro quando a conversão é exata. Por isso o valor foi armazenado como 42 (INTEGER).
