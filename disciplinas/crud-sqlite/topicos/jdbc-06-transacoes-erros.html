Transação no JDBC

Por padrão, o JDBC confirma cada instrução sozinha, assim que ela termina. Para agrupar várias instruções, desligue esse comportamento com setAutoCommit(false). Nada vale até o commit(). Se algo der errado, o rollback() desfaz tudo desde o último commit.

Animação: a troca de preços como transação

O método trocarPrecos lê os dois preços e faz duas atualizações. Acompanhe o caminho feliz e depois o caminho de erro, em que o segundo livro não existe e tudo é desfeito.

Passo a passo animado

O código abaixo é um trecho real do projeto. Avance com os botões ou use Animar: a linha em execução é destacada e a explicação acompanha.

public void trocarPrecos(long idA, long idB) throws SQLException {
    boolean autoCommitAntes = con.getAutoCommit();
    con.setAutoCommit(false);
    try {
        double precoA = precoDe(idA);
        double precoB = precoDe(idB);
        try (PreparedStatement ps = con.prepareStatement("UPDATE livro SET preco = ? WHERE id = ?")) {
            ps.setDouble(1, precoB);
            ps.setLong(2, idA);
            ps.executeUpdate();
            ps.setDouble(1, precoA);
            ps.setLong(2, idB);
            ps.executeUpdate();
        }
        con.commit();
    } catch (SQLException e) {
        con.rollback();
        throw e;
    } finally {
        con.setAutoCommit(autoCommitAntes);
    }
}

Rollback no lote

O mesmo padrão aparece em inserirLote. Se um livro do lote tiver preço negativo, o banco recusa o INSERT, o método executa rollback(), e nenhum dos livros anteriores permanece. Na demonstração, o total continua 2 depois da falha.

Lendo o erro: getErrorCode e getMessage

Uma SQLException traz uma mensagem e um código. Os principais códigos do SQLite:

CódigoNomeSignificado
1SQLITE_ERRORerro de SQL, como uma palavra digitada errado
5SQLITE_BUSYbanco ocupado por outra conexão escrevendo (“database is locked”)
19SQLITE_CONSTRAINTviolação de restrição: UNIQUE, CHECK, NOT NULL ou chave estrangeira

A mensagem entre colchetes, como [SQLITE_CONSTRAINT_UNIQUE], dá o detalhe da restrição. Ao exibir erros ao usuário, mostre uma mensagem clara, e registre o erro completo para o desenvolvedor.

package demos;

import biblioteca.Conexao;
import biblioteca.Livro;
import biblioteca.LivroDao;
import java.sql.Connection;
import java.sql.SQLException;
import java.util.List;

/** Tópico 6: transações com commit e rollback, e leitura dos erros do banco. */
public class Demo06Transacoes {

    public static void main(String[] args) throws Exception {
        String arq = "demo06.db";
        new java.io.File(arq).delete();
        try (Connection con = Conexao.abrir(arq)) {
            Conexao.criarTabelas(con);
            LivroDao dao = new LivroDao(con);
            long a = dao.inserir(new Livro(null, "Dom Casmurro", 1899, 29.9, null));
            long b = dao.inserir(new Livro(null, "Vidas Secas", 1938, 19.9, null));

            System.out.println("antes:  " + precos(dao, a, b));
            dao.trocarPrecos(a, b);
            System.out.println("troca:  " + precos(dao, a, b));

            try {
                dao.trocarPrecos(a, 999);     // o segundo livro não existe
            } catch (SQLException e) {
                System.out.println("falhou: " + e.getMessage());
            }
            System.out.println("depois da falha (nada mudou): " + precos(dao, a, b));

            System.out.println("== lote com um registro inválido (preço negativo)");
            try {
                dao.inserirLote(List.of(
                        new Livro(null, "Bom", 2000, 10, null),
                        new Livro(null, "Ruim", 2000, -1, null)));
            } catch (SQLException e) {
                System.out.println("lote recusado: código " + e.getErrorCode());
            }
            System.out.println("total após o lote recusado: " + dao.contar());
        }
        new java.io.File(arq).delete();
    }

    private static String precos(LivroDao dao, long a, long b) throws SQLException {
        return dao.buscarPorId(a).get().preco() + " / " + dao.buscarPorId(b).get().preco();
    }
}

Erros comuns

  • Não restaurar o autocommit no finally: a conexão volta ao uso com transação aberta.
  • Capturar a exceção sem relançar: o método parece bem-sucedido.
  • Transação longa: bloqueia escritas de outras conexões. Mantenha-as curtas.

Exercícios

1. Escreva registrarEmprestimo que insere um empréstimo e marca o livro como indisponível, em uma transação.

Gabarito: setAutoCommit(false); executar o INSERT e o UPDATE; commit(); no catch, rollback() e relançar; no finally, setAutoCommit(true).

2. Um erro com código 5 aparece quando dois programas escrevem ao mesmo tempo. O que a aplicação faz?

Gabarito: tenta de novo após uma pausa curta, com limite de tentativas, e avisa o usuário se continuar ocupado. Transações curtas reduzem a chance desse erro.
