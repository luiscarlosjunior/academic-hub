A estrutura de uma consulta

SELECT colunas
FROM   tabela
WHERE  condição         -- filtra linhas
GROUP BY colunas        -- agrupa linhas
HAVING condição         -- filtra grupos
ORDER BY colunas        -- ordena
LIMIT n OFFSET m;       -- pagina

A ordem das cláusulas é fixa e não corresponde à ordem de execução. O banco primeiro lê a tabela (FROM), depois filtra (WHERE), agrupa, filtra grupos (HAVING), ordena e só então limita. Entender essa ordem explica por que um alias definido no SELECT não pode ser usado no WHERE.

Filtros: comparação, LIKE, IN e BETWEEN

OperadorUsoExemplo
=, <>, <, >=comparaçãoano < 1900
LIKEpadrão de texto: % qualquer sequência, _ um caracteretitulo LIKE 'M%'
INpertence a uma listapreco IN (24.5, 34.0)
BETWEENintervalo, extremos incluídosano BETWEEN 1930 AND 1940
IS NULLo valor está ausenteisbn IS NULL
NULL não se compara com =: isbn = NULL nunca é verdadeiro, nem falso: é desconhecido. Por isso o exemplo mostra zero linhas para = NULL, e o certo é IS NULL.

Ordenação e paginação

ORDER BY ano DESC ordena do mais recente para o mais antigo. Sem ORDER BY, o SQLite pode devolver as linhas em qualquer ordem, e essa ordem pode mudar entre execuções. Para paginar uma lista na interface, use LIMIT tamanho OFFSET (pagina - 1) * tamanho, com ORDER BY sempre presente.

Agregação: COUNT, SUM, AVG, GROUP BY e HAVING

Funções de agregação resumem várias linhas numa só: COUNT, SUM, AVG, MIN, MAX. Com GROUP BY, o resumo é feito por grupo. HAVING filtra os grupos depois da agregação, enquanto WHERE filtra as linhas antes. A regra prática: condição sobre valor original vai no WHERE; condição sobre o resultado de uma agregação vai no HAVING.

Subconsultas e CASE

Uma subconsulta é um SELECT dentro de outro. No exemplo, (SELECT AVG(preco) FROM livro) calcula a média, e o WHERE externo compara cada livro com ela. CASE funciona como um “se-senão” dentro da consulta, útil para criar faixas ou rótulos.

   ('Dom Casmurro', 1899)
   ('Memórias Póstumas', 1881)

-- LIKE (curinga % e _)
   SQL: SELECT titulo FROM livro WHERE titulo LIKE 'M%' OR titulo LIKE '_idas%'
   ('Memórias Póstumas',)
   ('Vidas Secas',)

-- IN e BETWEEN
   SQL: SELECT titulo, preco FROM livro WHERE ano BETWEEN 1930 AND 1940 AND preco IN (24.5, 34.0)
   ('Vidas Secas', 24.5)
   ('Capitães da Areia', 34.0)

-- ORDER BY e LIMIT/OFFSET (paginação)
   SQL: SELECT titulo, ano FROM livro ORDER BY ano DESC LIMIT 2 OFFSET 1
   ('Vidas Secas', 1938)
   ('Capitães da Areia', 1937)

-- Agregação com GROUP BY e HAVING
   SQL: SELECT CASE WHEN ano < 1900 THEN 'século XIX' ELSE 'século XX' END AS epoca, COUNT(*) AS total, ROUND(AVG(preco), 2) AS preco_medio FROM livro GROUP BY epoca HAVING COUNT(*) > 1 ORDER BY total DESC
   ('século XX', 3, 28.5)
   ('século XIX', 2, 34.9)

-- NULL precisa de IS NULL, não de = NULL
   SQL: SELECT count(*) FROM livro WHERE isbn = NULL
   (0,)

-- ...e isto funciona
   SQL: SELECT count(*) FROM livro WHERE isbn IS NULL
   (0,)

-- Subconsulta: livros mais caros que a média
   SQL: SELECT titulo, preco FROM livro WHERE preco > (SELECT AVG(preco) FROM livro) ORDER BY preco DESC

   ('Capitães da Areia', 34.0)

-- Expressão CASE para classificar

   ('A Hora da Estrela', 'médio')
   ('Dom Casmurro', 'médio')
   ('Capitães da Areia', 'caro')
   ('Memórias Póstumas', 'caro')

import sqlite3

con = sqlite3.connect(":memory:")
con.executescript(open("biblioteca_schema.sql", encoding="utf-8").read())
con.executemany("INSERT INTO livro (titulo, ano, isbn, preco) VALUES (?,?,?,?)", [
    ("Dom Casmurro", 1899, "978-1", 29.9),
    ("Memórias Póstumas", 1881, "978-2", 39.9),
    ("Vidas Secas", 1938, "978-3", 24.5),
    ("Capitães da Areia", 1937, "978-4", 34.0),
    ("A Hora da Estrela", 1977, "978-5", 27.0),
])

def mostrar(titulo, sql, params=()):
    print(f"\n-- {titulo}")
    print("   SQL:", " ".join(sql.split()))
    for linha in con.execute(sql, params):
        print("  ", linha)

mostrar("WHERE com comparação", "SELECT titulo, ano FROM livro WHERE ano < 1900")
mostrar("LIKE (curinga % e _)", "SELECT titulo FROM livro WHERE titulo LIKE 'M%' OR titulo LIKE '_idas%'")
mostrar("IN e BETWEEN", "SELECT titulo, preco FROM livro WHERE ano BETWEEN 1930 AND 1940 AND preco IN (24.5, 34.0)")
mostrar("ORDER BY e LIMIT/OFFSET (paginação)", "SELECT titulo, ano FROM livro ORDER BY ano DESC LIMIT 2 OFFSET 1")
mostrar("Agregação com GROUP BY e HAVING", """
    SELECT CASE WHEN ano < 1900 THEN 'século XIX' ELSE 'século XX' END AS epoca,
           COUNT(*) AS total, ROUND(AVG(preco), 2) AS preco_medio
    FROM livro GROUP BY epoca HAVING COUNT(*) > 1 ORDER BY total DESC""")
mostrar("NULL precisa de IS NULL, não de = NULL", "SELECT count(*) FROM livro WHERE isbn = NULL")
mostrar("...e isto funciona", "SELECT count(*) FROM livro WHERE isbn IS NULL")
mostrar("Subconsulta: livros mais caros que a média", """
    SELECT titulo, preco FROM livro
    WHERE preco > (SELECT AVG(preco) FROM livro) ORDER BY preco DESC""")
mostrar("Expressão CASE para classificar", """
    SELECT titulo, CASE WHEN preco >= 30 THEN 'caro' WHEN preco >= 25 THEN 'médio' ELSE 'barato' END AS faixa
    FROM livro ORDER BY preco""")

Erros comuns

  • SELECT * em produção: traz colunas que você não usa e quebra quando a tabela muda de forma. Liste as colunas.
  • LIKE com maiúsculas: no SQLite, LIKE ignora maiúsculas apenas para caracteres ASCII. Para acentos, normalize antes ou use uma coluna auxiliar.
  • Agregação sem GROUP BY misturada com colunas comuns: o resultado é imprevisível, e o SQLite aceita sem reclamar.

Exercícios

1. Escreva a consulta dos títulos que começam com “A” e custam entre 20 e 30 reais, ordenados pelo preço.

Gabarito: SELECT titulo, preco FROM livro WHERE titulo LIKE 'A%' AND preco BETWEEN 20 AND 30 ORDER BY preco.

2. Quantos livros por década? Escreva a consulta com GROUP BY.

Gabarito: SELECT (ano / 10) * 10 AS decada, COUNT(*) FROM livro GROUP BY decada ORDER BY decada. A divisão inteira de INTEGER por 10 agrupa os anos por década.
