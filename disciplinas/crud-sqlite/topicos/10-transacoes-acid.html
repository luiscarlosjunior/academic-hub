O que é uma transação

Uma transação é um conjunto de operações que deve acontecer por inteiro ou não acontecer. O exemplo clássico é a transferência bancária: debitar de uma conta e creditar em outra. Se o programa cair entre as duas operações, o dinheiro some, a menos que as duas tenham sido agrupadas numa transação.

As propriedades ACID

PropriedadeSignificadoNa transferência
Atomicidadetudo ou nadao débito e o crédito acontecem juntos ou nenhum
Consistênciao banco vai de um estado válido a outro válidoo saldo continua não negativo (CHECK)
Isolamentotransações concorrentes não se veem pela metadeoutro leitor não vê o débito sem o crédito
Durabilidadeo que foi confirmado sobrevive a falhasapós o COMMIT, a queda de energia não desfaz a transferência

Comandos de transação

BEGIN IMMEDIATE;          -- inicia e já reserva a escrita
UPDATE conta SET saldo = saldo - 30 WHERE id = 1;
UPDATE conta SET saldo = saldo + 30 WHERE id = 2;
COMMIT;                   -- confirma tudo

BEGIN;
UPDATE conta SET saldo = saldo - 500 WHERE id = 1;   -- viola CHECK (saldo >= 0)
ROLLBACK;                 -- desfaz

Dentro de uma transação, as alterações são visíveis para a própria conexão, mas não definitivas. O COMMIT as torna permanentes; o ROLLBACK as descarta.

SAVEPOINT: desfazer só uma parte

SAVEPOINT cria um ponto de retorno dentro da transação. ROLLBACK TO ponto desfaz apenas o que veio depois dele, e a transação continua. É útil quando uma sub-etapa pode falhar sem invalidar o resto.

Como o SQLite implementa isso

O SQLite usa um arquivo de diário (rollback journal) para desfazer alterações, e no modo WAL (tópico 15) usa um arquivo de log separado. Em ambos os casos, há um escritor de cada vez. BEGIN IMMEDIATE adquire o direito de escrita logo no início, e BEGIN DEFERRED, o padrão, só o adquire na primeira escrita. Se duas conexões tentarem escrever ao mesmo tempo, a segunda recebe “database is locked” depois de um tempo limite.

Para transferências, use BEGIN IMMEDIATE: a leitura do saldo e a escrita ficam protegidas de uma concorrente que leria o mesmo valor antigo.

Transações no módulo sqlite3

Por padrão, o módulo sqlite3 abre transações implicitamente antes de um INSERT, UPDATE ou DELETE. Para controle total, abra a conexão com isolation_level=None, como no exemplo, e escreva BEGIN, COMMIT e ROLLBACK explicitamente. Um bloco with con: faz commit no fim e rollback em caso de exceção, sem fechar a conexão.

Exemplo executável: transferência, ROLLBACK e SAVEPOINT

O script faz uma transferência válida, uma que viola o CHECK e é desfeita, mostra que um débito no meio de uma transação some com o ROLLBACK, e demonstra o SAVEPOINT desfazendo só a parte final.

Ver o código completo 
import sqlite3

con = sqlite3.connect(":memory:", isolation_level=None)   # controle manual de transações
con.execute("CREATE TABLE conta (id INTEGER PRIMARY KEY, titular TEXT, saldo INTEGER NOT NULL CHECK (saldo >= 0))")
con.executemany("INSERT INTO conta VALUES (?,?,?)", [(1, "Ana", 100), (2, "Bruno", 50)])

def saldos():
    return con.execute("SELECT titular, saldo FROM conta ORDER BY id").fetchall()

def transferir(origem, destino, valor):
    con.execute("BEGIN IMMEDIATE")          # bloqueia escrita: outros escritores esperam
    try:
        con.execute("UPDATE conta SET saldo = saldo - ? WHERE id = ?", (valor, origem))
        con.execute("UPDATE conta SET saldo = saldo + ? WHERE id = ?", (valor, destino))
        con.execute("COMMIT")               # tudo ou nada
        return "confirmada"
    except sqlite3.IntegrityError as e:
        con.execute("ROLLBACK")             # desfaz as duas alterações
        return "desfeita: " + str(e)

print("inicial:", saldos())
print("transferir 30 de Ana para Bruno:", transferir(1, 2, 30), saldos())
print("transferir 500 de Ana para Bruno:", transferir(1, 2, 500), saldos())

# Atomicidade mesmo com erro no meio: o débito feito antes é desfeito
con.execute("BEGIN")
con.execute("UPDATE conta SET saldo = saldo - 10 WHERE id = 1")
print("dentro da transação, saldo de Ana:", con.execute("SELECT saldo FROM conta WHERE id=1").fetchone()[0])
con.execute("ROLLBACK")
print("após ROLLBACK, saldo de Ana:", con.execute("SELECT saldo FROM conta WHERE id=1").fetchone()[0])

# SAVEPOINT: desfaz só uma parte da transação
con.execute("BEGIN")
con.execute("UPDATE conta SET saldo = saldo + 5 WHERE id = 2")
con.execute("SAVEPOINT ponto1")
con.execute("UPDATE conta SET saldo = saldo + 1000 WHERE id = 2")
con.execute("ROLLBACK TO ponto1")
con.execute("COMMIT")
print("com SAVEPOINT, saldo de Bruno:", con.execute("SELECT saldo FROM conta WHERE id=2").fetchone()[0])

Erros comuns

  • Transação aberta e esquecida: o banco fica bloqueado para outros escritores até o COMMIT ou ROLLBACK.
  • Capturar a exceção e seguir: sem ROLLBACK, parte da transação fica pendente e é confirmada no próximo COMMIT.
  • Ler, calcular na aplicação e gravar: entre a leitura e a escrita, outra transação pode mudar o valor. Calcule no próprio UPDATE ou use BEGIN IMMEDIATE.

Exercícios

1. Escreva a transação que registra um empréstimo e marca o livro como indisponível. Se uma das duas falhar, nenhuma deve valer.

Gabarito: BEGIN; INSERT INTO emprestimo ...; UPDATE livro SET disponivel = 0 WHERE id = ?; COMMIT; em caso de erro, ROLLBACK. Com a transação, o empréstimo não fica registrado sem o livro marcado.

2. Qual propriedade ACID o modo WAL ajuda a manter com leitores e escritor simultâneos?

Gabarito: o isolamento: leitores veem o último estado confirmado e não esperam o escritor, sem enxergar alterações pela metade.
