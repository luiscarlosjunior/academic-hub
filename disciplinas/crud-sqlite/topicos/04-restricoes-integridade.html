Por que a integridade mora no banco

Toda aplicação tem validação, mas validação só na tela não basta: outro programa, uma importação, um script de manutenção ou um bug futuro podem gravar dados inválidos. A integridade é a garantia de que os dados respeitam as regras do domínio, sempre, independentemente de quem escreve. Ela é imposta pelo banco por meio de restrições (constraints).

As restrições e o que cada uma garante

NOT NULLa coluna sempre tem valortitulo TEXT NOT NULL
UNIQUEnão há dois valores iguaisisbn TEXT UNIQUE

Chave estrangeira e a pragma foreign_keys

A chave estrangeira é a restrição mais importante do modelo relacional. Ela diz: “este empréstimo só pode apontar para um livro que existe”. Mas há uma armadilha específica do SQLite: por motivos de compatibilidade, a verificação de chave estrangeira vem desligada por padrão. Ela precisa ser ligada em cada conexão:

PRAGMA foreign_keys = ON;

O exemplo mostra os dois comportamentos: com a pragma ligada, o empréstimo para um livro inexistente é recusado; com ela desligada, o banco aceita o dado inválido sem reclamar.

Erro de produção clássico: a aplicação funciona em testes e aceita dados órfãos em produção porque uma das conexões não executou a pragma. Coloque a pragma na função que abre a conexão, sempre.

CHECK e DEFAULT

CHECK aceita qualquer expressão booleana, incluindo combinações de colunas: CHECK (data_fim IS NULL OR data_fim >= data_inicio). Quando a condição resulta em falso, a inserção ou alteração é recusada. DEFAULT preenche automaticamente a coluna quando o INSERT não a menciona, e pode ser uma constante ou uma expressão como CURRENT_TIMESTAMP.

Exemplo executável: provocar cada restrição

Cada bloco do script tenta uma violação e captura o erro. Repare que o banco diz qual restrição falhou, o que ajuda a depurar a aplicação.

Exemplo executável

Este programa roda de ponta a ponta. A saída abaixo é a execução real, feita com Python 3.13 e SQLite 3.45.

Arquivo
exemplos/t04_restricoes.py
Como rodar
cd disciplinas/crud-sqlite/exemplos
python3 t04_restricoes.py
Saída real
1. NOT NULL:
   RECUSADO: NOT NULL constraint failed: autor.nome
2. UNIQUE (isbn):
   RECUSADO: UNIQUE constraint failed: livro.isbn
3. CHECK (ano > 0):
   RECUSADO: CHECK constraint failed: ano > 0
4. DEFAULT (preco sem valor informado):
   ('Padrão', 0.0)
5. FOREIGN KEY com PRAGMA foreign_keys = ON:
   RECUSADO: FOREIGN KEY constraint failed
6. Mesma regra com a chave estrangeira DESLIGADA (padrão antigo do SQLite):
   aceito -> sem PRAGMA, a regra é ignorada
Ver o código completo 
import sqlite3

def tentar(con, sql, params=()):
    try:
        con.execute(sql, params)
        return "aceito"
    except sqlite3.IntegrityError as e:
        return "RECUSADO: " + str(e)

con = sqlite3.connect(":memory:")
con.executescript(open("biblioteca_schema.sql", encoding="utf-8").read())

print("1. NOT NULL:")
print("  ", tentar(con, "INSERT INTO autor (nome) VALUES (NULL)"))

print("2. UNIQUE (isbn):")
con.execute("INSERT INTO livro (titulo, ano, isbn) VALUES ('Dom Casmurro', 1899, '978-1')")
print("  ", tentar(con, "INSERT INTO livro (titulo, ano, isbn) VALUES ('Outro', 2000, '978-1')"))

print("3. CHECK (ano > 0):")
print("  ", tentar(con, "INSERT INTO livro (titulo, ano) VALUES ('Sem ano', -5)"))

print("4. DEFAULT (preco sem valor informado):")
con.execute("INSERT INTO livro (titulo, ano) VALUES ('Padrão', 2010)")
print("  ", con.execute("SELECT titulo, preco FROM livro WHERE titulo = 'Padrão'").fetchone())

print("5. FOREIGN KEY com PRAGMA foreign_keys = ON:")
con.execute("INSERT INTO cliente (nome, email) VALUES ('Ana', 'ana@x.com')")
print("  ", tentar(con, "INSERT INTO emprestimo (livro_id, cliente_id, data_saida) VALUES (999, 1, '2026-10-01')"))

print("6. Mesma regra com a chave estrangeira DESLIGADA (padrão antigo do SQLite):")
con2 = sqlite3.connect(":memory:")
con2.execute("CREATE TABLE pai (id INTEGER PRIMARY KEY)")
con2.execute("CREATE TABLE filho (pai_id INTEGER REFERENCES pai(id))")
print("  ", tentar(con2, "INSERT INTO filho (pai_id) VALUES (999)"), "-> sem PRAGMA, a regra é ignorada")

Erros comuns

  • Esquecer a pragma: a chave estrangeira “existe” no CREATE, mas não é aplicada.
  • UNIQUE com NULL: o SQLite permite vários NULL em uma coluna UNIQUE, porque NULL não é igual a nenhum outro valor. Se a regra é “no máximo um”, use um índice único parcial ou valide na aplicação.
  • Confiar só na aplicação: a restrição no banco é a última linha de defesa. Ela existe justamente para o caso em que a aplicação falha.

Exercícios

1. Escreva a restrição para garantir que uma assinatura tenha data de término posterior à de início, quando houver término.

Gabarito: CHECK (fim IS NULL OR fim > inicio). O IS NULL permite assinaturas ainda ativas, que não têm término.

2. Por que o isbn repetido foi recusado, mas dois livros sem isbn (NULL) são aceitos?

Gabarito: UNIQUE compara valores; NULL não é igual a outro NULL, então não há conflito. A regra “isbn é único quando informado” é exatamente o que o UNIQUE implementa.
