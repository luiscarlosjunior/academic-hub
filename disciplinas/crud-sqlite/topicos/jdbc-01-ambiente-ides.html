O que você precisa instalar

Para programar Java com SQLite são necessárias três peças:

PeçaO que éComo verificar
JDK 17 ou mais recentecompilador (javac) e máquina virtual (java)java -version no terminal
Uma IDEeditor com compilação, execução e depuraçãoEclipse, VS Code (com Extension Pack for Java) ou NetBeans
Driver sqlite-jdbca ponte entre o Java (JDBC) e o SQLiteum arquivo .jar na pasta lib/

Além do driver, o projeto precisa do slf4j-api, que o driver usa para registrar mensagens. Sem ele, o programa para com NoClassDefFoundError. Os dois JARs estão na pasta lib/, com o link oficial de cada um.

JDK, não JRE: o JRE só executa programas prontos. Para compilar, é preciso o JDK completo, como o Temurin (Adoptium) ou o que a sua IDE indicar.

A estrutura do projeto

Pasta ou arquivoConteúdo

src/demos/uma demonstração por tópico desta aula

Os pacotes (biblioteca e demos) espelham o package no topo de cada arquivo. Regra que confunde iniciantes: a pasta tem o nome do pacote. Se o arquivo diz package biblioteca;, ele deve estar em src/biblioteca/.

Passo a passo no Eclipse

Use o Eclipse IDE for Java Developers (versão 2024 ou mais recente). Os nomes de menus podem variar um pouco entre versões.

  1. Verificar o JDK: Window → Preferences → Java → Installed JREs. Se o JDK 17 ou mais recente não aparecer, clique em Add…, escolha Standard VM e aponte para a pasta de instalação do JDK.
  2. Criar o projeto: File → New → Java Project. Nome: biblioteca-sqlite. Deixe o JRE em 17 ou mais recente e clique em Finish. O Eclipse cria a pasta src.
  3. Copiar o código: no explorador de arquivos do sistema operacional, copie as pastas biblioteca e demos de src/ para dentro da pasta src do projeto no Eclipse. Os pacotes são reconhecidos automaticamente.
  4. Adicionar os JARs: botão direito no projeto → Build Path → Configure Build Path… → aba Libraries → Add External JARs…. Selecione os dois arquivos de lib/ e clique em Apply and Close. Eles aparecem em Referenced Libraries.
  5. Executar uma demonstração: abra demos/Demo01Verificacao.java, clique no código e use Run → Run As → Java Application (ou Ctrl+F11). A saída aparece na aba Console.
  6. Executar a aplicação: abra biblioteca/App.java e use Run As → Java Application. O menu aparece no console: digite a opção e pressione Enter.
Repetir a sessão do exemplo: em Run → Run Configurations…, escolha App e veja se a aba Common oferece a opção de entrada por arquivo (Standard Input). Se a sua versão não oferecer, digite as respostas no console.

Passo a passo no VS Code

  1. Instalar: o VS Code e a extensão Extension Pack for Java, publicada pela Microsoft. Ela traz o compilador, o depurador e o gerenciador de projetos Java.
  2. Abrir a pasta: File → Open Folder… e escolha java-sqlite (a pasta que contém src e lib). Não abra só src.
  3. Conferir a configuração: o .vscode/settings.json informa a pasta de código, a de saída e os JARs (lib/**/*.jar). Na barra lateral, Java Projects deve mostrar Referenced Libraries com os dois JARs. Se não aparecer, use Developer: Reload Window.
  4. Executar: abra Demo01Verificacao.java e clique em Run, que aparece acima do método main. A saída vai para o terminal integrado.
  5. Entrada de dados: ao executar App.java, digite as respostas no terminal integrado, uma por vez.
Se o driver não aparecer: confira se a pasta lib está dentro da pasta aberta e se os nomes dos JARs batem com o settings.json. Depois, recarregue a janela.

Passo a passo no NetBeans

  1. Verificar o JDK: Tools → Java Platforms. O JDK 17 ou mais recente deve estar na lista; marque-o como padrão se necessário.
  2. Criar o projeto: File → New Project → Java with Ant → Java Application. Nome: biblioteca-sqlite.
  3. Copiar o código: copie as pastas biblioteca e demos para a pasta src do projeto. Os pacotes aparecem em Source Packages.
  4. Adicionar os JARs: botão direito no projeto → Properties → Libraries → Add JAR/Folder…. Selecione os dois arquivos de lib/.
  5. Definir a classe principal: em Properties → Run, escolha biblioteca.App como Main Class, para que Run Project execute a aplicação.
  6. Executar: botão direito em Demo01Verificacao.java → Run File. As respostas da aplicação são digitadas na janela Output.
Nomes de menus: o NetBeans e o Eclipse mudam nomes de itens entre versões. Se um nome não aparecer, procure pela palavra-chave (por exemplo, "Libraries" ou "Add JAR").

Passo a passo animado

O código abaixo é um trecho real do projeto. Avance com os botões ou use Animar: a linha em execução é destacada e a explicação acompanha.

public static void main(String[] args) throws Exception {
    System.out.println("Java: " + System.getProperty("java.version"));
    Class.forName("org.sqlite.JDBC");
    System.out.println("driver carregado: sim");
    try (Connection con = DriverManager.getConnection("jdbc:sqlite::memory:");
         Statement st = con.createStatement();
         ResultSet rs = st.executeQuery("SELECT sqlite_version()")) {
        rs.next();
        System.out.println("SQLite: " + rs.getString(1));
        DatabaseMetaData meta = con.getMetaData();
        System.out.println("nome do driver: " + meta.getDriverName());
        System.out.println("versão do driver: " + meta.getDriverVersion());
    }
}

            System.out.println("nome do driver: " + meta.getDriverName());

Exercícios

1. Troque o driver por um JAR de outra versão e rode a demonstração. O que muda na saída?

Gabarito: a linha da versão do driver e, conforme a versão, a do SQLite. O código não muda, porque a API JDBC é a mesma. A aplicação depende da interface, não do driver.

2. Por que a pasta out/ não deve ir para o Git?

Gabarito: ela contém arquivos gerados. Qualquer pessoa recompila com um comando, então versionar os .class só aumenta o repositório e gera conflitos.
