Sem índice: a varredura completa

Sem índice, para encontrar as linhas de um cliente, o banco lê a tabela inteira, linha por linha. Com 50 mil empréstimos, isso são 50 mil leituras para responder uma pergunta que traz 10 resultados. O plano de execução mostra esse comportamento como SCAN.

CREATE INDEX: uma estrutura de busca

CREATE INDEX idx_emprestimo_cliente ON emprestimo (cliente_id);

Um índice é uma estrutura auxiliar, em geral uma árvore B, que mantém os valores de uma ou mais colunas ordenados e aponta para as linhas. A busca passa de uma varredura para uma pesquisa, com custo logarítmico. O plano passa a mostrar SEARCH ... USING INDEX.

Índices compostos e o prefixo

Um índice em (cliente_id, data_saida) ajuda consultas que filtram por cliente_id, ou por cliente_id e data_saida. Mas não ajuda uma consulta que filtra só por data_saida, porque a árvore está ordenada primeiro por cliente. Essa regra do prefixo esquerdo explica o resultado do exemplo: o segundo plano mostra um SCAN pelo índice inteiro, em vez de uma busca.

EXPLAIN QUERY PLAN: ler o plano

Coloque EXPLAIN QUERY PLAN antes de qualquer SELECT para ver como o banco pretende executá-lo, sem rodá-lo. As palavras-chave mais importantes:

SaídaSignificado
SCAN tabelalê a tabela inteira
SEARCH tabela USING INDEX ...busca pelo índice
COVERING INDEXo índice tem todas as colunas pedidas; a tabela nem é lida
USE TEMP B-TREE FOR ORDER BYo banco precisou ordenar em memória ou disco

O custo do índice

Índices não são grátis. Cada INSERT, UPDATE ou DELETE precisa atualizar todos os índices da tabela. Por isso, indexar tudo é um erro: uma tabela com dez índices pode ficar lenta para escrever. A regra prática é indexar as colunas usadas em WHERE, JOIN e ORDER BY das consultas frequentes, e as chaves estrangeiras (que o SQLite não indexa automaticamente).

Meça antes de otimizar: o EXPLAIN QUERY PLAN mostra a estratégia, não o tempo. Para decidir, compare o plano antes e depois e, se possível, meça com dados realistas.

ANALYZE e as estatísticas

ANALYZE coleta estatísticas sobre a distribuição dos valores, e o otimizador as usa para escolher entre planos. Depois de cargas grandes de dados, rodar ANALYZE costuma corrigir escolhas ruins do plano.

Exemplo executável: antes e depois do índice

O script cria 50 mil empréstimos, mostra o plano com varredura, cria o índice e mostra a busca. Depois mostra o índice composto, com o prefixo e sem ele. O número de resultados é o mesmo nos dois casos: o índice muda o caminho, não a resposta.

Exemplo executável

Este programa roda de ponta a ponta. A saída abaixo é a execução real, feita com Python 3.13 e SQLite 3.45.

DEPOIS do índice:

resultado idêntico com e sem índice: 10 linhas

Ver o código completo 
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE emprestimo (id INTEGER PRIMARY KEY, cliente_id INTEGER, data_saida TEXT, devolvido INTEGER)")
# 50 mil registros para o plano de execução fazer diferença
con.executemany("INSERT INTO emprestimo (cliente_id, data_saida, devolvido) VALUES (?, ?, ?)",
                ((i % 5000, f"2026-{(i % 12) + 1:02d}-01", i % 2) for i in range(50000)))
con.execute("ANALYZE")

consulta = "SELECT id FROM emprestimo WHERE cliente_id = 42"

print("ANTES do índice:")
for linha in con.execute("EXPLAIN QUERY PLAN " + consulta):
    print("  ", linha[-1])

con.execute("CREATE INDEX idx_emprestimo_cliente ON emprestimo (cliente_id)")
con.execute("ANALYZE")

print("DEPOIS do índice:")
for linha in con.execute("EXPLAIN QUERY PLAN " + consulta):
    print("  ", linha[-1])

print("\nresultado idêntico com e sem índice:", len(con.execute(consulta).fetchall()), "linhas")

# Índice composto: a ordem das colunas importa (prefixo esquerdo)
con.execute("CREATE INDEX idx_cli_data ON emprestimo (cliente_id, data_saida)")
print("\nPLANO com filtro no 1º campo do índice composto:")
for linha in con.execute("EXPLAIN QUERY PLAN SELECT id FROM emprestimo WHERE cliente_id = 42 AND data_saida > '2026-06-01'"):
    print("  ", linha[-1])
print("PLANO com filtro só no 2º campo (não usa o prefixo):")
for linha in con.execute("EXPLAIN QUERY PLAN SELECT id FROM emprestimo WHERE data_saida > '2026-06-01'"):
    print("  ", linha[-1])

Erros comuns

  • Índice na coluna errada: indexar uma coluna com dois valores (como devolvido) quase não ajuda, porque a busca continua trazendo metade da tabela.
  • Função sobre a coluna: WHERE substr(data_saida, 1, 4) = '2026' impede o uso do índice. Reescreva como intervalo: data_saida >= '2026-01-01'.
  • Esquecer o índice da chave estrangeira: o JOIN e a exclusão em cascata passam a varrer a tabela filha inteira.

Exercícios

1. A consulta WHERE data_saida = '2026-10-01' usa o índice (cliente_id, data_saida)? Justifique.

Gabarito: não usa o prefixo, porque cliente_id não aparece no filtro. O plano seria um SCAN do índice (ou da tabela). Para essa consulta, um índice em data_saida sozinho seria a escolha.

2. Escreva o índice que acelera “empréstimos em aberto de um cliente”.

Gabarito: CREATE INDEX idx_aberto ON emprestimo (cliente_id, devolvido). Como cliente_id é o prefixo, o filtro por cliente vira busca, e devolvido é filtrado dentro do intervalo encontrado.
