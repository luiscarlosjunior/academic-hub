A forma do UPDATE

UPDATE livro
SET preco = preco * 1.10, ano = 1900
WHERE ano < 1900;

O WHERE decide quais linhas mudam. Sem WHERE, todas as linhas da tabela são alteradas, sem aviso. A prática segura é escrever primeiro o SELECT com a mesma condição, conferir o resultado e só então trocar por UPDATE.

Regra de ouro: antes de qualquer UPDATE ou DELETE em produção, rode o SELECT equivalente e confira quantas linhas aparecem. Faça a alteração dentro de uma transação, para poder desfazer se o número estiver errado.

Quantas linhas mudaram

cursor.rowcount informa quantas linhas a última instrução alterou. Use-o para decidir: se um UPDATE por id devolve 0, o registro não existe mais, e a aplicação deve saber disso em vez de assumir sucesso.

RETURNING no UPDATE

Assim como no INSERT, RETURNING devolve as linhas alteradas. Útil quando a interface precisa mostrar o valor final, por exemplo um preço já com desconto aplicado.

UPSERT: inserir ou atualizar

INSERT INTO livro (titulo, ano, isbn, preco) VALUES (?, ?, ?, ?)
ON CONFLICT (isbn) DO UPDATE SET preco = excluded.preco;

Se o isbn já existe, a linha atual é atualizada; se não, é inserida. A palavra excluded se refere aos valores que o INSERT tentou gravar. O UPSERT exige uma restrição UNIQUE ou chave primária na coluna do conflito.

Atualização condicional (controle otimista)

Imagine que dois atendentes leem o preço de 31,00, e os dois querem alterá-lo. Se o segundo sobrescrever o primeiro sem saber, uma alteração se perde. A solução é incluir o valor lido na condição do UPDATE: WHERE isbn = ? AND preco = ?. Se o valor já mudou, nenhuma linha é alterada, e a aplicação avisa o usuário para recarregar.

Exemplo executável: UPDATE, RETURNING, UPSERT e condição

O script aumenta preços só para os livros anteriores a 1900, mostra o RETURNING, faz um UPSERT com um isbn existente e outro novo, e testa a atualização condicional com o valor correto e com um valor antigo.

import sqlite3

con = sqlite3.connect(":memory:")
con.executescript(open("biblioteca_schema.sql", encoding="utf-8").read())
con.executemany("INSERT INTO livro (id, titulo, ano, isbn, preco) VALUES (?,?,?,?,?)", [
    (1, "Dom Casmurro", 1899, "978-1", 29.9),
    (2, "Vidas Secas", 1938, "978-3", 24.5),
])

# U de CRUD: UPDATE com WHERE. Sem WHERE, TODAS as linhas mudam.
cur = con.execute("UPDATE livro SET preco = preco * 1.10 WHERE ano < 1900")
print("linhas alteradas:", cur.rowcount)
print(con.execute("SELECT titulo, round(preco, 2) FROM livro").fetchall())

# UPDATE ... RETURNING: devolve o registro alterado
print("RETURNING:", con.execute("UPDATE livro SET preco = 19.9 WHERE id = 2 RETURNING titulo, preco").fetchone())

# UPSERT: insere, ou atualiza se a chave única já existir
for isbn, preco in [("978-1", 31.0), ("978-9", 15.0)]:
    con.execute("""INSERT INTO livro (titulo, ano, isbn, preco) VALUES ('Título', 2000, ?, ?)
                   ON CONFLICT (isbn) DO UPDATE SET preco = excluded.preco""", (isbn, preco))
print("após UPSERT:", con.execute("SELECT isbn, preco FROM livro ORDER BY isbn").fetchall())

# Atualização segura: a condição inclui o valor esperado (controle otimista)
antigo = 31.0
cur = con.execute("UPDATE livro SET preco = 35.0 WHERE isbn = '978-1' AND preco = ?", (antigo,))
print("atualização condicional aceita:", cur.rowcount == 1)
cur = con.execute("UPDATE livro SET preco = 36.0 WHERE isbn = '978-1' AND preco = ?", (antigo,))
print("segunda tentativa com valor antigo aceita:", cur.rowcount == 1)

Erros comuns

  • UPDATE sem WHERE: altera a tabela inteira. Confira o SELECT antes.
  • Atualizar duas vezes com base no valor lido antes: o cálculo preco = 30 * 1.1 em uma aplicação concorrente pode sobrescrever outra alteração. Prefira calcular no próprio banco (preco = preco * 1.1), ou usar a condição otimista.
  • Ignorar rowcount: o programa segue como se a alteração tivesse acontecido.

Exercícios

1. Escreva a atualização que dá 10% de desconto nos livros com preço acima de 30, sem alterar os demais.

Gabarito: UPDATE livro SET preco = preco * 0.9 WHERE preco > 30;. A condição no WHERE limita as linhas afetadas.

2. Por que a segunda tentativa da atualização condicional retornou False?

Gabarito: o preço já tinha mudado para 35,00, então a condição preco = 31.0 não era mais verdadeira. Nenhuma linha casou, e o rowcount foi zero.
