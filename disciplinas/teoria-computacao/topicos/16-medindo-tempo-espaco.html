Tópico 16 · Medindo tempo e espaço

Até aqui perguntamos se um problema é computável. A partir de agora, perguntamos quanto custa. Um problema decidível pode levar um século para uma entrada de tamanho 100; outro pode precisar de apenas um milissegundo. A teoria da complexidade mede esses custos em função do tamanho da entrada, e isso exige uma linguagem precisa para crescimento.

Notação assintótica

Para funções f, g: ℕ → ℝ+, dizemos:

  • f = O(g) se existem c > 0 e n0 tais que f(n) ≤ c·g(n) para todo n ≥ n0 (limite superior);
  • f = Ω(g) se g = O(f) (limite inferior);
  • f = Θ(g) se f = O(g) e f = Ω(g) (crescimento da mesma ordem).

Constantes e termos de menor ordem somem: 3n² + 10n + 7 = Θ(n²). Essa abstração é exatamente o que torna a complexidade independente da máquina e da linguagem de programação.

Classes de tempo e de espaço

Definimos:

  • DTIME(f(n)): as linguagens decididas por uma MT determinística que para em O(f(n)) passos em toda entrada de tamanho n;
  • DSPACE(f(n)): as linguagens decididas por uma MT determinística que usa O(f(n)) células de fita em toda entrada de tamanho n.

Duas classes importantes são P = ∪k DTIME(nk), o conjunto dos problemas decidíveis em tempo polinomial, e PSPACE = ∪k DSPACE(nk). Como cada passo usa no máximo uma célula nova, tempo limita espaço: DTIME(f) ⊆ DSPACE(f).

A escolha de "polinomial" como fronteira de tratabilidade é uma convenção, mas uma convenção bem fundada. A tese de Cobham-Edmonds afirma que os problemas computáveis em tempo polinomial são exatamente os tratáveis na prática. Ela vale para modelos razoáveis, porque mudanças de modelo afetam o tempo por um fator polinomial.

Teoremas de hierarquia

Mais tempo permite resolver mais problemas? Sim, e a prova é uma diagonalização controlada. O teorema da hierarquia de tempo afirma que, se f é construtível no tempo e f(n) log f(n) = o(g(n)), então DTIME(f(n)) ⊊ DTIME(g(n)). Analogamente, o teorema da hierarquia de espaço dá DSPACE(f) ⊊ DSPACE(g) quando f = o(g).

Consequência: DTIME(n) ⊊ DTIME(n²) ⊊ DTIME(2n). Os teoremas garantem infinitas classes distintas, mas não dizem onde P e NP se encaixam. Essa é a questão do tópico 17.

Animação: o custo de cada crescimento

Para uma entrada crescente, as barras mostram o número de operações de cada função. Observe como 2n escapa de qualquer polinômio.

Práticas

  1. Mostre que 3n² + 10n + 7 = O(n²) exibindo c e n0.
  2. Para n = 60, compare o número de passos de n² e de 2n. Se cada passo leva 1 ns, quanto tempo cada algoritmo leva?
  3. Explique por que DTIME(f) ⊆ DSPACE(f), e dê um exemplo de linguagem em DSPACE(n) que não se sabe estar em P.

Correto. Essa é a justificativa para tomar P como classe de problemas tratáveis.
