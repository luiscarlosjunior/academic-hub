Nesta aula

Por que a escolha da estrutura importa

Um programa é, em essência, dados organizados e algoritmos que os transformam. A mesma informação pode ser guardada de muitas maneiras, e cada maneira torna algumas operações rápidas e outras lentas. Por isso, a escolha da estrutura costuma ser a decisão de projeto mais importante de um sistema (CORMEN et al., 2022, cap. 10).

Convém separar duas coisas. O tipo abstrato de dados (TAD) descreve o que a estrutura oferece: por exemplo, “inserir, remover e perguntar se um valor existe”. A implementação descreve como: um vetor, uma lista encadeada, uma tabela hash. Esta aula segue sempre a mesma ordem: primeiro o contrato, depois a implementação, depois o custo e, por fim, uma animação que mostra a operação acontecendo.

O custo é medido pela notação assintótica. Escrever O(n) significa que o tempo cresce, no pior caso, proporcionalmente ao tamanho n da entrada, desprezando constantes e termos menores (CORMEN et al., 2022, cap. 3). Essa é a régua usada em todas as tabelas desta aula.

Contrato (TAD)

O que a estrutura promete: inserir, remover, buscar, percorrer.

Implementação

Como a memória é usada: contígua (vetor) ou por ponteiros (árvore, lista).

Custo

Quantas operações no pior caso, em função de n.

Objetivos de aprendizagem. Ao final desta aula, você deverá ser capaz de:

  • explicar o custo de acesso, inserção e remoção em vetores e matrizes, relacionando-o ao endereçamento de memória;
  • descrever a ordenação por bolha, inserção e quicksort, e justificar por que a busca binária exige um vetor ordenado;
  • aplicar filas (FIFO) e pilhas (LIFO) em problemas reais, como a verificação de parênteses e a busca em largura;
  • explicar colisões em tabelas hash e o papel da função de espalhamento;
  • representar uma árvore binária de busca e um grafo, e percorrê-los com BFS e DFS.

0. Complexidade: o crescimento medido com Big-O

Medir um algoritmo em segundos é frágil: o resultado depende do computador, do compilador e da carga do sistema. A análise de complexidade conta, em vez disso, quantas operações elementares o algoritmo executa em função do tamanho da entrada n. Essa contagem independe da máquina e mostra como o custo cresce.

A notação O (“O grande”) dá um limite superior assintótico. Dizemos que f(n) = O(g(n)) quando existem constantes c e n₀ tais que f(n) ≤ c · g(n) para todo n ≥ n₀. Em palavras: para entradas grandes, f cresce no máximo na proporção de g. Constantes e termos menores são descartados, porque o que domina o crescimento é o termo de maior ordem (CORMEN et al., 2022, cap. 3). A notação foi popularizada na computação por Knuth (1976), que também definiu as notações irmãs Ω (limite inferior) e Θ (limite justo).

Há duas medidas. A complexidade temporal conta operações; a complexidade espacial conta a memória extra usada além da própria entrada. Um algoritmo pode ser rápido e gastar muita memória, ou o contrário. Quando nada é dito, a complexidade de uma aula como esta é a do pior caso.

Regras para calcular
  • Constantes saem: O(3n) = O(n).
  • Fica o termo dominante: O(n² + n + 10) = O(n²).
  • Laços em sequência somam: O(n) + O(n²) = O(n²).
  • Laços aninhados multiplicam: um laço de n dentro de outro de n é O(n²).
  • Laço que divide por 2 executa O(log n) vezes.
Três perguntas diferentes
  • Pior caso: o máximo de operações para qualquer entrada de tamanho n. É a garantia usada na prática.
  • Caso médio: o valor esperado sob uma distribuição de entradas. Exige hipóteses sobre os dados.
  • Amortizado: a média de uma sequência de operações, mesmo que uma delas seja cara (como o realloc).

Complexidade espacial: quanta memória extra?

A complexidade espacial conta a memória auxiliar. Uma função que calcula o fatorial de forma iterativa usa duas variáveis, sempre, qualquer que seja n: O(1). A versão recursiva, porém, cria um quadro na pilha de execução para cada chamada pendente, e a pilha chega a n quadros: O(n). Ambas levam tempo O(n), mas só uma delas gasta memória proporcional a n.

Os dois programas abaixo medem as operações e a memória na prática. O primeiro conta operações para vários valores de n; o segundo compara as duas versões do fatorial.

Exemplo prático em C · bigo.c

#include <stdio.h>

/* Contador global de operações elementares, para medir o custo na prática */
static long ops = 0;

static int primeiro(const int a[]) {                       /* O(1) */
    ops++;
    return a[0];
}

static long soma(const int a[], int n) {                   /* O(n) */
    long s = 0;
    for (int i = 0; i < n; i++) { ops++; s += a[i]; }
    return s;
}

static int pares_iguais(const int a[], int n) {            /* O(n²) */
    int c = 0;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++) { ops++; if (a[i] == a[j]) c++; }
    return c;
}

static int halvings(int n) {                               /* O(log n) */
    int k = 0;
    for (int m = n; m > 1; m /= 2) { ops++; k++; }
    return k;
}

int main(void) {
    static int a[1024];
    for (int i = 0; i < 1024; i++) a[i] = i;

    printf("%6s %6s %9s %8s %10s\n", "n", "O(1)", "O(log n)", "O(n)", "O(n^2)");
    for (int n = 8; n <= 1024; n *= 2) {
        ops = 0; primeiro(a);            long c1 = ops;
        ops = 0; halvings(n);            long cl = ops;
        ops = 0; soma(a, n);             long cn = ops;
        ops = 0; pares_iguais(a, n);     long cq = ops;
        printf("%6d %6ld %9ld %8ld %10ld\n", n, c1, cl, cn, cq);
    }
    return 0;
}

Saída: uma tabela em que a coluna de O(1) fica constante, a de O(log n) cresce uma unidade por dobra de n, e as de O(n) e O(n²) dobram e quadruplicam, respectivamente.

Exemplo prático em C · espaco.c

#include <stdio.h>

/* Recursivo: cada chamada ocupa um quadro na pilha de execução.
   Espaço auxiliar O(n), além do tempo O(n). */
unsigned long long fat_rec(unsigned n) {
    return n <= 1 ? 1 : n * fat_rec(n - 1);
}

/* Iterativo: apenas duas variáveis locais, espaço auxiliar O(1). */
unsigned long long fat_it(unsigned n) {
    unsigned long long r = 1;
    for (unsigned i = 2; i <= n; i++) r *= i;
    return r;
}

int main(void) {
    printf("10! recursivo = %llu\n", fat_rec(10));
    printf("10! iterativo = %llu\n", fat_it(10));
    return 0;
}

Saída: 10! recursivo = 3628800 e 10! iterativo = 3628800. Mesmo resultado, memória auxiliar diferente.

Big-O não é tudo. Para n pequeno, uma constante grande pode fazer um O(n log n) perder de um O(n²) com constante minúscula. Big-O responde ao crescimento; o tempo real também depende do cache, da localidade de memória e do custo de cada operação, como vimos com matrizes.

1. Vetores: memória contígua e acesso direto

Um vetor (array) é uma sequência de elementos do mesmo tipo guardados em posições contíguas da memória. Cada elemento tem um índice, começando em 0. Essa organização faz do vetor a estrutura mais direta que existe: o endereço do elemento i é calculado por uma fórmula,

endereço(i) = endereço_base + i × tamanho_do_elemento

Como a conta não depende de n, o acesso por índice é O(1). Já procurar um valor sem saber sua posição exige olhar um a um, o que custa O(n). Inserir ou remover no meio é caro: é preciso deslocar todos os elementos seguintes, e o custo é O(n).

A contiguidade também tem um efeito prático. Como os elementos vizinhos ficam juntos, o processador carrega blocos inteiros da memória para o cache, e um percurso sequencial costuma ser muito mais rápido do que o custo teórico sugere (HENNESSY; PATTERSON, 2017, cap. 2). Esse princípio se chama localidade espacial.

Por dentro da memória

Em C, um vetor é um endereço (o do primeiro elemento) somado a um deslocamento. Por definição, arr[i] é o mesmo que *(arr + i): o compilador multiplica i pelo tamanho do tipo e soma ao endereço base. Não há busca nenhuma, por isso o acesso é O(1) (KERNIGHAN; RITCHIE, 1988, cap. 5).

Três cuidados nascem daí. C não verifica limites: arr[10] em um vetor de seis posições é comportamento indefinido, e o programa pode falhar ou corromper dados em silêncio (ISO/IEC, 2018). O tamanho precisa ser guardado pelo programador. Depois, realloc pode mover o bloco inteiro, por isso devolve um ponteiro que deve substituir o antigo. Por fim, inserir no meio exige deslocar elementos, e esse custo é O(n).

Exemplo prático em C · vetor.c

#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int n = 6;
    int *arr = malloc(n * sizeof *arr);          /* bloco contíguo de 6 inteiros */
    if (!arr) return 1;

    int valores[] = {4, 8, 15, 16, 23, 42};
    for (int i = 0; i < n; i++) arr[i] = valores[i];

    /* Acesso O(1): endereço = base + 3 * sizeof(int) */
    printf("arr[3] = %d\n", arr[3]);

    /* Inserir 10 na posição 2: realoca e desloca à direita, O(n) */
    arr = realloc(arr, (n + 1) * sizeof *arr);
    if (!arr) return 1;
    for (int j = n; j > 2; j--) arr[j] = arr[j - 1];
    arr[2] = 10;
    n++;

    for (int i = 0; i < n; i++) printf("%d ", arr[i]);
    printf("\n");

    free(arr);
    return 0;
}

Saída: arr[3] = 16 e, em seguida, 4 8 10 15 16 23 42.

Animação: acesso, inserção e remoção

Escolha a operação. Use Passo para avançar devagar, ou Reproduzir para ver tudo de uma vez. Cada passo traz a explicação do que está acontecendo.

Observe: no acesso, uma só conta resolve tudo. Na inserção, cada elemento à direita precisa andar uma casa, e a conta cresce com o tamanho do vetor. Em Java, ArrayList cresce por realocação com fator geométrico, o que torna a inserção no fim O(1) amortizado (CORMEN et al., 2022, cap. 17).

2. Matrizes: uma tabela, uma linha de memória

Uma matriz n × m é um vetor de posições indexadas por duas coordenadas (i, j). Como a memória do computador é linear, é preciso escolher uma ordem para empilhar as linhas. Na convenção linha-maior (row-major), usada por C, a linha 0 vem inteira, depois a linha 1, e assim por diante. Então a posição linear de (i, j) é:

k = i × m + j

A convenção coluna-maior (column-major), usada por Fortran e MATLAB, inverte essa ordem. Os dois modos dão o mesmo resultado lógico, mas custos físicos diferentes: percorrer na ordem da memória é mais rápido, porque aproveita a localidade (HENNESSY; PATTERSON, 2017, cap. 2).

Como já foi dito, a convenção linha-maior não é só teórica: em C ela é garantida pela linguagem. Em linguagens que representam matrizes como vetores de vetores, como Java, as linhas podem ocupar regiões separadas, mas a recomendação de percorrer por linhas continua valendo.

Matriz em C é um bloco contínuo

Em C, uma matriz declarada como int m[3][4] é um único bloco de 12 inteiros em memória, na ordem linha-maior. Essa garantia faz parte da linguagem, por isso o programa pode tratar a matriz como um vetor plano, como mostra o exemplo. Os índices m[i][j] são apenas uma forma cômoda de calcular a posição i × COLUNAS + j.

O custo de acesso é O(1), e o espaço é O(n·m), pois a matriz ocupa todas as suas células. Percorrer tudo custa O(n·m), e isso não pode ser evitado, porque cada célula precisa ser lida. A diferença entre percorrer por linhas e por colunas aparece no tempo real, não no Big-O: o cache favorece o acesso sequencial (HENNESSY; PATTERSON, 2017, cap. 2).

OperaçãoTempoEspaço extra
Acessar m[i][j]O(1)O(1)
Percorrer todas as célulasO(n·m)O(1)
Somar duas matrizes n × mO(n·m)O(n·m) se o resultado for nova matriz
Guardar a matriz—O(n·m)

Exemplo prático em C · matriz.c

#include <stdio.h>

#define LINHAS  3
#define COLUNAS 4

int main(void) {
    int m[LINHAS][COLUNAS];

    /* Percurso por linhas: a ordem de visita coincide com a da memória */
    for (int i = 0; i < LINHAS; i++)
        for (int j = 0; j < COLUNAS; j++)
            m[i][j] = i * COLUNAS + j;

    /* Em C, a matriz é um bloco contíguo de 12 inteiros, em linha-maior */
    const int *plano = &m[0][0];
    for (int k = 0; k < LINHAS * COLUNAS; k++)
        printf("%d ", plano[k]);
    printf("\n");

    /* m[i][j] está na posição linear k = i * COLUNAS + j */
    printf("m[2][1] = %d, plano[2 * %d + 1] = %d\n",
           m[2][1], COLUNAS, plano[2 * COLUNAS + 1]);
    return 0;
}

Saída: 0 1 2 … 11, seguido de m[2][1] = 9 e plano[9] = 9.

3. Algoritmos de ordenação

Ordenar é reorganizar um vetor para que a[0] ≤ a[1] ≤ … ≤ a[n−1]. Quase todo algoritmo de ordenação mantém um invariante: uma região do vetor já está correta, e a cada passo ela cresce. Entender esse invariante é a chave para entender o algoritmo (SEDGEWICK; WAYNE, 2011, cap. 2).

Três algoritmos clássicos ilustram as ideias principais. A ordenação por bolha troca vizinhos fora de ordem; a ordenação por inserção encaixa cada elemento na parte já ordenada, como quem organiza cartas na mão; o quicksort escolhe um pivô, separa menores e maiores e aplica a mesma ideia a cada lado. O quicksort foi proposto por Hoare (1962) e é, até hoje, um dos algoritmos mais usados na prática.

Animação: três algoritmos, o mesmo vetor

As barras têm altura proporcional ao valor. Verde = posição já definitiva; amarelo = comparação em curso. O contador conta as comparações.

Exemplo em C: bolha, inserção e quicksort, com contador de comparações. Repare que o laço da inserção é o mesmo “deslocamento” da seção de vetores.

Por que O(n²) e por que O(n log n)?

Na bolha, a passagem p percorre n − 1 − p pares. Somando todas as passagens, obtemos (n − 1) + (n − 2) + … + 1 = n(n − 1)/2, que é O(n²). Na inserção, cada elemento pode atravessar toda a parte ordenada, o que também dá O(n²) no pior caso. Mas, se o vetor já está ordenado, a inserção faz uma comparação por elemento e custa O(n). A bolha, com a parada antecipada da variável trocou, também é O(n) nesse caso.

No quicksort, cada partição custa O(n) e divide o problema em duas partes. Se o pivô cai perto da mediana, a árvore de chamadas tem altura O(log n) e o total é O(n log n). Se o pivô é sempre o extremo (por exemplo, um vetor já ordenado com o último elemento como pivô), a altura vira n e o custo sobe para O(n²). Esse é o pior caso (SEDGEWICK; WAYNE, 2011, cap. 2).

O espaço da bolha e da inserção é O(1), pois ordenam in place. O quicksort usa O(log n) de pilha de recursão, no caso médio. O merge sort é O(n log n) em tempo, mas exige O(n) de memória auxiliar.

Exemplo prático em C · ordenacao.c

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static long comparacoes = 0;

static void trocar(int *x, int *y) {
    int t = *x; *x = *y; *y = t;
}

/* Bolha: troca vizinhos fora de ordem; para cedo se não houve troca */
static void bolha(int a[], int n) {
    for (int p = 0; p < n - 1; p++) {
        int trocou = 0;
        for (int j = 0; j < n - 1 - p; j++) {
            comparacoes++;
            if (a[j] > a[j + 1]) {
                trocar(&a[j], &a[j + 1]);
                trocou = 1;
            }
        }
        if (!trocou) break;
    }
}

/* Inserção: a[0..i-1] já está ordenado */
static void insercao(int a[], int n) {
    for (int i = 1; i < n; i++) {
        int chave = a[i], j = i - 1;
        while (j >= 0) {
            comparacoes++;
            if (a[j] <= chave) break;
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = chave;
    }
}

/* Quicksort com partição de Lomuto */
static void quicksort(int a[], int lo, int hi) {
    if (lo >= hi) return;
    int pivo = a[hi], i = lo;
    for (int j = lo; j < hi; j++) {
        comparacoes++;
        if (a[j] < pivo) {
            trocar(&a[i], &a[j]);
            i++;
        }
    }
    trocar(&a[i], &a[hi]);
    quicksort(a, lo, i - 1);
    quicksort(a, i + 1, hi);
}

static int comparar_int(const void *x, const void *y) {
    int a = *(const int *)x, b = *(const int *)y;
    return (a > b) - (a < b);
}

static void mostrar(const char *nome, const int a[], int n) {
    printf("%-10s comparações=%2ld ->", nome, comparacoes);
    for (int i = 0; i < n; i++) printf(" %d", a[i]);
    printf("\n");
}

int main(void) {
    const int base[] = {29, 10, 14, 37, 13, 5, 42, 8};
    const int n = (int)(sizeof base / sizeof base[0]);
    int a[8];

    memcpy(a, base, sizeof base);
    comparacoes = 0; bolha(a, n);
    mostrar("bolha", a, n);

    memcpy(a, base, sizeof base);
    comparacoes = 0; insercao(a, n);
    mostrar("inserção", a, n);

    memcpy(a, base, sizeof base);
    comparacoes = 0; quicksort(a, 0, n - 1);
    mostrar("quicksort", a, n);

    /* Biblioteca padrão: qsort (o algoritmo interno depende da libc) */
    memcpy(a, base, sizeof base);
    qsort(a, n, sizeof a[0], comparar_int);
    printf("%-10s (sem contador) ->", "qsort");
    for (int i = 0; i < n; i++) printf(" %d", a[i]);
    printf("\n");
    return 0;
}

Saída: bolha com 28 comparações; inserção com 21; quicksort com 18; e o qsort da biblioteca, que não contamos.

Quando usar qual? Para vetores pequenos ou quase ordenados, a inserção é surpreendentemente boa. Para grandes volumes em geral, o quicksort ou o merge sort são a escolha. A bolha quase nunca é a melhor opção: ela aparece aqui porque é a mais fácil de acompanhar, não a mais rápida.

4. Busca binária: dividir para descartar

A busca binária procura um valor em um vetor ordenado. Ela compara o valor com o elemento do meio. Se o alvo for menor, a metade direita não pode conter o alvo, e é descartada; se for maior, a esquerda é descartada. Cada comparação elimina metade do intervalo restante.

Por isso, o número de comparações no pior caso é ⌊log₂ n⌋ + 1. Para n = 1 000 000, são no máximo 20 comparações, contra até um milhão da busca linear. Essa diferença explica por que a busca binária é uma das ideias mais importantes da computação (CORMEN et al., 2022, cap. 2).

A pré-condição é absoluta. Em um vetor não ordenado, a regra de descarte é inválida e o resultado pode estar errado sem nenhum aviso. Jon Bentley observou que a maioria das implementações de busca binária que circulavam na época continha algum erro sutil (BENTLEY, 1999, cap. 4). Um deles é clássico: calcular o meio como (lo + hi) / 2 pode estourar o limite do inteiro; a forma segura é lo + (hi − lo) / 2, como mostrou Bloch (2006).

Quantas comparações, afinal?

Cada passo corta o intervalo ao meio: n, n/2, n/4, … até restar um elemento. O número de passos é o menor k tal que n / 2k ≤ 1, ou seja, k = log₂ n. Isso explica o tempo O(log n): para um bilhão de elementos, bastam cerca de 30 comparações.

O espaço depende da implementação. A versão iterativa, mostrada aqui, usa poucas variáveis: O(1). A versão recursiva cria um quadro por nível de recursão, e o espaço vira O(log n). Por isso, em C, a forma iterativa costuma ser preferida.

Ordenar antes, para poder buscar com a bináriaO(n log n)depende do algoritmo de ordenação

Exemplo prático em C · busca_binaria.c

#include <stdio.h>

/* Devolve o índice de alvo em a[0..n-1], ou -1; conta as comparações feitas */
static int busca_binaria(const int a[], int n, int alvo, int *comparacoes) {
    int lo = 0, hi = n - 1;
    *comparacoes = 0;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;      /* evita estouro de int */
        (*comparacoes)++;
        if (a[mid] == alvo) return mid;
        if (a[mid] < alvo) lo = mid + 1;   /* descarta a metade esquerda */
        else hi = mid - 1;                 /* descarta a metade direita */
    }
    return -1;
}

int main(void) {
    const int a[] = {3, 7, 11, 15, 19, 24, 28, 33, 41, 47, 52, 60};
    const int n = (int)(sizeof a / sizeof a[0]);
    const int alvos[] = {24, 40, 3};

    for (int k = 0; k < 3; k++) {
        int cmp;
        int idx = busca_binaria(a, n, alvos[k], &cmp);
        if (idx >= 0)
            printf("%2d: índice %d, %d comparação(ões)\n", alvos[k], idx, cmp);
        else
            printf("%2d: não encontrado, %d comparação(ões)\n", alvos[k], cmp);
    }
    return 0;
}

Saída: 24 no índice 5, com 1 comparação; 40 não encontrado, com 4 comparações; 3 no índice 0, com 3 comparações.

Animação: encontrar e não encontrar

O vetor é ordenado e tem 12 elementos. lo e hi delimitam o intervalo ativo; os elementos apagados já foram descartados. Teste um valor presente e um ausente.

5. Filas: primeiro a entrar, primeiro a sair

Uma fila segue a regra FIFO (first in, first out): quem entra primeiro sai primeiro, como numa fila de banco. As operações essenciais são enqueue (inserir no fim) e dequeue (remover da frente). Com um ponteiro para cada extremidade, ambas custam O(1).

Filas aparecem em toda parte: buffers de rede e de áudio, filas de impressão, escalonadores de processos e, como veremos na seção de grafos, na busca em largura (CORMEN et al., 2022, cap. 10).

Atenção a um detalhe: remover do início de um vetor comum custa O(n), porque todos os outros elementos precisam andar. Por isso, implementações reais usam uma fila circular ou uma lista encadeada.

Por que um buffer circular?

Um vetor comum, com enqueue no fim e dequeue no início, custaria O(n) a cada remoção, porque todos os elementos precisariam andar uma casa. O truque é usar o índice módulo a capacidade: a frente avança e o fim dá a volta quando chega ao final do vetor. Cada operação vira uma aritmética de tempo constante.

O espaço é O(C), a capacidade fixa. Se a fila encher, é preciso reconstruir o buffer com o dobro do tamanho, copiando tudo. Essa cópia custa O(n) naquele momento, mas, espalhada pelas inserções anteriores, resulta em O(1) amortizado por operação (CORMEN et al., 2022, cap. 17).

OperaçãoTempoEspaço extra
enqueueO(1)O(1)
dequeueO(1)O(1)
Buscar um elementoO(n)O(1)
Guardar n elementos—O(C), com C ≥ n

Exemplo prático em C · fila.c

#include <stdio.h>

#define CAP 4   /* capacidade fixa do buffer circular */

typedef struct {
    char dados[CAP];
    int frente;     /* índice do primeiro elemento */
    int tamanho;    /* quantos elementos estão na fila */
} Fila;

/* enqueue: insere no fim, O(1) */
static int enqueue(Fila *f, char c) {
    if (f->tamanho == CAP) return 0;                 /* cheia */
    int fim = (f->frente + f->tamanho) % CAP;        /* índice circular */
    f->dados[fim] = c;
    f->tamanho++;
    return 1;
}

/* dequeue: remove da frente, O(1) */
static int dequeue(Fila *f, char *c) {
    if (f->tamanho == 0) return 0;                   /* vazia */
    *c = f->dados[f->frente];
    f->frente = (f->frente + 1) % CAP;
    f->tamanho--;
    return 1;
}

int main(void) {
    Fila f = {{0}, 0, 0};
    char c;

    enqueue(&f, 'A');
    enqueue(&f, 'B');
    enqueue(&f, 'C');
    if (dequeue(&f, &c)) printf("saiu %c\n", c);   /* A */
    enqueue(&f, 'D');                               /* reaproveita a posição livre */
    while (dequeue(&f, &c)) printf("saiu %c\n", c); /* B, C, D */
    printf("fila vazia: %s\n", f.tamanho == 0 ? "sim" : "não");
    return 0;
}

Saída: saiu A, saiu B, saiu C, saiu D e, por fim, fila vazia: sim.

Animação: enfileirar e desenfileirar

A sequência de operações é fixa: três entradas, uma saída, outra entrada e outra saída.

6. Pilhas: o último a entrar é o primeiro a sair

Uma pilha segue a regra LIFO (last in, first out). Só o topo é acessível: push empilha, pop desempilha, ambos em O(1). Pense numa pilha de pratos.

A pilha é a estrutura por trás de muitas coisas que você usa sem perceber. A pilha de chamadas do programa guarda as funções que estão em execução; a avaliação de expressões aritméticas e o desfazer (undo) de editores também usam pilhas (AHO; LAM; SETHI; ULLMAN, 2006, cap. 1).

Um problema clássico mostra a força da estrutura: verificar se parênteses estão balanceados. Cada abertura é empilhada; cada fechamento deve casar com o topo. Se casar, desempilha. No fim, a pilha deve estar vazia.

Pilha com vetor, em C

A pilha usa um vetor e um índice topo. push incrementa o índice e grava; pop lê e decrementa. Não há laço, por isso ambas custam O(1). Note que pop em pilha vazia é um erro: o exemplo evita isso testando vazia() antes.

A verificação de parênteses percorre a expressão uma vez, com no máximo um push ou pop por caractere. Logo, o tempo é O(n). No pior caso, a pilha guarda todas as aberturas, e o espaço é O(n). Repare que o tipo de cada abertura importa: {(}) tem a mesma quantidade de aberturas e fechamentos, mas não é válida. Um simples contador não resolve o problema; a pilha resolve.

OperaçãoTempoEspaço extra
pushO(1)O(1)
popO(1)O(1)
Verificar parênteses de n caracteresO(n)O(n) no pior caso

Exemplo prático em C · pilha.c

#include <stdio.h>

#define MAX 64

typedef struct {
    char dados[MAX];
    int topo;                 /* índice do topo; -1 significa vazia */
} Pilha;

static void push(Pilha *p, char c) { p->dados[++p->topo] = c; }
static char pop(Pilha *p)          { return p->dados[p->topo--]; }
static int  vazia(const Pilha *p)  { return p->topo < 0; }

/* Devolve 1 se os parênteses, colchetes e chaves estão balanceados */
static int balanceada(const char *expr) {
    Pilha p = { .topo = -1 };
    for (const char *s = expr; *s; s++) {
        char c = *s;
        if (c == '(' || c == '[' || c == '{') {
            push(&p, c);
        } else if (c == ')' || c == ']' || c == '}') {
            if (vazia(&p)) return 0;            /* fechamento sem abertura */
            char abre = pop(&p);
            if ((c == ')' && abre != '(') ||
                (c == ']' && abre != '[') ||
                (c == '}' && abre != '{'))
                return 0;                       /* pares não casam */
        }
    }
    return vazia(&p);                           /* sobrou abertura? */
}

int main(void) {
    const char *testes[] = {"{[()]}", "{[(])}", "((()"};
    for (int i = 0; i < 3; i++)
        printf("%-8s -> %s\n", testes[i],
               balanceada(testes[i]) ? "balanceada" : "não balanceada");
    return 0;
}

Saída: {[()]} é balanceada; {[(])} e ((() não são.

Animação: validar parênteses

A faixa de cima é a expressão, e o caractere atual fica destacado. À direita, a pilha com o topo em destaque. Compare as duas expressões.

7. Tabelas hash: acesso médio em O(1)

Uma tabela hash associa chaves a valores. Uma função de espalhamento h(chave) transforma a chave em um índice de um vetor de baldes. Assim, para encontrar uma chave, basta calcular h e olhar um balde, o que dá O(1) em média.

Surge uma dificuldade: duas chaves diferentes podem cair no mesmo balde. Isso é uma colisão, e é inevitável, porque há mais chaves possíveis do que baldes (o princípio da casa dos pombos). As duas soluções clássicas são:

  • Encadeamento: cada balde guarda uma lista das chaves que caíram nele. É a usada aqui.
  • Endereçamento aberto: se o balde está ocupado, a chave procura outro lugar na própria tabela (sondagem linear, quadrática ou duplo espalhamento).

O desempenho depende do fator de carga α = n / M (elementos sobre baldes). Quando α cresce, a tabela é redimensionada e todas as chaves são redistribuídas (rehash). Knuth (1998, v. 3, seção 6.4) analisa esses custos em detalhe. Em Java, HashMap segue esse modelo e exige que equals e hashCode sejam coerentes entre si (ORACLE, [s.d.]).

Caso médio, caso ruim

No caso médio, com um bom espalhamento, cada balde tem cerca de α = n / M elementos. Buscar custa O(1 + α), e como α é mantido limitado, isso é O(1). No pior caso, todas as chaves caem no mesmo balde: a lista vira uma lista encadeada de tamanho n, e a busca custa O(n). Por isso a qualidade da função h importa. A função didática desta aula (soma dos códigos) é ruim: anagramas como ab e ba sempre colidem.

O espaço é O(M + n): o vetor de baldes mais um nó para cada chave. Quando α passa de um limite (por exemplo, 0,75), a tabela cresce e é reconstruída, o que custa O(n) naquele momento. Amortizado por inserção, o custo continua O(1) (CORMEN et al., 2022, cap. 11; KNUTH, 1998, v. 3, seção 6.4).

A inserção do exemplo acrescenta no início da lista do balde, por isso a chave mais recente aparece primeiro.

OperaçãoCaso médioPior casoEspaço
InserirO(1)O(n)O(1) por chave
BuscarO(1)O(n)—
RemoverO(1)O(n)—

Exemplo prático em C · hash.c

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define M 5   /* número de baldes */

typedef struct No {
    char chave[16];
    struct No *prox;      /* encadeamento: lista de colisões do balde */
} No;

/* Função didática: soma dos códigos dos caracteres, módulo M */
static unsigned h(const char *s) {
    unsigned soma = 0;
    for (; *s; s++) soma += (unsigned char)*s;
    return soma % M;
}

/* Inserção no início da lista do balde: O(1) */
static void inserir(No *tab[], const char *chave) {
    No *novo = malloc(sizeof *novo);
    if (!novo) exit(1);
    strcpy(novo->chave, chave);
    unsigned b = h(chave);
    novo->prox = tab[b];
    tab[b] = novo;
}

/* Busca: custo médio O(1), mais o tamanho da lista do balde */
static int buscar(No *tab[], const char *chave) {
    for (No *p = tab[h(chave)]; p != NULL; p = p->prox)
        if (strcmp(p->chave, chave) == 0) return 1;
    return 0;
}

static void liberar(No *tab[]) {
    for (int b = 0; b < M; b++) {
        No *p = tab[b];
        while (p) {
            No *seguinte = p->prox;
            free(p);
            p = seguinte;
        }
        tab[b] = NULL;
    }
}

int main(void) {
    No *tab[M] = {NULL};
    const char *chaves[] = {"ana", "bia", "caio", "dani", "eva", "fabio"};

    for (int i = 0; i < 6; i++) {
        inserir(tab, chaves[i]);
        printf("h(\"%s\") = %u\n", chaves[i], h(chaves[i]));
    }

    printf("\nBaldes:\n");
    for (int b = 0; b < M; b++) {
        printf("  %d:", b);
        for (No *p = tab[b]; p; p = p->prox) printf(" %s", p->chave);
        printf("\n");
    }

    printf("\nbusca \"dani\": %s\n", buscar(tab, "dani") ? "encontrada" : "não encontrada");
    printf("busca \"zeca\": %s\n", buscar(tab, "zeca") ? "encontrada" : "não encontrada");
    liberar(tab);
    return 0;
}

Saída: h("ana") = 4, h("caio") = 2, h("dani") = 2 e os baldes 0: bia · 1: eva · 2: dani caio · 3: fabio · 4: ana. A busca de dani encontra; a de zeca não.

Animação: inserir, colidir e buscar

A função didática soma os códigos ASCII das letras e tira o resto da divisão por 5. Observe a colisão no balde 2 e a busca de dani.

8. Árvores binárias de busca

Uma árvore é um grafo acíclico com uma raiz; cada nó tem zero ou mais filhos. Em uma árvore binária, cada nó tem no máximo um filho à esquerda e um à direita. A altura h é o número de arestas do caminho mais longo da raiz até uma folha (CORMEN et al., 2022, cap. 12).

Uma árvore binária de busca (BST) acrescenta uma regra: em cada nó, os valores da subárvore esquerda são menores e os da direita são maiores. Essa propriedade torna a busca uma descida, em que cada comparação descarta uma subárvore inteira, exatamente como na busca binária.

O custo de busca, inserção e remoção é O(h). Se a árvore é razoavelmente balanceada, h ≈ log₂ n e o custo é O(log n). Mas a ordem de inserção importa: inserir 20, 30, 40 em sequência produz uma “lista” de altura n − 1, e o custo volta a O(n). Por isso existem árvores que se reequilibram sozinhas, como a AVL (ADELSON-VEL’SKII; LANDIS, 1962) e a rubro-negra (GUIBAS; SEDGEWICK, 1978). Um percurso em-ordem (esquerda, raiz, direita) sempre devolve os valores ordenados.

Recursão, altura e espaço

A inserção desce um nível por chamada recursiva, então o tempo é proporcional à altura h. Em uma árvore razoavelmente balanceada, h é O(log n). Em uma árvore degenerada, como a da segunda parte do exemplo (valores de 1 a 5 inseridos em ordem), h é n − 1 e o tempo é O(n).

O espaço dos nós é O(n). A recursão também usa pilha de execução, de tamanho O(h): O(log n) no caso balanceado e O(n) no degenerado. Esse é um motivo prático para escrever a inserção de forma iterativa em árvores muito profundas. Percorrer a árvore inteira, em qualquer ordem, custa O(n), pois cada nó é visitado uma vez.

OperaçãoTempoEspaço extra
Buscar, inserir ou removerO(h): O(log n) balanceada; O(n) degeneradaO(h) de pilha (recursiva)
Percurso completo (em-ordem, pré-ordem, pós-ordem)O(n)O(h) de pilha (recursiva)
Guardar n nós—O(n)

Exemplo prático em C · arvore.c

#include <stdio.h>
#include <stdlib.h>

typedef struct No {
    int v;
    struct No *esq, *dir;
} No;

static No *novo_no(int v) {
    No *n = malloc(sizeof *n);
    if (!n) exit(1);
    n->v = v;
    n->esq = n->dir = NULL;
    return n;
}

/* Inserção recursiva: custo O(h), com h a altura da árvore */
static No *inserir(No *raiz, int v) {
    if (raiz == NULL) return novo_no(v);
    if (v < raiz->v)      raiz->esq = inserir(raiz->esq, v);
    else if (v > raiz->v) raiz->dir = inserir(raiz->dir, v);
    return raiz;                                  /* repetidos são ignorados */
}

/* Percurso em-ordem: esquerda, raiz, direita */
static void em_ordem(const No *raiz) {
    if (raiz == NULL) return;
    em_ordem(raiz->esq);
    printf("%d ", raiz->v);
    em_ordem(raiz->dir);
}

/* Número de níveis; a altura em arestas é este valor menos 1 */
static int niveis(const No *raiz) {
    if (raiz == NULL) return 0;
    int e = niveis(raiz->esq), d = niveis(raiz->dir);
    return 1 + (e > d ? e : d);
}

static void liberar(No *raiz) {
    if (raiz == NULL) return;
    liberar(raiz->esq);
    liberar(raiz->dir);
    free(raiz);
}

int main(void) {
    int seq[] = {50, 30, 70, 20, 40, 60, 80, 35};
    No *raiz = NULL;
    for (int i = 0; i < 8; i++) raiz = inserir(raiz, seq[i]);

    printf("em-ordem: ");
    em_ordem(raiz);
    printf("\naltura: %d arestas\n", niveis(raiz) - 1);

    /* Caso ruim: valores já ordenados formam uma "lista" */
    No *ruim = NULL;
    for (int v = 1; v <= 5; v++) ruim = inserir(ruim, v);
    printf("inserindo 1..5 em ordem: altura %d arestas\n", niveis(ruim) - 1);

    liberar(raiz);
    liberar(ruim);
    return 0;
}

Saída: em-ordem: 20 30 35 40 50 60 70 80, altura de 3 arestas; com valores de 1 a 5 em ordem, a altura sobe para 4 arestas.

Animação: inserir oito valores e percorrer em-ordem

Inserimos 50, 30, 70, 20, 40, 60, 80 e 35. Em cada inserção, o caminho percorrido fica destacado. Ao final, o percurso em-ordem revela a sequência ordenada.

9. Grafos: vértices, arestas e travessias

Um grafo G = (V, E) é um conjunto de vértices ligados por arestas. Ele modela redes sociais, mapas, dependências entre tarefas e a web. Pode ser dirigido (as arestas têm sentido) ou não dirigido, e pode ter pesos nas arestas (CORMEN et al., 2022, cap. 22).

Há duas representações clássicas. A matriz de adjacências usa uma tabela V × V: consulta de aresta em O(1), mas ocupa O(V²) de memória. A lista de adjacências guarda, para cada vértice, a lista de vizinhos: ocupa O(V + E) e é preferida na maioria dos casos esparsos.

Duas travessias são fundamentais. A busca em largura (BFS) usa uma fila e visita o grafo em camadas, a partir da origem. Em grafos sem pesos, ela encontra os caminhos mais curtos (MOORE, 1959). A busca em profundidade (DFS) usa uma pilha (ou a própria recursão) e desce por um caminho até o fim antes de voltar; ela é a base para detectar ciclos e componentes conexos (TARJAN, 1972).

Quanto custa percorrer um grafo?

Na BFS e na DFS, cada vértice entra uma vez na fila ou na pilha, e cada aresta é examinada uma vez (duas vezes no caso não dirigido, uma de cada lado). O tempo é O(V + E). Note que V + E não é sempre O(V²): em um grafo esparso, E é muito menor que V².

O espaço depende da representação. A lista de adjacências ocupa O(V + E). A matriz de adjacências ocupa O(V²), mesmo que o grafo tenha poucas arestas. O vetor visitado usa O(V), e a fila ou a pilha auxiliar usa O(V) no pior caso (CORMEN et al., 2022, cap. 22). Na prática, a lista domina em grafos esparsos, que são o caso típico de redes e mapas.

OperaçãoLista de adjacênciasMatriz de adjacências
Verificar se existe a aresta u–vO(grau de u)O(1)

EspaçoO(V + E)O(V²)

Exemplo prático em C · grafo.c

#include <stdio.h>

#define V     7    /* vértices A..G, numerados 0..6 */
#define GRAU  4    /* grau máximo usado nos exemplos */
#define TAM   64   /* capacidade das filas e pilhas auxiliares */

typedef struct {
    int vizinhos[GRAU];
    int n;         /* quantos vizinhos esse vértice tem */
} Lista;

/* Grafo não dirigido: cada aresta entra nas duas listas */
static void aresta(Lista g[], int u, int v) {
    g[u].vizinhos[g[u].n++] = v;
    g[v].vizinhos[g[v].n++] = u;
}

/* BFS com fila: visita em camadas */
static void bfs(const Lista g[], int origem) {
    int visitado[V] = {0};
    int fila[TAM], ini = 0, fim = 0;

    fila[fim++] = origem;
    visitado[origem] = 1;
    while (ini < fim) {
        int u = fila[ini++];
        printf("%c ", 'A' + u);
        for (int k = 0; k < g[u].n; k++) {
            int v = g[u].vizinhos[k];
            if (!visitado[v]) {
                visitado[v] = 1;
                fila[fim++] = v;
            }
        }
    }
    printf("\n");
}

/* DFS iterativa com pilha: empilha os vizinhos na ordem inversa */
static void dfs(const Lista g[], int origem) {
    int visitado[V] = {0};
    int pilha[TAM], topo = 0;

    pilha[topo++] = origem;
    while (topo > 0) {
        int u = pilha[--topo];
        if (visitado[u]) continue;
        visitado[u] = 1;
        printf("%c ", 'A' + u);
        for (int k = g[u].n - 1; k >= 0; k--) {
            int v = g[u].vizinhos[k];
            if (!visitado[v]) pilha[topo++] = v;
        }
    }
    printf("\n");
}

int main(void) {
    Lista g[V] = {{{0}, 0}};

    /* Arestas: A-B, A-C, B-D, B-E, C-F, E-G, F-G */
    aresta(g, 0, 1);
    aresta(g, 0, 2);
    aresta(g, 1, 3);
    aresta(g, 1, 4);
    aresta(g, 2, 5);
    aresta(g, 4, 6);
    aresta(g, 5, 6);

    printf("BFS a partir de A: ");
    bfs(g, 0);
    printf("DFS a partir de A: ");
    dfs(g, 0);
    return 0;
}

Saída: BFS a partir de A: A B C D E F G e DFS a partir de A: A B D E G F C.

Animação: BFS e DFS no mesmo grafo

O grafo tem sete vértices, todos alcançáveis a partir de A. Os vértices verdes já foram visitados; o âmbar é o vértice atual. A faixa de baixo mostra a estrutura auxiliar: fila na BFS, pilha na DFS.

Escolhendo a estrutura certa

A pergunta-chave é: quais operações são frequentes? A estrutura ideal é a que torna essas operações baratas.

Teste seus conhecimentos

Qual é o custo de acessar arr[i] em um vetor com n elementos?

Correto. O endereço é calculado diretamente: base + i × tamanho, sem depender de n.

Uma busca binária é aplicada a um vetor que não está ordenado. O que pode acontecer?

Correto. A regra de descarte pressupõe a ordem. Sem ela, o algoritmo pode dar uma resposta errada sem avisar.

Qual estrutura verifica de forma natural se os parênteses de uma expressão estão balanceados?

Correto. Cada abertura é empilhada e cada fechamento deve casar com o topo, que é desempilhado.

Em uma tabela hash com encadeamento, o que é uma colisão?

Correto. Como há mais chaves possíveis do que baldes, colisões são inevitáveis, e o encadeamento as resolve com uma lista por balde.

Qual estrutura a busca em largura (BFS) usa para explorar o grafo em camadas?

Correto. A fila (FIFO) faz com que os vizinhos da origem sejam visitados antes dos vizinhos dos vizinhos.

Um laço percorre o vetor e, dentro dele, outro laço percorre o vetor inteiro de novo. Qual é a complexidade temporal?

Correto. Laços aninhados multiplicam: n passos externos, cada um com n internos, dão n² operações. A constante 2 seria descartada.

Por que o fatorial iterativo tem complexidade espacial O(1), enquanto a versão recursiva tem O(n)?

Correto. O espaço auxiliar cresce com a profundidade da recursão. Ambas executam O(n) passos, mas só a recursiva guarda n quadros ao mesmo tempo.

O que levar desta aula

  • Toda estrutura é um contrato (o que faz) implementado por uma forma de memória (como faz). O custo nasce da combinação dos dois.
  • Vetores dão acesso O(1) por índice; inserções e remoções no meio custam O(n) por causa dos deslocamentos.
  • Ordenar é manter um invariante. Bolha e inserção são O(n²); quicksort e merge sort são O(n log n) na média.
  • A busca binária corta o intervalo pela metade a cada passo, mas só funciona em vetor ordenado.
  • Filas (FIFO) e pilhas (LIFO) controlam a ordem de atendimento. A fila leva à BFS; a pilha, à DFS e à verificação de parênteses.
  • Tabelas hash dão acesso médio O(1) ao custo de tratar colisões e de redimensionar quando o fator de carga cresce.
  • Árvores binárias de busca mantêm a ordem, com custo O(h). Balancear a árvore é o que garante O(log n).
  • Grafos modelam relações arbitrárias. BFS (fila) dá caminhos mais curtos em grafos sem peso; DFS (pilha) serve para explorar e detectar ciclos.
  • Big-O descreve o crescimento do custo no pior caso, descartando constantes e termos menores. Compare O(log n), O(n), O(n log n) e O(n²) pela escala, não por um valor isolado.
  • A complexidade espacial conta a memória auxiliar. Recursão custa O(profundidade) em pilha de execução; estruturas auxiliares custam conforme o seu tamanho.
  • Em C, toda estimativa de custo precisa considerar o que o programador controla: tamanho de buffers, malloc/free e a recursão.
