Tópico 5 · Busca linear e binária

Buscar é achar um valor numa coleção. Parece simples, mas a forma de buscar muda o custo de forma enorme: uma busca pode precisar olhar todos os elementos, ou apenas uma dúzia de comparações. Nesta página você vai ver as duas buscas fundamentais, com código em C, depuração passo a passo e exemplos reais.

O que você vai conseguir fazer

  • Implementar a busca linear e a busca binária em C e explicar cada linha.
  • Depurar as duas buscas com o seu próprio vetor e o valor que você escolher.
  • Reconhecer quando a binária é permitida (vetor ordenado) e quando a linear é a escolha certa.
  • Evitar os erros clássicos de busca binária: ordem errada, estouro e laço infinito.
  • Explicar onde essas buscas aparecem em bancos de dados, bibliotecas e ferramentas como o Git.
Dica para estudar: leia as duas seções nesta ordem, rode o depurador de cada uma com um vetor seu e só depois veja os exemplos. Depurar é a forma mais rápida de entender um laço.

Antes de começar: medir uma busca

Para comparar algoritmos, contamos comparações: quantas vezes o programa olha um valor do vetor. Essa conta não depende do computador e mostra como o custo cresce quando o vetor cresce.

Tamanho nBusca linear (pior caso)Busca binária (pior caso)
1010 comparações4 comparações
1 0001 000 comparações10 comparações
1 000 0001 000 000 comparações20 comparações
1 000 000 0001 000 000 000 comparações30 comparações

A linear cresce junto com n. A binária cresce com log₂ n: cada comparação elimina metade dos candidatos. Por isso, em um vetor de bilhão de valores, a binária faz cerca de 30 comparações e a linear, um bilhão.

Parte 1 · Busca linear

A busca linear é a mais simples: percorre o vetor do início ao fim e para no primeiro valor igual ao buscado. Não exige ordem, por isso é a escolha natural quando o vetor é desordenado e a busca acontece uma única vez.

O código em C

Em C · busca_linear · 05-busca.c, linhas 9 a 13

static long busca_linear(const int a[], size_t n, int x) {
    for (size_t i = 0; i < n; i++)
        if (a[i] == x) return (long)i;
    return -1;
}

Exemplos em C

O primeiro exemplo conta as comparações, para você medir o custo. O segundo usa uma sentinela: o alvo é colocado depois do fim do vetor, e o laço não precisa testar o limite a cada volta.

Em C · 05-busca-etapas.c · ex-a: contar comparações

static long linear_contando(const int a[], size_t n, int x, int *cmp) {
    *cmp = 0;
    for (size_t i = 0; i < n; i++) {
        (*cmp)++;
        if (a[i] == x) return (long)i;
    }
    return -1;
}

Em C · 05-busca-etapas.c · ex-b: sentinela

 * então o laço não precisa testar i < n a cada volta. Exige a[n] livre. */
static long linear_sentinela(int a[], size_t n, int x) {
    int salvo = a[n];
    a[n] = x;
    size_t i = 0;
    while (a[i] != x) i++;
    a[n] = salvo;
    return (i < n) ? (long)i : -1;
}

Parte 2 · Busca binária

A busca binária compara o valor buscado com o elemento do meio do intervalo. Se o valor é menor, a metade direita não pode conter o valor e é descartada; se é maior, a esquerda sai. Cada comparação elimina metade dos candidatos.

Pré-condição obrigatória: o vetor precisa estar ordenado. Em um vetor desordenado, descartar uma metade pode eliminar o valor buscado, e a busca responde "não existe" sem nenhum aviso.

O código em C

Em C · busca_binaria (versão iterativa) · 05-busca.c, linhas 17 a 26

static long busca_binaria(const int a[], size_t n, int x) {
    size_t lo = 0, hi = n;                         /* intervalo [lo, hi) */
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        if (a[mid] == x) return (long)mid;
        if (a[mid] < x) lo = mid + 1;
        else hi = mid;
    }
    return -1;
}

Exemplos em C

A trilha mostra o intervalo e o meio em cada passo. O exemplo seguinte explica por que o meio é calculado como lo + (hi − lo) / 2.

Em C · 05-busca-etapas.c · ex-c: trilha da binária

static long binaria_trilha(const int a[], size_t n, int x) {
    size_t lo = 0, hi = n;
    int passo = 0;
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        passo++;
        printf("  passo %d: intervalo [%zu, %zu) meio=%zu a[meio]=%d\n", passo, lo, hi, mid, a[mid]);
        if (a[mid] == x) {
            printf("  achou em %zu após %d passos\n", mid, passo);
            return (long)mid;
        }
        if (a[mid] < x) lo = mid + 1;
        else hi = mid;
    }
    printf("  intervalo vazio após %d passos: não existe\n", passo);
    return -1;
}

Em C · 05-busca-etapas.c · ex-d: o estouro do meio

static void demonstra_estouro(void) {
    unsigned int lo = 3000000000u, hi = 3500000000u;
    unsigned int ingenuo = (lo + hi) / 2;      /* a soma passa de UINT_MAX e dá a volta */
    unsigned int seguro = lo + (hi - lo) / 2;
    printf("  lo=%u hi=%u\n", lo, hi);
    printf("  (lo + hi) / 2     = %u  (errado: a soma estourou)\n", ingenuo);
    printf("  lo + (hi - lo)/2  = %u  (correto)\n", seguro);
}

Operação 3 · lower_bound: a primeira posição

Em vetores com repetições, a pergunta útil costuma ser onde começa o valor. lower_bound devolve a primeira posição com a[i] ≥ x. Ela é a busca binária com uma troca: quando a[mid] ≥ x, a resposta está em mid ou à esquerda, então guardamos hi = mid. Com ela, contar ocorrências é lower_bound(x+1) − lower_bound(x).

Em C · 05-busca.c · op:lower-bound

static size_t lower_bound(const int a[], size_t n, int x) {
    size_t lo = 0, hi = n;
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        if (a[mid] < x) lo = mid + 1;
        else hi = mid;
    }
    return lo;                                     /* primeira posição com a[i] >= x */
}

Animação: lower_bound, a primeira ocorrência

Com valores repetidos, lower_bound converge para a primeira posição com valor maior ou igual ao alvo.

Linear ou binária: qual escolher

CritérioBusca linearBusca binária
Exige vetor ordenado?NãoSim
Custo no pior casoO(n)O(log n)
Memória extraO(1)O(1) iterativa
Quando vale a penabusca única, vetor pequeno ou desordenadomuitas buscas em dados ordenados que mudam pouco

Ordenar um vetor custa O(n log n). Se você vai fazer uma única busca, ordenar não compensa: a linear é mais barata. Se vai fazer milhares de buscas no mesmo vetor, a ordenação se paga logo.

Animação: a corrida

As duas buscas procuram o mesmo valor no mesmo vetor ordenado. Cada quadro é uma comparação de cada uma. A linear avança uma posição por vez; a binária salta para o meio do intervalo.

Erros comuns e casos de borda

Estes são os erros que mais aparecem em busca. Cada um tem um exemplo curto. São trechos ilustrativos, para você reconhecer o problema; a versão correta está nas seções anteriores.

1. Buscar binário em vetor desordenado

Em C · ilustrativo

int a[] = {7, 2, 9};   /* desordenado */
long r = busca_binaria(a, 3, 7);
/* r == -1, mas 7 está em a[0]: a regra de descarte foi aplicada a um vetor fora de ordem */

2. Laço infinito ao atualizar os limites errado

Em C · ilustrativo

while (lo < hi) {
    size_t mid = lo + (hi - lo) / 2;
    if (a[mid] < x) lo = mid;      /* errado: deveria ser mid + 1 */
    else hi = mid;
}
/* com lo == mid, o intervalo nunca encolhe quando hi = lo + 1 */

3. Tamanho zero com índice inclusivo

Em C · ilustrativo

size_t hi = n - 1;   /* se n == 0, n - 1 dá a volta: vira o maior valor de size_t */

A versão desta página usa o intervalo [lo, hi), em que hi = n é válido. Isso evita o problema: com n = 0, o laço simplesmente não roda.

4. Estouro no meio

O exemplo ex-d mostra o caso: (lo + hi) / 2 pode estourar o tipo, enquanto lo + (hi − lo) / 2 nunca estoura.

Sempre teste com: vetor vazio, um elemento, valor na primeira posição, valor na última, valor inexistente menor que o primeiro e maior que o último, e valores repetidos.

Agenda de contatos

Uma lista de nomes ordenada é uma agenda. Comparar strings com strcmp dá a ordem alfabética, e a binária encontra o nome em log₂ n comparações.

Em C · 05-busca-etapas.c · ex-e: agenda

static long agenda_busca(const char *nomes[], size_t n, const char *alvo) {
    size_t lo = 0, hi = n;
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        int c = strcmp(nomes[mid], alvo);
        if (c == 0) return (long)mid;
        if (c < 0) lo = mid + 1;
        else hi = mid;
    }
    return -1;
}

Valores repetidos

Com repetições, a linear conta todas as ocorrências. A binária faz lower_bound(x + 1) − lower_bound(x): a diferença entre as duas primeiras posições é a quantidade de ocorrências de x.

Em C · 05-busca-etapas.c · ex-f: ocorrências

static size_t lower_bound(const int a[], size_t n, int x) {
    size_t lo = 0, hi = n;
    while (lo < hi) {
        size_t m = lo + (hi - lo) / 2;
        if (a[m] < x) lo = m + 1;
        else hi = m;
    }
    return lo;
}

static size_t ocorrencias_linear(const int a[], size_t n, int x) {
    size_t c = 0;
    for (size_t i = 0; i < n; i++)
        if (a[i] == x) c++;
    return c;
}

static size_t ocorrencias_binaria(const int a[], size_t n, int x) {
    return lower_bound(a, n, x + 1) - lower_bound(a, n, x);
}

Aplicação: git bisect

Quando um bug aparece, o git bisect localiza o commit que o introduziu. Você marca um commit bom e um ruim, e o Git testa o commit do meio, repetindo até achar o primeiro ruim. Com 16 commits, bastam 4 testes. O exemplo ex-g é o mesmo raciocínio em C.

Em C · 05-busca-etapas.c · ex-g: bisect

static int ruim(int commit, int primeiro_ruim) {
    return commit >= primeiro_ruim;
}

static int bisect(int total, int primeiro_ruim) {
    int lo = 1, hi = total, testes = 0;
    while (lo < hi) {
        int meio = lo + (hi - lo) / 2;
        testes++;
        printf("  testa commit %d: %s\n", meio, ruim(meio, primeiro_ruim) ? "ruim" : "bom");
        if (ruim(meio, primeiro_ruim)) hi = meio;
        else lo = meio + 1;
    }
    printf("  primeiro commit ruim = %d, encontrado em %d testes\n", lo, testes);
    return lo;
}

Onde a busca é aplicada no dia a dia

  • Índices de banco de dados: a maioria dos índices é uma árvore B. Dentro de cada página, a busca pelas chaves é binária; é por isso que achar uma linha pela chave primária é rápido mesmo com milhões de registros.
  • Bibliotecas padrão: Python tem o módulo bisect; Java tem Arrays.binarySearch; C tem bsearch na biblioteca padrão.
  • Git: git bisect acha o commit que introduziu um bug em log₂ n testes.
  • Tabelas de faixa: imposto, frete e tarifas são tabelas ordenadas de limites; achar a faixa de um valor é uma busca.
  • Logs e séries temporais: arquivos ordenados por horário são buscados por data sem ler o arquivo inteiro.
  • Autocomplete: a lista de palavras ordenada permite achar o primeiro nome que começa com um prefixo.

Como o mercado trata a busca

Busca binária é um dos temas mais cobrados em entrevistas técnicas de software, em três formas: a busca clássica, a busca de limites (lower e upper bound) e a busca sobre a resposta. O motivo é prático: quem entende a pré-condição, o intervalo e os casos de borda escreve a busca sem erro. Os erros mais comuns são justamente os de limite (BENTLEY, 1999; BLOCH, 2006).

Na engenharia real, a decisão é de projeto, não só de algoritmo. Busca binária exige dados ordenados: se a tabela muda muito, manter a ordem custa caro, e costuma-se preferir hash para igualdade ou árvore balanceada para dados dinâmicos. A pergunta de um profissional é: os dados estão ordenados, mudam pouco e são consultados muitas vezes?

  • Documentação oficial: Python, bisect (docs.python.org/3/library/bisect.html); Java, Arrays.binarySearch (docs.oracle.com, pacote java.util); Git, git bisect (git-scm.com/docs/git-bisect).
  • Padrão C: ISO/IEC 9899:2018, função bsearch de stdlib.h, que exige vetor ordenado pelo mesmo critério de comparação.
  • Banco de dados: COMER, D. "The Ubiquitous B-Tree". ACM Computing Surveys, v. 11, n. 2, p. 121–137, 1979.
  • Livros: BENTLEY, J. Programming Pearls. 2. ed. Addison-Wesley, 1999, cap. 4; KNUTH, D. E. The Art of Computer Programming, v. 3, seção 6.2.1.
  • Erro clássico: BLOCH, J. "Extra, extra – read all about it: nearly all binary searches and mergesorts are broken". Google Research Blog, 2006.

Quando usar a busca binária, e quando não

  • Use a binária: dados ordenados, estáticos ou quase estáticos, consultados muitas vezes; buscas por intervalo, limite ou prefixo; problemas com resposta monotônica.
  • Use a linear: vetor pequeno, vetor desordenado, ou uma única busca (ordenar sairia mais caro).
  • Use hash para igualdade pura em grande volume: O(1) em média.
  • Use árvore balanceada quando os dados mudam e precisam continuar ordenados.

Padrão de resolução: busca sobre a resposta

Muitos problemas pedem “o menor/maior valor tal que …”. Se a condição é monotônica (se vale para um valor, vale para os seguintes, ou o contrário), não precisamos adivinhar a resposta: buscamos sobre o intervalo de respostas possíveis. Cada teste custa O(f) e o número de testes é log(intervalo). O exercício de raiz quadrada ilustra o padrão.

  1. Defina o intervalo de respostas possíveis [lo, hi].
  2. Escreva um teste viável(x), monotônico em x.
  3. Busque o menor (ou maior) x com viável(x) verdadeiro.
  4. Cuidado com o meio: arredonde para cima quando a resposta pode ser mid, para não entrar em laço infinito.

Exercícios resolvidos

Exercício 1: primeira ocorrência

Enunciado. Num vetor ordenado com repetições, devolva o índice da primeira ocorrência de x, ou −1.

Ideia. lower_bound já devolve a primeira posição com valor ≥ x. Basta verificar se essa posição existe e contém exatamente x. Se a busca comum devolvesse uma ocorrência qualquer, precisaríamos andar para trás, o que seria O(n) no pior caso.

Complexidade: O(log n).

Em C · 05-busca.c · ex:primeira

static long primeira_ocorrencia(const int a[], size_t n, int x) {
    size_t p = lower_bound(a, n, x);
    return (p < n && a[p] == x) ? (long)p : -1;
}

Exercício 2: raiz quadrada inteira

Enunciado. Calcule o maior r tal que r² ≤ n, sem usar funções de ponto flutuante.

Padrão: busca sobre a resposta. A condição r² ≤ n é verdadeira até um certo r e falsa depois. Para evitar estouro, escrevemos mid ≤ n / mid em vez de mid · mid ≤ n. O meio arredonda para cima, para que lo = mid avance sempre.

Complexidade: O(log n) testes, cada um O(1).

Em C · 05-busca.c · ex:raiz

static unsigned long raiz_inteira(unsigned long n) {
    unsigned long lo = 0, hi = n;                  /* a resposta está em [lo, hi] */
    while (lo < hi) {
        unsigned long mid = lo + (hi - lo + 1) / 2;   /* arredonda para cima */
        if (mid <= n / mid) lo = mid;              /* mid² <= n, sem estouro */
        else hi = mid - 1;
    }
    return lo;
}

Exercício 3: mínimo em vetor ordenado e rotacionado

Enunciado. O vetor [4,5,6,7,0,1,2] foi ordenado e depois rotacionado. Encontre o mínimo em O(log n), com valores distintos.

Ideia. Em um vetor rotacionado, a metade que contém a virada tem o mínimo. Comparar a[mid] com a[hi] decide de que lado a virada está: se a[mid] > a[hi], o mínimo está à direita de mid; senão, mid ou algo à esquerda dele é o mínimo.

Complexidade: O(log n).

Em C · 05-busca.c · ex:rotacionado

static int minimo_rotacionado(const int a[], size_t n) {
    size_t lo = 0, hi = n - 1;
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        if (a[mid] > a[hi]) lo = mid + 1;          /* o mínimo está à direita */
        else hi = mid;
    }
    return a[lo];
}

Exercício 4: elemento de pico

Enunciado. Um pico é um elemento maior que seus vizinhos. Encontre um pico em O(log n), sabendo que a[i] ≠ a[i+1].

Ideia. Se a[mid] < a[mid+1], o vetor está subindo: um pico existe à direita (o último elemento pode ser o pico, com a fronteira implícita −∞). Senão, o vetor está descendo ou em um pico: há pico em mid ou à esquerda. Assim, a busca sempre tem um lado garantido.

Complexidade: O(log n).

Em C · 05-busca.c · ex:pico

static size_t achar_pico(const int a[], size_t n) {
    size_t lo = 0, hi = n - 1;
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        if (a[mid] < a[mid + 1]) lo = mid + 1;     /* subindo: pico à direita */
        else hi = mid;                             /* descendo: pico em mid ou à esquerda */
    }
    return lo;
}

Conceitos complementares e uso no dia a dia

Conceitos complementares

  • Busca interpolada: se os valores estão uniformemente distribuídos, estimar a posição pelo valor (em vez de pelo meio) reduz as comparações para O(log log n) em média.
  • Índices e trade-offs: uma busca O(log n) em árvore B é cara em escrita, mas barata em leitura. Hash dá O(1) médio, mas não preserva ordem para busca por intervalo.
  • Busca sobre a resposta: é a ferramenta por trás de problemas de alocação, como "qual a menor capacidade que atende a todos os pedidos".
  • Invariantes de busca: o erro clássico é atualizar os limites de forma que o intervalo não encolha. Um teste simples com vetores pequenos descobre quase todos os erros.

Onde isso aparece no dia a dia

  • Git bisect: para achar em qual commit um bug entrou, o Git faz busca binária no histórico, testando o commit do meio. Com 1024 commits, são 10 testes.
  • Autocompletar e dicionários: sugestões em ordem alfabética são obtidas por busca binária no vetor de palavras ordenadas.
  • Agenda e contatos: aplicativos de contatos mantêm a lista ordenada por nome e buscam por prefixo com lower_bound.
  • Tabelas de preço e faixas: calcular a faixa de imposto ou de frete de um valor é uma busca binária em uma tabela ordenada de limites.

Exercícios propostos

P1. Menor capacidade de navio para enviar todos os pacotes em D dias, com pesos em ordem fixa e capacidade igual a cada dia.

Resposta: busca sobre a resposta. O intervalo é [maior peso, soma total]. O teste “com capacidade c, cabe em D dias?” é monotônico em c. Cada teste é O(n), total O(n log(soma)).

P2. Dado um vetor ordenado, conte quantas vezes x aparece, em O(log n).

Resposta: lower_bound(x + 1) − lower_bound(x). Cada chamada é O(log n). Cuidado com a diferença de tipos quando x é o maior inteiro possível.

Teste seus conhecimentos

Quantas comparações, no máximo, a busca binária faz em um vetor de 1024 elementos?

Correto. Cada comparação reduz o intervalo pela metade: 1024 → 512 → … → 1, são ⌊log₂ 1024⌋ + 1 = 11 comparações no máximo.

Por que lo + (hi − lo) / 2 é preferível a (lo + hi) / 2?

Correto. A soma lo + hi pode ultrapassar o máximo do tipo int antes da divisão, mesmo que o índice médio caiba. Bloch (2006) descreveu esse erro.

Em qual cenário a busca linear é preferível à binária?

Correto. Ordenar custa O(n log n); se a busca é única, ordenar não compensa. A binária só vale a pena com muitas buscas sobre dados já ordenados.

O que levar desta página

  • Busca linear não exige nada e custa O(n); busca binária exige ordem e custa O(log n).
  • Use intervalos semiabertos e atualize lo ou hi de forma que o espaço de busca sempre diminua.
  • Para a primeira ocorrência, use lower_bound.
  • Problemas de “menor valor que satisfaz …” com condição monotônica são busca sobre a resposta.
