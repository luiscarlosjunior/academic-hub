Tópico 5 · Busca

Buscar é a operação mais frequente em qualquer sistema: achar um usuário, uma chave, uma posição. O custo depende de duas coisas: se os dados estão organizados, e quanto da organização o algoritmo consegue aproveitar. Esta página vai da busca linear, que não exige nada, à busca binária, que exige ordem e transforma O(n) em O(log n), e à busca sobre a resposta, que usa a mesma ideia para problemas que nem parecem de busca.

Objetivos desta página. Ao final, você deve conseguir:

  • justificar a busca linear e calcular seu custo, com e sem ordem;
  • implementar a busca binária de forma correta, sem armadilhas de limites;
  • usar lower_bound para achar a primeira ocorrência;
  • aplicar busca sobre a resposta a problemas com resposta monotônica.

Teoria: por que dividir ao meio funciona

Numa busca binária, comparamos o alvo com o elemento do meio. Se o alvo é menor, a metade direita não pode conter o alvo, e a descartamos sem olhar. Cada comparação elimina metade do espaço restante. Após k comparações, restam n / 2k candidatos. O processo termina quando resta um, ou seja, k = log₂ n: O(log n). Para um bilhão de elementos, bastam cerca de 30 comparações.

A regra é absoluta: a busca binária só funciona se o vetor estiver ordenado. Sem a ordem, descartar uma metade pode eliminar o alvo, e o algoritmo devolve “não encontrado” sem nenhum aviso. Bentley (1999, cap. 4) mostrou que uma fração grande das implementações publicadas tinha algum erro sutil de limites, e Bloch (2006) descreveu um desses erros, de estouro de inteiro, que aparecia em bibliotecas padrão. A forma segura do meio é lo + (hi − lo) / 2.

Operação 1 · Busca linear

Percorre o vetor do início ao fim até achar o valor. É o método certo quando os dados não estão ordenados e a busca é feita uma única vez: ordenar custa O(n log n), mais do que a própria busca. Pior caso: O(n), quando o valor não existe ou está no fim.

Em C · 05-busca.c · op:linear

static long busca_linear(const int a[], size_t n, int x) {
    for (size_t i = 0; i < n; i++)
        if (a[i] == x) return (long)i;
    return -1;
}

Animação: busca linear

Operação 2 · Busca binária

A versão iterativa mantém o intervalo semiaberto [lo, hi): o alvo, se existir, está dentro dele. Essa convenção evita casos especiais: lo == hi significa intervalo vazio. A versão recursiva é mais clara, mas usa O(log n) de pilha. Em C, prefira a iterativa.

Em C · 05-busca.c · op:binaria-iter

static long busca_binaria(const int a[], size_t n, int x) {
    size_t lo = 0, hi = n;                         /* intervalo [lo, hi) */
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        if (a[mid] == x) return (long)mid;
        if (a[mid] < x) lo = mid + 1;
        else hi = mid;
    }
    return -1;
}

Em C · 05-busca.c · op:binaria-rec

static long busca_rec(const int a[], size_t lo, size_t hi, int x) {
    if (lo >= hi) return -1;
    size_t mid = lo + (hi - lo) / 2;
    if (a[mid] == x) return (long)mid;
    if (a[mid] < x) return busca_rec(a, mid + 1, hi, x);
    return busca_rec(a, lo, mid, x);
}

static long busca_binaria_rec(const int a[], size_t n, int x) {
    return busca_rec(a, 0, n, x);
}

Animação: busca binária

Os elementos apagados já foram descartados. Teste um valor presente, um ausente e o primeiro elemento.

Operação 3 · lower_bound: a primeira posição

Em vetores com repetições, a pergunta útil costuma ser onde começa o valor. lower_bound devolve a primeira posição com a[i] ≥ x. Ela é a busca binária com uma troca: quando a[mid] ≥ x, a resposta está em mid ou à esquerda, então guardamos hi = mid. Com ela, contar ocorrências é lower_bound(x+1) − lower_bound(x).

Em C · 05-busca.c · op:lower-bound

static size_t lower_bound(const int a[], size_t n, int x) {
    size_t lo = 0, hi = n;
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        if (a[mid] < x) lo = mid + 1;
        else hi = mid;
    }
    return lo;                                     /* primeira posição com a[i] >= x */
}

Padrão de resolução: busca sobre a resposta

Muitos problemas pedem “o menor/maior valor tal que …”. Se a condição é monotônica (se vale para um valor, vale para os seguintes, ou o contrário), não precisamos adivinhar a resposta: buscamos sobre o intervalo de respostas possíveis. Cada teste custa O(f) e o número de testes é log(intervalo). O exercício de raiz quadrada ilustra o padrão.

  1. Defina o intervalo de respostas possíveis [lo, hi].
  2. Escreva um teste viável(x), monotônico em x.
  3. Busque o menor (ou maior) x com viável(x) verdadeiro.
  4. Cuidado com o meio: arredonde para cima quando a resposta pode ser mid, para não entrar em laço infinito.

Exercícios resolvidos

Exercício 1: primeira ocorrência

Enunciado. Num vetor ordenado com repetições, devolva o índice da primeira ocorrência de x, ou −1.

Ideia. lower_bound já devolve a primeira posição com valor ≥ x. Basta verificar se essa posição existe e contém exatamente x. Se a busca comum devolvesse uma ocorrência qualquer, precisaríamos andar para trás, o que seria O(n) no pior caso.

Complexidade: O(log n).

Em C · 05-busca.c · ex:primeira

static long primeira_ocorrencia(const int a[], size_t n, int x) {
    size_t p = lower_bound(a, n, x);
    return (p < n && a[p] == x) ? (long)p : -1;
}

Exercício 2: raiz quadrada inteira

Enunciado. Calcule o maior r tal que r² ≤ n, sem usar funções de ponto flutuante.

Padrão: busca sobre a resposta. A condição r² ≤ n é verdadeira até um certo r e falsa depois. Para evitar estouro, escrevemos mid ≤ n / mid em vez de mid · mid ≤ n. O meio arredonda para cima, para que lo = mid avance sempre.

Complexidade: O(log n) testes, cada um O(1).

Em C · 05-busca.c · ex:raiz

static unsigned long raiz_inteira(unsigned long n) {
    unsigned long lo = 0, hi = n;                  /* a resposta está em [lo, hi] */
    while (lo < hi) {
        unsigned long mid = lo + (hi - lo + 1) / 2;   /* arredonda para cima */
        if (mid <= n / mid) lo = mid;              /* mid² <= n, sem estouro */
        else hi = mid - 1;
    }
    return lo;
}

Exercício 3: mínimo em vetor ordenado e rotacionado

Enunciado. O vetor [4,5,6,7,0,1,2] foi ordenado e depois rotacionado. Encontre o mínimo em O(log n), com valores distintos.

Ideia. Em um vetor rotacionado, a metade que contém a virada tem o mínimo. Comparar a[mid] com a[hi] decide de que lado a virada está: se a[mid] > a[hi], o mínimo está à direita de mid; senão, mid ou algo à esquerda dele é o mínimo.

Complexidade: O(log n).

Em C · 05-busca.c · ex:rotacionado

static int minimo_rotacionado(const int a[], size_t n) {
    size_t lo = 0, hi = n - 1;
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        if (a[mid] > a[hi]) lo = mid + 1;          /* o mínimo está à direita */
        else hi = mid;
    }
    return a[lo];
}

Exercício 4: elemento de pico

Enunciado. Um pico é um elemento maior que seus vizinhos. Encontre um pico em O(log n), sabendo que a[i] ≠ a[i+1].

Ideia. Se a[mid] < a[mid+1], o vetor está subindo: um pico existe à direita (o último elemento pode ser o pico, com a fronteira implícita −∞). Senão, o vetor está descendo ou em um pico: há pico em mid ou à esquerda. Assim, a busca sempre tem um lado garantido.

Complexidade: O(log n).

Em C · 05-busca.c · ex:pico

static size_t achar_pico(const int a[], size_t n) {
    size_t lo = 0, hi = n - 1;
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        if (a[mid] < a[mid + 1]) lo = mid + 1;     /* subindo: pico à direita */
        else hi = mid;                             /* descendo: pico em mid ou à esquerda */
    }
    return lo;
}

Mais exemplos em C

Quatro problemas adicionais, cada um com uma técnica diferente. Todos estão no arquivo 05-mais-exemplos.c, que compila com os mesmos avisos como erro.

Exemplo A: Busca em matriz achatada

Uma matriz ordenada por linhas é, em ordem linear, um vetor ordenado. Basta converter o índice linear em (linha, coluna) com divisão e resto, e aplicar a busca binária.

Em C · 05-mais-exemplos.c · ex-a

static int busca_matriz(int l, int c, const int m[][4], int alvo) {
    int lo = 0, hi = l * c - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        int v = m[mid / c][mid % c];
        if (v == alvo) return 1;
        if (v < alvo) lo = mid + 1;
        else hi = mid - 1;
    }
    return 0;
}

Exemplo B: Menor prefixo com soma mínima

A soma dos prefixos cresce com k, então a condição "soma ≥ alvo" é monotônica. A busca sobre a resposta encontra o menor k em O(log n) testes.

Em C · 05-mais-exemplos.c · ex-b

static int menor_prefixo(const int a[], int n, long alvo) {
    long p[64];
    p[0] = 0;
    for (int i = 0; i < n; i++) p[i + 1] = p[i] + a[i];
    int lo = 1, hi = n, resp = -1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (p[mid] >= alvo) { resp = mid; hi = mid - 1; }
        else lo = mid + 1;
    }
    return resp;
}

Exemplo C: Contagem de ocorrências com limites

contar(x) = primeira posição ≥ x+1 menos primeira posição ≥ x. Para um valor que não existe, como o 4 da lista, o resultado é 0.

Em C · 05-mais-exemplos.c · ex-c

static int primeiro_maior_igual(const int a[], int n, int x) {
    int lo = 0, hi = n;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] < x) lo = mid + 1;
        else hi = mid;
    }
    return lo;
}

static int contar(const int a[], int n, int x) {
    return primeiro_maior_igual(a, n, x + 1) - primeiro_maior_igual(a, n, x);
}

Exemplo D: Máximo de função unimodal (busca ternária)

Em cada passo, compara dois pontos internos e descarta um terço do intervalo. A função −(x − 3)² + 10 tem máximo em x = 3, e o método converge para ele.

Em C · 05-mais-exemplos.c · ex-d

static double f(double x) { return -(x - 3.0) * (x - 3.0) + 10.0; }

static double maximo_unimodal(double lo, double hi, int passos) {
    for (int k = 0; k < passos; k++) {
        double m1 = lo + (hi - lo) / 3.0, m2 = hi - (hi - lo) / 3.0;
        if (f(m1) < f(m2)) lo = m1;
        else hi = m2;
    }
    return (lo + hi) / 2.0;
}

Conceitos complementares e uso no dia a dia

Conceitos complementares

  • Busca interpolada: se os valores estão uniformemente distribuídos, estimar a posição pelo valor (em vez de pelo meio) reduz as comparações para O(log log n) em média.
  • Índices e trade-offs: uma busca O(log n) em árvore B é cara em escrita, mas barata em leitura. Hash dá O(1) médio, mas não preserva ordem para busca por intervalo.
  • Busca sobre a resposta: é a ferramenta por trás de problemas de alocação, como "qual a menor capacidade que atende a todos os pedidos".
  • Invariantes de busca: o erro clássico é atualizar os limites de forma que o intervalo não encolha. Um teste simples com vetores pequenos descobre quase todos os erros.

Onde isso aparece no dia a dia

  • Git bisect: para achar em qual commit um bug entrou, o Git faz busca binária no histórico, testando o commit do meio. Com 1024 commits, são 10 testes.
  • Autocompletar e dicionários: sugestões em ordem alfabética são obtidas por busca binária no vetor de palavras ordenadas.
  • Agenda e contatos: aplicativos de contatos mantêm a lista ordenada por nome e buscam por prefixo com lower_bound.
  • Tabelas de preço e faixas: calcular a faixa de imposto ou de frete de um valor é uma busca binária em uma tabela ordenada de limites.

Animação: lower_bound, a primeira ocorrência

Com valores repetidos, lower_bound converge para a primeira posição com valor maior ou igual ao alvo.

Depurador: a busca linha por linha

O depurador executa as duas buscas como o programa C faria. Escolha a busca no seletor, avance uma linha por vez e observe as variáveis: na binária, lo, hi e mid mudam a cada volta, e o intervalo encolhe pela metade.

Esta é a versão iterativa de busca_binaria. Ela mantém um intervalo que contém o alvo, se o alvo existir, e o reduz pela metade a cada volta.

Corrida: busca linear contra busca binária

As duas buscas procuram o mesmo valor no mesmo vetor ordenado de 16 posições. Cada quadro é uma comparação de cada uma. Repare que a linear avança uma posição por vez, enquanto a binária salta para o meio do intervalo.

Exemplos em C, passo a passo

Sete exemplos com um problema cada um. Eles seguem a ordem em que as ideias aparecem: contar comparações, sentinela, trilha da binária, o estouro do meio, busca de texto, repetições e, por fim, o bisect. Todo o código está em 05-busca-etapas.c, que compila com -Werror.

Contar comparações

A linear faz uma comparação por posição visitada. Contar isso é a forma mais direta de medir o custo: o contador mostra que achar o 41 leva 9 comparações num vetor de 12 valores.

Em C · 05-busca-etapas.c · ex-a

static long linear_contando(const int a[], size_t n, int x, int *cmp) {
    *cmp = 0;
    for (size_t i = 0; i < n; i++) {
        (*cmp)++;
        if (a[i] == x) return (long)i;
    }
    return -1;
}

Sentinela

Colocar o alvo logo depois do fim do vetor elimina a checagem de limite do laço. Como o alvo sempre está no vetor, o laço para sozinho. Exige uma posição extra livre: uma técnica clássica para acelerar a linear.

Em C · 05-busca-etapas.c · ex-b

 * então o laço não precisa testar i < n a cada volta. Exige a[n] livre. */
static long linear_sentinela(int a[], size_t n, int x) {
    int salvo = a[n];
    a[n] = x;
    size_t i = 0;
    while (a[i] != x) i++;
    a[n] = salvo;
    return (i < n) ? (long)i : -1;
}

Trilha da binária

Imprimir o intervalo e o meio em cada passo torna visível a redução pela metade. Para o 41, são 3 passos; para o 40, que não existe, o intervalo esvazia em 4.

Em C · 05-busca-etapas.c · ex-c

static long binaria_trilha(const int a[], size_t n, int x) {
    size_t lo = 0, hi = n;
    int passo = 0;
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        passo++;
        printf("  passo %d: intervalo [%zu, %zu) meio=%zu a[meio]=%d\n", passo, lo, hi, mid, a[mid]);
        if (a[mid] == x) {
            printf("  achou em %zu após %d passos\n", mid, passo);
            return (long)mid;
        }
        if (a[mid] < x) lo = mid + 1;
        else hi = mid;
    }
    printf("  intervalo vazio após %d passos: não existe\n", passo);
    return -1;
}

O estouro do meio

Com números grandes, (lo + hi) / 2 passa do limite do tipo e dá um índice errado. A forma lo + (hi − lo) / 2 nunca estoura, porque hi − lo é sempre menor que o próprio tipo. Foi esse bug que Bloch (2006) descreveu em bibliotecas padrão.

Em C · 05-busca-etapas.c · ex-d

static void demonstra_estouro(void) {
    unsigned int lo = 3000000000u, hi = 3500000000u;
    unsigned int ingenuo = (lo + hi) / 2;      /* a soma passa de UINT_MAX e dá a volta */
    unsigned int seguro = lo + (hi - lo) / 2;
    printf("  lo=%u hi=%u\n", lo, hi);
    printf("  (lo + hi) / 2     = %u  (errado: a soma estourou)\n", ingenuo);
    printf("  lo + (hi - lo)/2  = %u  (correto)\n", seguro);
}

Agenda de contatos

Uma lista de nomes ordenada é uma agenda. Comparar strings com strcmp dá a ordem alfabética, e a binária encontra o nome em log₂ n comparações, sem percorrer a lista.

Em C · 05-busca-etapas.c · ex-e

static long agenda_busca(const char *nomes[], size_t n, const char *alvo) {
    size_t lo = 0, hi = n;
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        int c = strcmp(nomes[mid], alvo);
        if (c == 0) return (long)mid;
        if (c < 0) lo = mid + 1;
        else hi = mid;
    }
    return -1;
}

Valores repetidos

Com repetições, a linear conta todas as ocorrências. A binária conta com lower_bound(x + 1) − lower_bound(x): a diferença entre a primeira posição de x + 1 e a de x é a quantidade de ocorrências de x.

Em C · 05-busca-etapas.c · ex-f

static size_t lower_bound(const int a[], size_t n, int x) {
    size_t lo = 0, hi = n;
    while (lo < hi) {
        size_t m = lo + (hi - lo) / 2;
        if (a[m] < x) lo = m + 1;
        else hi = m;
    }
    return lo;
}

static size_t ocorrencias_linear(const int a[], size_t n, int x) {
    size_t c = 0;
    for (size_t i = 0; i < n; i++)
        if (a[i] == x) c++;
    return c;
}

static size_t ocorrencias_binaria(const int a[], size_t n, int x) {
    return lower_bound(a, n, x + 1) - lower_bound(a, n, x);
}

Bisect

Se os commits estão em ordem e, a partir de um deles, todos estão ruins, a binária acha o primeiro ruim em log₂ n testes. É o mesmo raciocínio do git bisect, que veremos na animação a seguir.

Em C · 05-busca-etapas.c · ex-g

static int ruim(int commit, int primeiro_ruim) {
    return commit >= primeiro_ruim;
}

static int bisect(int total, int primeiro_ruim) {
    int lo = 1, hi = total, testes = 0;
    while (lo < hi) {
        int meio = lo + (hi - lo) / 2;
        testes++;
        printf("  testa commit %d: %s\n", meio, ruim(meio, primeiro_ruim) ? "ruim" : "bom");
        if (ruim(meio, primeiro_ruim)) hi = meio;
        else lo = meio + 1;
    }
    printf("  primeiro commit ruim = %d, encontrado em %d testes\n", lo, testes);
    return lo;
}

Animação: o git bisect, uma busca binária no histórico

Quando um bug aparece, o Git pode localizar o commit que o introduziu com git bisect. Você marca um commit como bom e outro como ruim, e o Git testa o commit do meio do intervalo, repetindo até achar o primeiro ruim. Com 16 commits, bastam 4 testes.

Onde a busca é aplicada no dia a dia

  • Índices de banco de dados: a maioria dos índices é uma árvore B. Dentro de cada página, a busca é binária sobre as chaves ordenadas; é por isso que achar uma linha por chave primária é rápido mesmo com milhões de registros.
  • Bibliotecas padrão: Python tem o módulo bisect; Java tem Arrays.binarySearch; C tem bsearch na biblioteca padrão. Você raramente precisa escrever a sua.
  • Git: git bisect acha o commit que introduziu um bug em log₂ n testes, mesmo que o histórico tenha milhares de commits.
  • Tabelas de faixa: imposto, frete e tarifa de energia são tabelas ordenadas de limites. Achar a faixa de um valor é uma busca pelo limite superior.
  • Logs e séries temporais: arquivos de log ordenados por horário são buscados por data com busca binária, sem ler o arquivo inteiro.
  • Listas de contatos e dicionários: a ordem alfabética permite a busca por nome e a busca por prefixo (autocomplete).

Como o mercado trata a busca binária

Busca binária é um dos temas mais cobrados em entrevistas técnicas de software, e costuma aparecer de três formas: a busca clássica, a busca de limites (lower e upper bound) e a busca sobre a resposta. O motivo é prático: quem entende a pré-condição, a invariante do intervalo e os casos de borda costuma escrever a busca sem erro. Os erros mais comuns são justamente os de limite, como os descritos por Bentley (1999) e Bloch (2006).

Na prática de engenharia, a decisão é de projeto, não só de algoritmo. Uma busca binária exige dados ordenados: se a tabela muda muito, manter a ordem custa caro, e o mercado costuma preferir uma tabela hash para igualdade ou uma árvore balanceada para dados dinâmicos. A pergunta que um profissional faz é: os dados estão ordenados, mudam pouco e são consultados muitas vezes?

  • Padrão C: ISO/IEC 9899:2018, função bsearch da biblioteca padrão (stdlib.h), que exige que o vetor esteja ordenado pelo mesmo critério de comparação.
  • Banco de dados: COMER, D. "The Ubiquitous B-Tree". ACM Computing Surveys, v. 11, n. 2, p. 121–137, 1979.
  • Livros de referência: BENTLEY, J. Programming Pearls. 2. ed. Addison-Wesley, 1999, cap. 4; KNUTH, D. E. The Art of Computer Programming, v. 3, seção 6.2.1.
  • Erro clássico: BLOCH, J. "Extra, extra – read all about it: nearly all binary searches and mergesorts are broken". Google Research Blog, 2006.

Onde a busca binária pode ser usada, e onde não

  • Pode ser usada: dados estáticos ou quase estáticos, ordenados, consultados muitas vezes; buscas por intervalo, prefixo ou limite; problemas em que a resposta é monotônica (busca sobre a resposta).
  • Não convém: dados que mudam o tempo todo sem uma estrutura de apoio; busca por igualdade pura em grande volume (uma tabela hash costuma ser melhor); vetor pequeno, em que a linear é mais simples e quase tão rápida.
  • Alternativas: hash para igualdade (O(1) médio); árvore balanceada (AVL, rubro-negra) para dados que mudam e precisam de ordem; busca linear quando o vetor não está ordenado e a busca é única.
  • Armadilhas: vetor não ordenado (o resultado vira errado sem aviso); estouro em lo + hi; laço infinito por atualizar lo ou hi de forma que o intervalo não encolha; confundir intervalo fechado com semiaberto.

Exercícios propostos

P1. Menor capacidade de navio para enviar todos os pacotes em D dias, com pesos em ordem fixa e capacidade igual a cada dia.

Resposta: busca sobre a resposta. O intervalo é [maior peso, soma total]. O teste “com capacidade c, cabe em D dias?” é monotônico em c. Cada teste é O(n), total O(n log(soma)).

P2. Dado um vetor ordenado, conte quantas vezes x aparece, em O(log n).

Resposta: lower_bound(x + 1) − lower_bound(x). Cada chamada é O(log n). Cuidado com a diferença de tipos quando x é o maior inteiro possível.

Teste seus conhecimentos

Quantas comparações, no máximo, a busca binária faz em um vetor de 1024 elementos?

Correto. Cada comparação reduz o intervalo pela metade: 1024 → 512 → … → 1, são ⌊log₂ 1024⌋ + 1 = 11 comparações no máximo.

Por que lo + (hi − lo) / 2 é preferível a (lo + hi) / 2?

Correto. A soma lo + hi pode ultrapassar o máximo do tipo int antes da divisão, mesmo que o índice médio caiba. Bloch (2006) descreveu esse erro.

Em qual cenário a busca linear é preferível à binária?

Correto. Ordenar custa O(n log n); se a busca é única, ordenar não compensa. A binária só vale a pena com muitas buscas sobre dados já ordenados.

O que levar desta página

  • Busca linear não exige nada e custa O(n); busca binária exige ordem e custa O(log n).
  • Use intervalos semiabertos e atualize lo ou hi de forma que o espaço de busca sempre diminua.
  • Para a primeira ocorrência, use lower_bound.
  • Problemas de “menor valor que satisfaz …” com condição monotônica são busca sobre a resposta.
