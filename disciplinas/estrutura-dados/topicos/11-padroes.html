Tópico 11 · Padrões de resolução de problemas

As páginas anteriores ensinaram estruturas e operações. Esta página ensina a usar essas peças. Quase todo problema de programação competitiva, de entrevista técnica ou de engenharia real cai em um pequeno número de padrões. Reconhecê-los é mais importante do que decorar soluções: um padrão é uma forma de pensar que se adapta a problemas novos.

Objetivos desta página. Ao final, você deve conseguir:

  • seguir um roteiro fixo para atacar qualquer problema, da leitura do enunciado ao teste;
  • reconhecer os sinais de cada padrão no enunciado;
  • implementar em C os padrões: dois ponteiros, janela deslizante, prefixos, backtracking, divisão e conquista, guloso e programação dinâmica;
  • justificar a escolha de um padrão com complexidade de tempo e espaço.

O roteiro de seis passos

  1. Entenda a entrada e a saída. Qual é o formato exato? Pode haver vazio, um elemento, repetidos, negativos, valores enormes? Escreva os casos de borda antes de codificar.
  2. Resolva um exemplo pequeno à mão. Use um caso de 4 a 6 elementos. Anote o que você faz, passo a passo: a intuição do método aparece aqui.
  3. Escreva a força bruta e seu custo. Ela é a referência de correção e o ponto de partida. Se ela já cabe nos limites, pare.
  4. Identifique o padrão. Procure os sinais da tabela abaixo: ordenação, intervalo contínuo, soma fixa, escolha que se repete, resposta monotônica, dependência entre subproblemas.
  5. Escolha a estrutura e otimize. Vetor ordenado, hash, pilha, fila, árvore ou grafo. A otimização quase sempre troca tempo por espaço, ou por uma ordenação prévia.
  6. Teste as bordas e compare com a força bruta. Gere entradas pequenas e aleatórias e confira as duas versões. Um teste bem escolhido vale mais que cinco revisões.

Padrão 1 · Dois ponteiros

Dois índices percorrem o vetor, geralmente das extremidades para o centro, ou ambos no mesmo sentido em velocidades diferentes. A cada passo, uma comparação decide qual ponteiro avança, e como os ponteiros só andam para a frente, o total é O(n). Sinal: vetor ordenado e um par, uma soma ou uma condição sobre dois valores.

A correção vem da ordem: se a soma atual é pequena demais, aumentar o menor valor é a única forma de crescê-la, e o maior valor já foi descartado com o par que ele formava. Sem a ordenação, essa lógica não se sustenta.

Em C · 11-padroes.c · pad:dois-ponteiros

static int par_soma(const int a[], size_t n, long alvo, size_t *i, size_t *j) {
    if (n < 2) return 0;
    size_t lo = 0, hi = n - 1;                       /* vetor já ordenado */
    while (lo < hi) {
        long s = (long)a[lo] + a[hi];
        if (s == alvo) {
            *i = lo;
            *j = hi;
            return 1;
        }
        if (s < alvo) lo++;                          /* soma pequena: aumenta o menor */
        else hi--;                                   /* soma grande: diminui o maior */
    }
    return 0;
}

Padrão 2 · Janela deslizante

Uma janela cobre um trecho contínuo do vetor. Ao andar uma posição, entra um elemento à direita e sai um à esquerda, e a soma (ou outra estatística) é atualizada em O(1). Recalcular cada janela do zero custaria O(n·k); a janela desliza em O(n). Sinal: subvetor ou substring contígua com tamanho fixo ou com uma condição sobre os elementos.

Em C · 11-padroes.c · pad:janela

static long soma_janela_max(const int a[], size_t n, size_t k, size_t *inicio) {
    long s = 0;
    for (size_t i = 0; i < k; i++) s += a[i];
    long melhor = s;
    *inicio = 0;
    for (size_t i = k; i < n; i++) {
        s += a[i] - a[i - k];                        /* entra a[i], sai a[i-k] */
        if (s > melhor) {
            melhor = s;
            *inicio = i - k + 1;
        }
    }
    return melhor;
}

Padrão 3 · Somas de prefixos

Pré-compute p[i] = a[0] + … + a[i−1] em O(n). Depois, a soma do intervalo [l, r] é p[r+1] − p[l], em O(1). Com muitas consultas, o investimento se paga: q consultas custam O(n + q), em vez de O(n·q). A mesma ideia responde a “quantos elementos com determinada propriedade existem até i?” e, combinada com hash, a “subvetor com soma k”.

Em C · 11-padroes.c · pad:prefixos

static void prefixos(const int a[], size_t n, long p[]) {    /* p tem n+1 posições */
    p[0] = 0;
    for (size_t i = 0; i < n; i++) p[i + 1] = p[i] + a[i];
}

static long soma_intervalo(const long p[], size_t l, size_t r) {   /* [l, r] inclusive */
    return p[r + 1] - p[l];
}

Padrão 4 · Backtracking

Constrói uma solução uma escolha de cada vez, explorando todas as alternativas. Quando uma escolha leva a um beco sem saída, desfaz-se a escolha e tenta-se a seguinte. Para subconjuntos, cada elemento é incluído ou não: são 2ⁿ soluções, então o custo é exponencial, mas necessário quando se precisa de todas. A chave é a poda: descartar cedo ramos que não podem dar solução.

Em C · 11-padroes.c · pad:backtracking

static void imprimir_subconjunto(const int a[], size_t k) {
    printf("{");
    for (size_t i = 0; i < k; i++) printf("%s%d", i ? "," : "", a[i]);
    printf("} ");
}

static void subconjuntos(const int a[], size_t n, size_t i, int atual[], size_t k) {
    if (i == n) {
        imprimir_subconjunto(atual, k);
        return;
    }
    subconjuntos(a, n, i + 1, atual, k);             /* escolha 1: sem a[i] */
    atual[k] = a[i];
    subconjuntos(a, n, i + 1, atual, k + 1);         /* escolha 2: com a[i] */
}

Padrão 5 · Divisão e conquista

Divide o problema em partes menores e independentes, resolve cada uma recursivamente e combina os resultados. Para o mínimo e o máximo, a recorrência T(n) = 2T(n/2) + O(1) dá O(n), sem ganho em relação à varredura, mas mostra o padrão. Em outros problemas, a combinação é o trabalho: a intercalação do merge sort e a contagem de inversões da página 4 são exemplos.

Em C · 11-padroes.c · pad:divisao

typedef struct {
    int min, max;
} MinMax;

static MinMax minmax(const int a[], size_t lo, size_t hi) {    /* [lo, hi), hi > lo */
    MinMax r;
    if (hi - lo == 1) {
        r.min = r.max = a[lo];
        return r;
    }
    size_t mid = lo + (hi - lo) / 2;
    MinMax e = minmax(a, lo, mid), d = minmax(a, mid, hi);
    r.min = e.min < d.min ? e.min : d.min;
    r.max = e.max > d.max ? e.max : d.max;
    return r;
}

Padrão 6 · Algoritmo guloso

Faz, a cada passo, a escolha que parece melhor no momento, sem voltar atrás. Funciona quando o problema tem subestrutura ótima e escolha gulosa segura: a escolha local pode ser completada até uma solução ótima. Essa propriedade precisa ser provada. O exemplo de troco funciona para o sistema de moedas 25, 10, 5 e 1, mas falha para sistemas arbitrários: com moedas 1, 3 e 4, o troco de 6 gulosamente seria 4 + 1 + 1 (três moedas), enquanto 3 + 3 usa duas.

Em C · 11-padroes.c · pad:guloso

static int moedas_gulosas(int valor, int usadas[4]) {    /* sistema 25, 10, 5, 1 */
    const int sistema[4] = {25, 10, 5, 1};
    int total = 0;
    for (size_t i = 0; i < 4; i++) {
        usadas[i] = valor / sistema[i];
        total += usadas[i];
        valor %= sistema[i];
    }
    return total;
}
Teste antes de confiar: antes de usar o guloso, procure um contraexemplo pequeno. Se a força bruta e o guloso divergem em alguma entrada pequena, o guloso está errado.

Padrão 7 · Programação dinâmica

Quando um problema se decompõe em subproblemas que se repetem, resolva cada subproblema uma só vez e guarde o resultado. A tabela de resultados é a estrutura; a recorrência é o coração. O processo tem quatro passos: defina o estado (o que o subproblema representa), escreva a recorrência, defina os casos base e escolha a ordem de preenchimento. Versões de baixo para cima evitam a recursão e costumam usar menos memória.

Exemplo: escadas. Para chegar ao degrau n com passos de 1 ou 2, f(n) = f(n−1) + f(n−2). A versão recursiva pura custa O(2ⁿ); com a tabela, O(n); e, como só os dois últimos valores são usados, O(1) de espaço.

Em C · 11-padroes.c · pad:dinamica

static unsigned long long escadas(unsigned n) {      /* passos de 1 ou 2 */
    if (n <= 1) return 1;
    unsigned long long a = 1, b = 1;
    for (unsigned i = 2; i <= n; i++) {
        unsigned long long c = a + b;                 /* f(i) = f(i-1) + f(i-2) */
        a = b;
        b = c;
    }
    return b;
}

Exercícios resolvidos

Exercício 1: trio com soma zero

Enunciado. Existem três valores distintos de índices cuja soma é zero?

Passo 1 (força bruta): três laços, O(n³). Passo 2 (padrão): fixe o primeiro valor a[i] e resolva o problema de dois ponteiros para −a[i] no restante. Ordenar uma vez custa O(n log n), e para cada i, os dois ponteiros custam O(n).

Complexidade: O(n²) de tempo, dominado pelos dois ponteiros aninhados no fixo i.

Em C · 11-padroes.c · ex:tres-soma

static int tres_soma_zero(int a[], size_t n) {
    qsort(a, n, sizeof *a, cmp_int);                 /* ordena: O(n log n) */
    for (size_t i = 0; i + 2 < n; i++) {
        size_t lo = i + 1, hi = n - 1;
        while (lo < hi) {
            long s = (long)a[i] + a[lo] + a[hi];
            if (s == 0) return 1;
            if (s < 0) lo++;
            else hi--;
        }
    }
    return 0;                                         /* O(n²) no total */
}

Exercício 2: subvetor com soma alvo

Enunciado. Num vetor de inteiros positivos, encontre um trecho contínuo cuja soma é exatamente o alvo.

Passo 2: como os valores são positivos, a soma de uma janela cresce ao estender e diminui ao encolher. Isso permite uma janela de tamanho variável: a janela cresce à direita; enquanto a soma passa do alvo, encolhe pela esquerda. Ao igualar, temos a resposta.

Para {1, 2, 3, 7, 5} e alvo 12, a resposta é o trecho de índices 1 a 3 (2 + 3 + 7).

Complexidade: O(n), porque cada índice entra e sai da janela no máximo uma vez.

Em C · 11-padroes.c · ex:subarray

static int subarray_com_soma(const int a[], size_t n, long alvo, size_t *ini, size_t *fim) {
    /* valores positivos: a janela só cresce quando a soma é pequena */
    size_t l = 0;
    long s = 0;
    for (size_t r = 0; r < n; r++) {
        s += a[r];
        while (s > alvo && l <= r) {
            s -= a[l];
            l++;
        }
        if (s == alvo) {
            *ini = l;
            *fim = r;
            return 1;
        }
    }
    return 0;
}

Exercício 3: formas de formar um valor com moedas

Enunciado. De quantas formas diferentes é possível formar 10 com moedas de 1, 2 e 5? A ordem das moedas não importa.

Passo 1 e 4: a força bruta enumera combinações; o padrão é programação dinâmica. Seja dp[v] o número de formas de formar v. Para cada moeda m, todo v ≥ m ganha as formas que usam m: dp[v] += dp[v − m]. Processar moeda por moeda evita contar a mesma combinação em ordens diferentes.

Resultado: 10 formas. A tabela tem tamanho valor + 1.

Complexidade: O(valor · número de moedas) de tempo, O(valor) de espaço.

Em C · 11-padroes.c · ex:moedas

static unsigned long long formas_troco(unsigned valor) {
    unsigned long long *dp = calloc(valor + 1, sizeof *dp);
    if (dp == NULL) return 0;
    dp[0] = 1;
    const unsigned moedas[3] = {1, 2, 5};
    for (size_t m = 0; m < 3; m++)
        for (unsigned v = moedas[m]; v <= valor; v++)
            dp[v] += dp[v - moedas[m]];           /* as formas que usam a moeda m */
    unsigned long long r = dp[valor];
    free(dp);
    return r;
}

Como aplicar a problemas novos

Um exemplo de raciocínio completo, sem código, ajuda a fixar o roteiro. Problema: dada uma lista de intervalos de reunião, diga o número mínimo de salas necessárias.

  1. Entrada e saída: intervalos [início, fim); saída, um inteiro. Casos de borda: lista vazia (0 salas); intervalos que se tocam exatamente no fim (não se sobrepõem).
  2. Exemplo à mão: [0,30), [5,10), [15,20). O primeiro e o segundo se sobrepõem; o terceiro começa depois do segundo acabar, mas antes do primeiro terminar. Resposta: 2.
  3. Força bruta: para cada instante, conte os intervalos ativos; O(n²) ou pior.
  4. Padrão: os sinais são “intervalos” e “número mínimo de recursos”. Ordenar por início e manter um conjunto de salas ocupadas com fim mínimo: guloso com fila de prioridade (ou dois ponteiros sobre eventos de início e fim).
  5. Estrutura e custo: ordenar eventos O(n log n); varrer os eventos e contar a sobreposição máxima com dois ponteiros em O(n). Total O(n log n).
  6. Teste: confira com a força bruta em entradas pequenas aleatórias; teste também intervalos idênticos e encostados.

Exercícios propostos

P1. Dado um vetor de valores 0 e 1, encontre o maior trecho contínuo com a mesma quantidade de 0s e de 1s. Qual padrão usar?

Resposta: troque 0 por −1 e use somas de prefixos: um trecho [l, r] tem soma zero quando p[l] = p[r+1]. Guarde, num hash, a primeira posição de cada valor de prefixo; o maior trecho é o maior r − l com o mesmo prefixo. O(n) de tempo e espaço.

P2. Escreva o contraexemplo que mostra que o guloso não resolve a mochila 0/1, e diga qual padrão resolve.

Resposta: capacidade 50; itens (valor, peso): (60, 10), (100, 20), (120, 30). Ordenando por valor/peso, o guloso pega os dois primeiros (160 com peso 30), e o terceiro não cabe, somando 160 com 20 de folga. A solução ótima pega os dois últimos (220, peso 50). A programação dinâmica sobre a capacidade resolve em O(n · W).

Teste seus conhecimentos

Qual padrão é o mais indicado para o maior trecho contínuo com soma máxima de tamanho fixo k?

Correto. Cada janela muda por uma entrada e uma saída, então o total é O(n), contra O(n·k) da soma recalculada.

Por que um algoritmo guloso precisa de uma prova de corretude?

Correto. O guloso é rápido mas arriscado: funciona para certos problemas, como o troco com moedas canônicas, e falha em outros, como a mochila 0/1.

Qual é a principal ideia da programação dinâmica?

Correto. A tabela de resultados transforma uma recursão exponencial em uma varredura polinomial.

O que levar desta página

  • Siga o roteiro de seis passos: entenda, exemplifique à mão, faça a força bruta, identifique o padrão, otimize, teste.
  • Reconheça o padrão pelos sinais do enunciado, não pela solução que você já conhece.
  • Dois ponteiros e janelas transformam O(n²) em O(n) quando há ordem ou contiguidade.
  • Guloso exige prova; programação dinâmica exige um estado bem definido e uma recorrência correta.
  • Teste sempre contra a força bruta em entradas pequenas. É o único jeito seguro de confiar na otimização.
