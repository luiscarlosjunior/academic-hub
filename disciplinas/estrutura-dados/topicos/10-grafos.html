Tópico 10 · Grafos

Um grafo G = (V, E) é um conjunto de vértices ligados por arestas. Redes sociais, mapas, dependências entre módulos, a web e redes de comunicação são grafos. Quase todo problema de conexão ou de caminho vira uma pergunta sobre um grafo: é possível ir de A até B? qual o caminho mais curto? existe uma ordem válida para executar as tarefas?

Objetivos desta página. Ao final, você deve conseguir:

  • escolher entre lista e matriz de adjacências, com seus custos de espaço e consulta;
  • implementar BFS e DFS, e explicar por que a BFS dá distâncias mínimas em grafos sem peso;
  • usar travessias para contar componentes conexas e detectar ciclos;
  • implementar Dijkstra com arestas de peso não negativo e ordenação topológica para grafos dirigidos acíclicos.

Teoria: representar o grafo

A matriz de adjacências usa uma tabela V × V: consultar se u e v estão ligados é O(1), mas ocupa O(V²) de memória, mesmo que o grafo tenha poucas arestas. A lista de adjacências guarda, para cada vértice, a lista dos vizinhos: ocupa O(V + E) e percorrer os vizinhos de u custa O(grau de u). Em grafos esparsos, que são a regra em redes e mapas, a lista é a escolha natural.

Um grafo pode ser não dirigido (cada aresta vale nos dois sentidos) ou dirigido, e pode ter pesos. Um ciclo é um caminho que volta ao início. Um grafo dirigido sem ciclos é um DAG, e só DAGs admitem ordenação topológica.

Representação em C

Para manter os exemplos simples, a lista de adjacências usa vetores de tamanho fixo (MAXV). Em uma implementação de produção, cada vértice teria uma lista dinâmica. A ideia é a mesma. Repare que, em grafo não dirigido, cada aresta entra nas duas listas.

Em C · 10-grafos.c · op:lista-adjacencias

typedef struct {
    size_t V;                          /* número de vértices */
    int viz[MAXV][MAXV];               /* viz[u][k]: k-ésimo vizinho de u */
    int peso[MAXV][MAXV];              /* peso da aresta correspondente */
    size_t grau[MAXV];                 /* quantos vizinhos cada vértice tem */
} Grafo;

static void grafo_iniciar(Grafo *g, size_t V) {
    g->V = V;
    memset(g->grau, 0, sizeof g->grau);
}

static void grafo_aresta(Grafo *g, int u, int v, int w, int dirigido) {
    g->viz[u][g->grau[u]] = v;
    g->peso[u][g->grau[u]++] = w;
    if (!dirigido) {
        g->viz[v][g->grau[v]] = u;
        g->peso[v][g->grau[v]++] = w;
    }
}

Operação 1 · Busca em largura (BFS)

A BFS visita o grafo em camadas: primeiro os vizinhos da origem (distância 1), depois os vizinhos desses (distância 2), e assim por diante. Isso acontece porque a fila é FIFO: todo vértice de distância d entra antes dos de distância d + 1. Por isso, em grafo sem pesos, a primeira vez que um vértice é alcançado corresponde ao caminho mais curto (MOORE, 1959). O vetor dist marca a distância e serve também de “visitado”. Custo: O(V + E), porque cada vértice entra uma vez e cada aresta é examinada uma vez (ou duas, em não dirigido).

Em C · 10-grafos.c · op:bfs

static void bfs(const Grafo *g, int origem, int dist[]) {
    int fila[MAXV];
    size_t ini = 0, fim = 0;
    for (size_t i = 0; i < g->V; i++) dist[i] = -1;
    dist[origem] = 0;
    fila[fim++] = origem;
    while (ini < fim) {
        int u = fila[ini++];
        for (size_t k = 0; k < g->grau[u]; k++) {
            int v = g->viz[u][k];
            if (dist[v] < 0) {
                dist[v] = dist[u] + 1;
                fila[fim++] = v;
            }
        }
    }
}

Animação: BFS e DFS no mesmo grafo

Grafo com sete vértices, todos alcançáveis a partir de A. Verde = visitado; âmbar = vértice atual. A faixa de baixo mostra a estrutura auxiliar: fila na BFS, pilha na DFS.

A: B, C  |  B: A, D, E  |  C: A, F  |  D: B  |  E: B, G  |  F: C, G  |  G: E, F

Operação 2 · Busca em profundidade (DFS)

A DFS desce por um caminho até não poder mais e só então volta (backtrack). A versão recursiva usa a pilha de execução; a versão iterativa usa uma pilha explícita. Ambas são O(V + E). A DFS não dá distâncias mínimas, mas é a ferramenta certa para explorar, contar componentes, detectar ciclos e ordenar topologicamente.

Em C · 10-grafos.c · op:dfs

static void dfs_aux(const Grafo *g, int u, int vis[], int ordem[], size_t *n) {
    vis[u] = 1;
    ordem[(*n)++] = u;
    for (size_t k = 0; k < g->grau[u]; k++) {
        int v = g->viz[u][k];
        if (!vis[v]) dfs_aux(g, v, vis, ordem, n);
    }
}

static size_t dfs(const Grafo *g, int origem, int ordem[]) {
    int vis[MAXV] = {0};
    size_t n = 0;
    dfs_aux(g, origem, vis, ordem, &n);
    return n;
}

Operação 3 · Componentes conexas e ciclos

Uma componente conexa é um conjunto de vértices mutuamente alcançáveis. Para contá-las, percorremos os vértices; cada vez que encontramos um não visitado, iniciamos uma DFS e incrementamos o contador. Em um grafo não dirigido, há um ciclo se uma DFS encontra um vizinho já visitado que não é o pai do vértice atual: a aresta de volta fecha um caminho. Esse é o motivo de guardar o pai na chamada.

Em C · 10-grafos.c · op:componentes

static int componentes(const Grafo *g) {
    int vis[MAXV] = {0}, ordem[MAXV];
    int c = 0;
    for (size_t s = 0; s < g->V; s++)
        if (!vis[s]) {
            size_t n = 0;
            c++;
            dfs_aux(g, (int)s, vis, ordem, &n);
        }
    return c;
}

Em C · 10-grafos.c · op:ciclo

static int ciclo_aux(const Grafo *g, int u, int pai, int vis[]) {
    vis[u] = 1;
    for (size_t k = 0; k < g->grau[u]; k++) {
        int v = g->viz[u][k];
        if (!vis[v]) {
            if (ciclo_aux(g, v, u, vis)) return 1;
        } else if (v != pai) {
            return 1;                           /* aresta de retorno: há ciclo */
        }
    }
    return 0;
}

static int tem_ciclo(const Grafo *g) {          /* grafo não dirigido */
    int vis[MAXV] = {0};
    for (size_t s = 0; s < g->V; s++)
        if (!vis[s] && ciclo_aux(g, (int)s, -1, vis)) return 1;
    return 0;
}

Operação 4 · Caminho mínimo com pesos (Dijkstra)

Com pesos, a BFS não basta. O algoritmo de Dijkstra (DIJKSTRA, 1959) funciona com pesos não negativos e tem uma ideia gulosa e correta: o vértice não fechado mais próximo da origem já tem sua distância definitiva, porque qualquer outro caminho teria de passar por um vértice ainda mais distante, e pesos não negativos não permitem “encurtar” depois. A cada passo, fechamos o vértice e relaxamos suas arestas. Esta versão escolhe o mínimo por busca linear, O(V²). Com um heap binário, a escolha cai para O(log V) e o total para O((V + E) log V).

Atenção: pesos negativos quebram a correção. Para isso, use Bellman-Ford (cap. 24 de Cormen et al.).

Em C · 10-grafos.c · op:dijkstra

static void dijkstra(const Grafo *g, int origem, int dist[]) {
    int feito[MAXV] = {0};
    for (size_t i = 0; i < g->V; i++) dist[i] = INT_MAX;
    dist[origem] = 0;
    for (size_t it = 0; it < g->V; it++) {
        int u = -1;
        for (size_t v = 0; v < g->V; v++)       /* escolhe o não visitado mais perto */
            if (!feito[v] && dist[v] != INT_MAX && (u < 0 || dist[v] < dist[u]))
                u = (int)v;
        if (u < 0) break;
        feito[u] = 1;
        for (size_t k = 0; k < g->grau[u]; k++) {
            int v = g->viz[u][k], w = g->peso[u][k];
            if (dist[u] + w < dist[v]) dist[v] = dist[u] + w;
        }
    }
}

Animação: Dijkstra passo a passo

Grafo dirigido com seis arestas. Cada vértice mostra a distância conhecida (∞ = ainda desconhecida). Acompanhe quando uma rota mais longa é trocada por uma mais curta.

Operação 5 · Ordenação topológica

Em um DAG, uma ordenação topológica lista os vértices de modo que toda aresta u → v aparece com u antes de v. É o modelo de dependências: compilar módulos, instalar pacotes, executar tarefas. O algoritmo de Kahn começa pelos vértices sem dependências (grau de entrada zero) e vai removendo-os. Se, ao final, sobram vértices, há um ciclo: não existe ordem válida.

Em C · 10-grafos.c · ex:topologica

static int ordenacao_topologica(const Grafo *g, int ordem[]) {
    int entrada[MAXV] = {0}, fila[MAXV];
    size_t ini = 0, fim = 0, n = 0;
    for (size_t u = 0; u < g->V; u++)
        for (size_t k = 0; k < g->grau[u]; k++) entrada[g->viz[u][k]]++;
    for (size_t v = 0; v < g->V; v++)
        if (entrada[v] == 0) fila[fim++] = (int)v;
    while (ini < fim) {
        int u = fila[ini++];
        ordem[n++] = u;
        for (size_t k = 0; k < g->grau[u]; k++) {
            int v = g->viz[u][k];
            if (--entrada[v] == 0) fila[fim++] = v;
        }
    }
    return n == g->V;                 /* se faltou algum vértice, há ciclo */
}

Padrões de resolução com grafos

Modelar antes de programar

Grades, mapas, dependências e conflitos viram grafos. Defina o que é vértice, o que é aresta e o que a resposta mede.

BFS para o mínimo sem peso

Se todas as arestas custam o mesmo, BFS dá a resposta em O(V + E). Vale também para grades (exercício 1).

Grau de entrada

Contar as arestas que chegam a cada vértice permite processar dependências em ordem (exercício 2).

Visitado como estado

Marcar um vértice ao entrar na fila ou na pilha (não ao sair) evita processá-lo várias vezes e mantém O(V + E).

Exercícios resolvidos

Exercício 1: menor caminho em uma grade

Enunciado. Uma grade tem células livres (.) e obstáculos (#). Movimentos são nas quatro direções. Qual o menor número de passos de (0,0) até o canto oposto?

Modelagem. Cada célula livre é um vértice; cada movimento entre células livres vizinhas é uma aresta de peso 1. Como o peso é uniforme, BFS é suficiente. A fila guarda a célula, e dist marca a distância, que também faz o papel de visitado.

Complexidade: O(L · C) de tempo e espaço, já que cada célula entra uma vez.

Em C · 10-grafos.c · ex:grade

#define LIN 5
#define COL 6

static int caminho_grade(const char g[LIN][COL]) {
    int dist[LIN][COL];
    int fila[LIN * COL];
    size_t ini = 0, fim = 0;
    for (int i = 0; i < LIN; i++)
        for (int j = 0; j < COL; j++) dist[i][j] = -1;
    dist[0][0] = 0;
    fila[fim++] = 0;
    const int di[4] = {1, -1, 0, 0}, dj[4] = {0, 0, 1, -1};
    while (ini < fim) {
        int p = fila[ini++], i = p / COL, j = p % COL;
        for (int d = 0; d < 4; d++) {
            int ni = i + di[d], nj = j + dj[d];
            if (ni < 0 || nj < 0 || ni >= LIN || nj >= COL) continue;
            if (g[ni][nj] == '#' || dist[ni][nj] >= 0) continue;
            dist[ni][nj] = dist[i][j] + 1;
            fila[fim++] = ni * COL + nj;
        }
    }
    return dist[LIN - 1][COL - 1];
}

Exercício 2: ordenação topológica de tarefas

Enunciado. Quatro tarefas têm dependências: 0 antes de 1 e de 2; 1 e 2 antes de 3. Dê uma ordem válida, ou diga que não existe.

Ideia. Kahn: calcule o grau de entrada de cada tarefa, coloque na fila as que têm zero, e a cada retirada diminua o grau dos sucessores. Um sucessor entra na fila quando seu grau chega a zero. Se a ordem final tem menos vértices que o grafo, há ciclo.

Complexidade: O(V + E) de tempo e espaço.

Em C · 10-grafos.c · ex:topologica

static int ordenacao_topologica(const Grafo *g, int ordem[]) {
    int entrada[MAXV] = {0}, fila[MAXV];
    size_t ini = 0, fim = 0, n = 0;
    for (size_t u = 0; u < g->V; u++)
        for (size_t k = 0; k < g->grau[u]; k++) entrada[g->viz[u][k]]++;
    for (size_t v = 0; v < g->V; v++)
        if (entrada[v] == 0) fila[fim++] = (int)v;
    while (ini < fim) {
        int u = fila[ini++];
        ordem[n++] = u;
        for (size_t k = 0; k < g->grau[u]; k++) {
            int v = g->viz[u][k];
            if (--entrada[v] == 0) fila[fim++] = v;
        }
    }
    return n == g->V;                 /* se faltou algum vértice, há ciclo */
}

Exemplo A: Ciclo em grafo dirigido com três cores

Branco é não visitado, cinza está em exploração e preto está concluído. Uma aresta para um vértice cinza fecha um ciclo. 0→1→2→3 é acíclico; ao acrescentar 3→1, surge um ciclo.

Em C · 10-mais-exemplos.c · ex-a

static int ciclo_aux(const Grafo *g, int u, int cor[]) {
    cor[u] = 1;
    for (int k = 0; k < g->g[u]; k++) {
        int v = g->viz[u][k];
        if (cor[v] == 1) return 1;                   /* aresta para cinza: ciclo */
        if (cor[v] == 0 && ciclo_aux(g, v, cor)) return 1;
    }
    cor[u] = 2;
    return 0;
}

static int tem_ciclo(const Grafo *g) {
    int cor[V] = {0};
    for (int u = 0; u < g->n; u++)
        if (cor[u] == 0 && ciclo_aux(g, u, cor)) return 1;
    return 0;
}

Exemplo B: Componentes com union-find

Une vértices com compressão de caminho e conta as raízes. Com arestas 0-1, 1-2 e 3-4 em 5 vértices, há 2 componentes, sem percorrer o grafo.

Em C · 10-mais-exemplos.c · ex-b

static int pai[V];

static int achar(int x) {
    while (pai[x] != x) {
        pai[x] = pai[pai[x]];
        x = pai[x];
    }
    return x;
}

static void unir(int a, int b) {
    int ra = achar(a), rb = achar(b);
    if (ra != rb) pai[ra] = rb;
}

static int componentes_uf(int n, const int ar[][2], int m) {
    for (int i = 0; i < n; i++) pai[i] = i;
    for (int i = 0; i < m; i++) unir(ar[i][0], ar[i][1]);
    int c = 0;
    for (int i = 0; i < n; i++)
        if (achar(i) == i) c++;
    return c;
}

Exemplo C: Caminho reconstruído pela BFS

A BFS guarda o pai de cada vértice; seguindo os pais a partir do destino e invertendo a sequência, obtém-se o caminho. De 0 a 4 o caminho é 0 → 1 → 4.

Em C · 10-mais-exemplos.c · ex-c

static int caminho_bfs(const Grafo *g, int origem, int destino, int saida[], int *tam) {
    int pai_b[V], vis[V] = {0}, fila[V], ini = 0, fim = 0;
    for (int i = 0; i < V; i++) pai_b[i] = -1;
    fila[fim++] = origem;
    vis[origem] = 1;
    while (ini < fim) {
        int u = fila[ini++];
        for (int k = 0; k < g->g[u]; k++) {
            int v = g->viz[u][k];
            if (!vis[v]) {
                vis[v] = 1;
                pai_b[v] = u;
                fila[fim++] = v;
            }
        }
    }
    if (!vis[destino]) return 0;
    int tmp[V], t = 0;
    for (int x = destino; x != -1; x = pai_b[x]) tmp[t++] = x;
    for (int i = 0; i < t; i++) saida[i] = tmp[t - 1 - i];
    *tam = t;
    return 1;
}

Exemplo D: Vértice de maior grau de saída

Conta as arestas que saem de cada vértice; em caso de empate vale o menor índice. Aqui o resultado é o vértice 0.

Em C · 10-mais-exemplos.c · ex-d

static int maior_grau(const Grafo *g) {
    int melhor = 0;
    for (int u = 1; u < g->n; u++)
        if (g->g[u] > g->g[melhor]) melhor = u;
    return melhor;
}

Conceitos complementares e uso no dia a dia

Conceitos complementares

  • Árvore geradora mínima: Prim e Kruskal encontram o conjunto mais barato de arestas que conecta todos os vértices. Kruskal usa union-find, como no exemplo do tópico.
  • Busca A*: Dijkstra com uma heurística que estima a distância até o destino. É o padrão em jogos e navegação, ao custo de precisar de uma estimativa admissível.
  • Fluxo máximo: quanto de material pode passar de uma origem a um destino com capacidades nas arestas. Modela redes de distribuição e de transmissão.
  • Grafos com pesos negativos: Bellman-Ford resolve o caminho mínimo nesse caso, e detecta ciclos de peso negativo.

Onde isso aparece no dia a dia

  • GPS e rotas: mapas são grafos com pesos (tempo ou distância); apps de navegação calculam rotas com variações de Dijkstra e A*.
  • Redes sociais: "pessoas que você talvez conheça" são vértices a distância 2 no grafo de amizades, encontrados com BFS.
  • Gerenciadores de pacotes: npm, pip e apt resolvem dependências com ordenação topológica e detectam conflitos por ciclos.
  • Roteamento na internet: protocolos como OSPF calculam caminhos mais curtos entre roteadores com Dijkstra.
  • Pipelines de CI/CD: etapas de build e testes são um DAG; a ordem de execução é uma ordenação topológica, e etapas independentes rodam em paralelo.

Animação: ordenação topológica (Kahn)

Vértices sem dependências entram na fila. Ao removê-los, as dependências dos sucessores diminuem.

Animação: union-find com compressão de caminho

Union-find junta conjuntos e responde se dois vértices estão no mesmo conjunto, com quase custo constante.

Exercícios propostos

P1. Por que Dijkstra falha com pesos negativos? Dê um grafo pequeno em que a resposta está errada.

Resposta: um vértice dado como fechado pode ser alcançado depois por um caminho com peso negativo mais barato. Exemplo: A→B com peso 2, A→C com peso 1 e C→B com peso −3. Dijkstra fecha B com 2 antes de descobrir que o caminho por C custa −2.

P2. Como você detectaria um ciclo num grafo dirigido? A regra do pai ainda vale?

Resposta: não. Em dirigido, a regra do pai não basta. Use três cores: branco (não visitado), cinza (em exploração) e preto (concluído). Uma aresta para um vértice cinza indica ciclo. Alternativamente, use o Kahn: se ele não ordena tudo, há ciclo.

Teste seus conhecimentos

Qual estrutura auxiliar a BFS usa?

Correto. A fila (FIFO) garante a exploração em camadas.

Qual é a complexidade de BFS ou DFS com lista de adjacências?

Correto. Cada vértice entra uma vez e cada aresta é examinada uma ou duas vezes.

Em um grafo dirigido, o que indica a impossibilidade de uma ordenação topológica?

Correto. Com ciclo, algum vértice depende de si mesmo direta ou indiretamente, e não há ordem que satisfaça todas as dependências.

O que levar desta página

  • Lista de adjacências para grafos esparsos; matriz para consultas de aresta frequentes e grafos densos.
  • BFS (fila) dá distâncias mínimas sem peso; DFS (pilha ou recursão) explora e detecta ciclos.
  • Dijkstra dá o caminho mínimo com pesos não negativos, fechando um vértice por vez.
  • Kahn produz uma ordenação topológica e revela ciclos pela falta de vértices no resultado.
