Tópico 8 · Tabelas hash

Uma tabela hash associa chaves a valores com acesso médio O(1), independente do número de chaves. O segredo é uma função de espalhamento h(chave), que transforma a chave num índice de um vetor. Para achar uma chave, calculamos h e olhamos uma posição, sem varrer nada. É a estrutura por trás de dicionários, conjuntos, caches e tabelas de símbolos de compiladores.

Objetivos desta página. Ao final, você deve conseguir:

  • explicar o que é uma colisão e por que ela é inevitável;
  • implementar encadeamento e endereçamento aberto com sondagem linear, em C;
  • calcular o fator de carga e decidir quando redimensionar a tabela;
  • resolver problemas de contagem, de complementos e de identificação de duplicados com hash.

Teoria: espalhamento, colisões e fator de carga

Há mais chaves possíveis do que posições na tabela. Logo, duas chaves diferentes acabam no mesmo índice: isso é uma colisão, e é inevitável pelo princípio da casa dos pombos. O que se deseja é que as colisões sejam raras e bem distribuídas. Uma função boa espalha chaves parecidas em posições distantes; uma função ruim, como a soma simples dos caracteres, faz anagramas colidirem sempre.

O desempenho depende do fator de carga α = n / M, a razão entre elementos e posições. No encadeamento, a busca média custa O(1 + α). No endereçamento aberto, as sondagens crescem muito quando α se aproxima de 1, por causa dos aglomerados (clusters). Por isso, tabelas reais redimensionam antes de encher: a regra comum é dobrar a capacidade quando α passa de 0,75. Knuth (1998, v. 3, seção 6.4) analisa esses custos com precisão.

Operação 1 · Função de espalhamento para strings

O algoritmo djb2, de Daniel J. Bernstein, multiplica o acumulado por 33 e soma cada caractere. A multiplicação espalha os bits de forma que a ordem dos caracteres importa: "ab" e "ba" dão valores diferentes. A posição final é h(chave) mod M. Em C, o tamanho M deve ser, de preferência, primo ou uma potência de dois com cuidado, para que o módulo use bem os bits.

Em C · 08-tabelas-hash.c · op:hash-string

static unsigned long hash_str(const char *s) {        /* djb2 */
    unsigned long h = 5381;
    for (; *s; s++) h = h * 33 + (unsigned char)*s;
    return h;
}

Operação 2 · Encadeamento (chaining)

Cada balde é uma lista encadeada. Inserir calcula o balde, percorre a lista para atualizar a chave se ela já existe, e senão adiciona um nó no início. Buscar faz o mesmo percurso. Quando as colisões são poucas, cada operação é O(1); no pior caso, todas as chaves caem no mesmo balde e a tabela vira uma lista de n nós.

Em C · 08-tabelas-hash.c · op:encadeamento-inserir

static void enc_inserir(TabEnc *t, const char *chave, int valor) {
    size_t len = strlen(chave);
    if (len >= sizeof ((No *)0)->chave) return;
    size_t b = hash_str(chave) % t->m;
    for (No *p = t->baldes[b]; p; p = p->prox)
        if (strcmp(p->chave, chave) == 0) {    /* chave já existe: atualiza */
            p->valor = valor;
            return;
        }
    No *n = malloc(sizeof *n);
    if (n == NULL) return;
    memcpy(n->chave, chave, len + 1);
    n->valor = valor;
    n->prox = t->baldes[b];                    /* entra no início: O(1) */
    t->baldes[b] = n;
    t->n++;
}

Em C · 08-tabelas-hash.c · op:encadeamento-buscar

static int enc_buscar(const TabEnc *t, const char *chave, int *valor) {
    size_t b = hash_str(chave) % t->m;
    for (const No *p = t->baldes[b]; p; p = p->prox)
        if (strcmp(p->chave, chave) == 0) {
            *valor = p->valor;
            return 1;
        }
    return 0;
}

Operação 3 · Endereçamento aberto com sondagem linear

Em vez de listas, todas as chaves ficam dentro da própria tabela. Se a posição h(k) está ocupada, testamos a seguinte, e assim por diante, dando a volta. A busca segue a mesma sequência e para ao achar a chave ou uma posição vazia. Como não há ponteiros, a tabela é mais compacta e amigável ao cache, mas remover exige cuidado: é preciso marcar posições como “apagadas”, para não quebrar as sequências de sondagem. Aglomerados de posições ocupadas tornam as sondagens cada vez mais longas.

Em C · 08-tabelas-hash.c · op:sondagem-inserir

static int sondagem_inserir(TabAberta *t, int chave, int valor) {
    if (t->n == t->cap) return 0;                       /* cheia */
    size_t i = (size_t)chave % t->cap;
    while (t->chaves[i] != VAZIO && t->chaves[i] != chave)
        i = (i + 1) % t->cap;                           /* sondagem linear */
    if (t->chaves[i] == VAZIO) t->n++;
    t->chaves[i] = chave;
    t->vals[i] = valor;
    return 1;
}

Em C · 08-tabelas-hash.c · op:sondagem-buscar

static int sondagem_buscar(const TabAberta *t, int chave, int *valor) {
    size_t i = (size_t)chave % t->cap;
    for (size_t k = 0; k < t->cap; k++) {
        if (t->chaves[i] == VAZIO) return 0;            /* achou vazio: não está */
        if (t->chaves[i] == chave) {
            *valor = t->vals[i];
            return 1;
        }
        i = (i + 1) % t->cap;
    }
    return 0;
}

Operação 4 · Redimensionar (rehash)

Quando o fator de carga cresce demais, criamos uma tabela com o dobro da capacidade e reinserimos todas as chaves, porque h(k) mod M muda quando M muda. O custo da reconstrução é O(n), mas é raro: como a capacidade dobra, o custo é amortizado em O(1) por inserção, o mesmo princípio do vetor dinâmico (página 2).

Em C · 08-tabelas-hash.c · op:redimensionar

static int aberta_redimensionar(TabAberta *t) {
    TabAberta nova;
    if (!aberta_criar(&nova, t->cap * 2)) return 0;
    for (size_t i = 0; i < t->cap; i++)
        if (t->chaves[i] != VAZIO) sondagem_inserir(&nova, t->chaves[i], t->vals[i]);
    aberta_liberar(t);
    *t = nova;
    return 1;
}

Padrões de resolução com hash

Memorizar o que já vi

Ao percorrer uma sequência, guarde o que já passou no hash. Cada elemento pergunta “o complemento que preciso já apareceu?” em O(1) (exercício 1).

Contar frequências

Mapear chave → contagem resolve moda, duplicados, anagramas e agrupamentos (exercício 2).

Troca de tempo por espaço

Um hash usa O(n) de memória para transformar buscas O(n) em O(1). Vale quando as buscas se repetem.

Cuidado com o caso ruim

O O(1) é médio. Em entradas adversárias, com chaves escolhidas para colidir, o custo vira O(n). Sistemas expostos a entradas externas usam funções com semente aleatória.

Exercícios resolvidos

Exercício 1: dois somas

Enunciado. Dado um vetor de inteiros não negativos e um alvo, encontre dois índices distintos cujos valores somam o alvo.

Padrão: memorizar o que já vi. Para cada valor a[j], calculamos o complemento alvo − a[j]. Se ele já foi visto, a resposta é o par (índice guardado, j). Senão, guardamos a[j] com seu índice. A força bruta testaria os n² pares; o hash troca essa busca por uma consulta O(1).

Complexidade: O(n) médio, O(n) de espaço.

Em C · 08-tabelas-hash.c · ex:dois-somas

static int dois_somas(const int a[], size_t n, int alvo, size_t *i_out, size_t *j_out) {
    TabAberta t;
    if (!aberta_criar(&t, 2 * n + 1)) return 0;
    int achou = 0;
    for (size_t j = 0; j < n && !achou; j++) {
        int i = 0;
        int falta = alvo - a[j];                      /* o complemento que falta */
        if (falta >= 0 && sondagem_buscar(&t, falta, &i)) {
            *i_out = (size_t)i;
            *j_out = j;
            achou = 1;
        } else {
            sondagem_inserir(&t, a[j], (int)j);      /* guarda valor -> índice */
        }
    }
    aberta_liberar(&t);
    return achou;
}

Exercício 2: contagem de palavras

Enunciado. Conte quantas vezes cada palavra aparece numa lista.

Ideia. Mapeie palavra → contagem. Para cada palavra, leia a contagem atual (0 se não existe) e grave a contagem + 1. Com encadeamento, a tabela aceita chaves de tamanho variável. Esse é o núcleo de contadores de frequência, de palavras-chave e de histogramas.

Complexidade: O(n) médio sobre n palavras; O(k) de espaço para k palavras distintas.

Em C · 08-tabelas-hash.c · ex:frequencias

static void contar_palavras(TabEnc *t, const char *const palavras[], size_t n) {
    for (size_t i = 0; i < n; i++) {
        int c = 0;
        enc_buscar(t, palavras[i], &c);
        enc_inserir(t, palavras[i], c + 1);
    }
}

Exercícios propostos

P1. Dado um fluxo de números, descubra o primeiro que aparece uma única vez, com duas passagens e O(n) de espaço.

Resposta: primeira passagem conta as frequências no hash; segunda passagem, na ordem de chegada, devolve o primeiro com contagem 1. Como o fluxo é lido de novo, o fluxo precisa estar guardado ou ser reproduzível.

P2. Por que chaves como ponteiros, usadas em tabelas hash, costumam usar o endereço como hash?

Resposta: o endereço é único enquanto o objeto existe, então dispensa comparação de conteúdo. Mas os bits baixos do endereço costumam ser alinhados (múltiplos de 8 ou 16); é preciso misturá-los antes do módulo para não concentrar colisões.

Teste seus conhecimentos

O que é uma colisão em uma tabela hash?

Correto. Como há mais chaves possíveis que posições, colisões são inevitáveis; o encadeamento e a sondagem as resolvem.

Por que a sondagem linear precisa de cuidado especial para remover elementos?

Correto. Uma posição vazia encerra a busca. Se uma chave saiu no meio de uma sequência, outra chave pode parecer ausente. Usa-se uma marca de “apagado”.

Por que o redimensionamento é O(1) amortizado por inserção?

Correto. É o mesmo argumento do vetor dinâmico: n inserções custam O(n) no total, incluindo as reconstruções.

O que levar desta página

  • Hash transforma chave em índice; a busca média é O(1), mas o pior caso é O(n).
  • Colisões são inevitáveis: resolva com encadeamento (listas) ou sondagem (posições dentro da tabela).
  • O fator de carga controla o desempenho; redimensione antes de encher.
  • Memorizar o que já passou e contar frequências são os dois padrões mais úteis.
