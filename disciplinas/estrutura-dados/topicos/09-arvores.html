Tópico 9 · Árvores binárias de busca

Uma árvore organiza dados de forma hierárquica: uma raiz e subárvores. Uma árvore binária de busca (BST) acrescenta uma regra: valores menores ficam à esquerda de cada nó, e maiores à direita. Essa regra torna a busca uma descida, em que cada comparação descarta uma subárvore inteira, como na busca binária. A árvore combina a flexibilidade de uma estrutura ligada com a ordem de um vetor ordenado.

Objetivos desta página. Ao final, você deve conseguir:

  • definir raiz, folha, altura e a propriedade de ordem de uma BST;
  • implementar inserção, busca, mínimo e remoção (com sucessor) em C;
  • gerar os percursos pré-ordem, em-ordem, pós-ordem e por níveis, e saber quando usar cada um;
  • resolver problemas de validação, ancestral comum e estatística de ordem.

Teoria: altura, equilíbrio e custo

Todas as operações da BST custam O(h), onde h é a altura: o número de arestas do caminho mais longo da raiz a uma folha. O valor de h depende da ordem de inserção. Com valores aleatórios, a altura média é O(log n). Com valores já ordenados, cada novo nó vira filho direito do anterior, a árvore degenera em uma lista e h = n − 1. O custo passa de O(log n) para O(n), e é por isso que árvores práticas se reequilibram sozinhas: AVL (ADELSON-VEL'SKII; LANDIS, 1962) e rubro-negras (GUIBAS; SEDGEWICK, 1978) garantem h = O(log n).

Os percursos definem a ordem de visita: pré-ordem (raiz, esquerda, direita) serve para copiar ou serializar a árvore; em-ordem (esquerda, raiz, direita) devolve os valores ordenados numa BST; pós-ordem (esquerda, direita, raiz) serve para liberar memória ou calcular propriedades que dependem dos filhos; por níveis usa uma fila e visita da raiz para as folhas, nível a nível.

Operação 1 · Inserir e buscar

Inserir desce a partir da raiz, escolhendo a subárvore pela comparação, até achar uma posição livre. Buscar faz a mesma descida, mas para ao achar o valor ou ao chegar em nulo. A versão recursiva de inserção devolve o nó atual, o que permite ligar o novo nó ao pai de forma simples. A animação mostra o caminho percorrido em cada inserção.

Em C · 09-arvores.c · op:inserir

static No *inserir(No *r, int v) {
    if (r == NULL) return no_criar(v);
    if (v < r->v) r->esq = inserir(r->esq, v);
    else if (v > r->v) r->dir = inserir(r->dir, v);
    return r;                                  /* repetido: ignora */
}

Em C · 09-arvores.c · op:buscar

static const No *buscar(const No *r, int v) {
    while (r != NULL && r->v != v)             /* O(h) */
        r = (v < r->v) ? r->esq : r->dir;
    return r;
}

Operação 2 · Mínimo e remoção

O mínimo é o nó mais à esquerda. A remoção tem três casos. Se o nó é uma folha ou tem um só filho, ele é substituído pelo filho. Se tem dois filhos, a BST precisa continuar ordenada: substituímos o valor pelo sucessor em-ordem, que é o mínimo da subárvore direita, e removemos esse sucessor de lá, o que é mais simples porque ele tem no máximo um filho. É o caso mais difícil e o mais comum de errar.

Em C · 09-arvores.c · op:minimo

static const No *minimo(const No *r) {
    if (r == NULL) return NULL;
    while (r->esq != NULL) r = r->esq;
    return r;
}

Em C · 09-arvores.c · op:remover

static No *remover(No *r, int v) {
    if (r == NULL) return NULL;
    if (v < r->v) {
        r->esq = remover(r->esq, v);
    } else if (v > r->v) {
        r->dir = remover(r->dir, v);
    } else if (r->esq == NULL) {               /* sem filho à esquerda */
        No *d = r->dir;
        free(r);
        return d;
    } else if (r->dir == NULL) {               /* sem filho à direita */
        No *e = r->esq;
        free(r);
        return e;
    } else {                                   /* dois filhos: sucessor em-ordem */
        const No *s = minimo(r->dir);
        r->v = s->v;
        r->dir = remover(r->dir, s->v);
    }
    return r;
}

Operação 3 · Percursos

Os três percursos recursivos diferem só na posição em que o nó é visitado. A animação abaixo mostra cada um na mesma árvore. Os níveis usam uma fila, o que ilustra a relação entre árvores e a busca em largura da página de grafos.

Em C · 09-arvores.c · op:percursos

static void pre_ordem(const No *r) {
    if (r == NULL) return;
    printf("%d ", r->v);
    pre_ordem(r->esq);
    pre_ordem(r->dir);
}

static void em_ordem(const No *r) {
    if (r == NULL) return;
    em_ordem(r->esq);
    printf("%d ", r->v);
    em_ordem(r->dir);
}

static void pos_ordem(const No *r) {
    if (r == NULL) return;
    pos_ordem(r->esq);
    pos_ordem(r->dir);
    printf("%d ", r->v);
}

/* Por níveis: usa uma fila (array circular de ponteiros) */
static void por_niveis(const No *raiz) {
    const No *fila[64];
    size_t ini = 0, fim = 0;
    if (raiz == NULL) return;
    fila[fim++] = raiz;
    while (ini < fim) {
        const No *r = fila[ini++];
        printf("%d ", r->v);
        if (r->esq) fila[fim++] = r->esq;
        if (r->dir) fila[fim++] = r->dir;
    }
}

Operação 4 · Altura

A altura é calculada por recursão: a altura de um nó é 1 mais a maior das alturas dos filhos, e a de nulo é −1 (contando arestas). Visita cada nó uma vez: O(n) de tempo, e O(h) de pilha.

Em C · 09-arvores.c · op:altura

static int altura(const No *r) {          /* número de arestas no caminho mais longo */
    if (r == NULL) return -1;
    int e = altura(r->esq), d = altura(r->dir);
    return 1 + (e > d ? e : d);
}

Padrões de resolução com árvores

Recursão pela estrutura

Para qualquer propriedade de árvore, resolva para a raiz assumindo que as subárvores já estão resolvidas. Altura, validação e contagem seguem esse padrão.

Limites que se propagam

Para validar a BST, cada subárvore recebe um intervalo (min, max) que se estreita ao descer (exercício 1).

Descida guiada

Na BST, a comparação com a raiz diz de que lado está o alvo. Ancestral comum e buscas usam só um caminho (exercício 2).

Contar durante o percurso

Em-ordem visita os valores em ordem; um contador durante a visita responde a perguntas de posição, como o k-ésimo menor (exercício 3).

Exercícios resolvidos

Exercício 1: verificar se uma árvore é uma BST

Enunciado. Dada uma árvore binária, diga se ela satisfaz a propriedade de BST. Cuidado: não basta comparar cada nó com seus filhos.

Armadilha: uma árvore pode ter cada filho corretamente posicionado em relação ao pai e ainda violar a regra, porque um nó da subárvore esquerda pode ser maior que a raiz. A regra vale para toda a subárvore.

Padrão: limites que se propagam. Cada nó deve estar estritamente entre um mínimo e um máximo. Ao descer à esquerda, o máximo passa a ser o valor do pai; ao descer à direita, o mínimo passa a ser o pai. Usamos LONG_MIN e LONG_MAX para a raiz.

Complexidade: O(n) de tempo, O(h) de pilha.

Em C · 09-arvores.c · ex:e-bst

static int e_bst(const No *r, long min, long max) {
    if (r == NULL) return 1;
    if (r->v <= min || r->v >= max) return 0;
    return e_bst(r->esq, min, r->v) && e_bst(r->dir, r->v, max);
}

Exercício 2: ancestral comum mais próximo

Enunciado. Em uma BST, encontre o ancestral comum mais próximo de dois valores, que existem na árvore.

Ideia. Desça a partir da raiz. Se os dois valores são menores que o nó, o ancestral comum está à esquerda; se são maiores, à direita. Quando os caminhos se separam (um valor é menor ou igual, e o outro maior ou igual), o nó atual é o ancestral comum. A BST torna isso uma descida simples, sem visitar a árvore inteira.

Em {50, 30, 70, 20, 40, 60, 80, 35}: o ancestral de 20 e 35 é 30, e o de 60 e 80 é 70.

Complexidade: O(h) de tempo, O(1) de espaço.

Em C · 09-arvores.c · ex:ancestral

static const No *ancestral_comum(const No *r, int a, int b) {
    while (r != NULL) {
        if (a < r->v && b < r->v) r = r->esq;      /* os dois estão à esquerda */
        else if (a > r->v && b > r->v) r = r->dir; /* os dois estão à direita */
        else return r;                             /* o nó separa a e b */
    }
    return NULL;
}

Exercício 3: o k-ésimo menor

Enunciado. Encontre o k-ésimo menor valor de uma BST.

Ideia. O percurso em-ordem visita os valores em ordem crescente. Um contador, incrementado a cada visita, diz qual posição estamos vendo: quando chega a k, paramos e devolvemos o nó. Para não percorrer tudo depois de achar, a recursão propaga o nó encontrado.

Para a árvore da aula, o terceiro menor é 35.

Complexidade: O(k + h) de tempo no caso típico; O(n) no pior caso.

Em C · 09-arvores.c · ex:kesimo

static const No *kesimo_aux(const No *r, int k, int *cont) {
    if (r == NULL) return NULL;
    const No *e = kesimo_aux(r->esq, k, cont);
    if (e != NULL) return e;
    if (++(*cont) == k) return r;
    return kesimo_aux(r->dir, k, cont);
}

static const No *kesimo_menor(const No *r, int k) {
    int cont = 0;
    return kesimo_aux(r, k, &cont);
}

Exercícios propostos

P1. Escreva a versão iterativa da inserção em BST. Qual é a vantagem em relação à recursiva?

Resposta: use um ponteiro para ponteiro (No **) que aponta para o campo onde o novo nó deve ser ligado. A vantagem é espaço O(1) de pilha, o que evita estouro em árvores degeneradas profundas.

P2. Uma árvore tem n nós e altura h. Quantos nós, no mínimo, ela pode ter? E no máximo?

Resposta: no mínimo h + 1 nós (um caminho). No máximo 2^(h+1) − 1 nós (árvore cheia). Por isso, uma árvore binária cheia com n nós tem altura ⌊log₂ n⌋, o que explica o O(log n) das árvores balanceadas.

Teste seus conhecimentos

Qual percurso devolve os valores de uma BST em ordem crescente?

Correto. Em-ordem visita a subárvore esquerda (menores), a raiz e a direita (maiores).

Ao remover um nó com dois filhos, qual valor pode substituí-lo para manter a propriedade de BST?

Correto. O sucessor é maior que tudo à esquerda e menor que o resto à direita. Também serve o predecessor (o máximo da esquerda), mas o sucessor é o padrão do exemplo.

Qual o custo de buscar um valor numa BST degenerada, com n nós em linha?

Correto. A altura é n − 1, e a busca desce por todos os níveis. É a mesma situação de uma lista encadeada.

O que levar desta página

  • Em BST, todas as operações custam O(h): balanceada é O(log n), degenerada é O(n).
  • Remover com dois filhos troca o valor pelo sucessor em-ordem.
  • Em-ordem devolve valores ordenados; pré-ordem e pós-ordem servem a outras tarefas.
  • Propriedades de árvore se resolvem recursivamente, com limites ou contadores propagados.
