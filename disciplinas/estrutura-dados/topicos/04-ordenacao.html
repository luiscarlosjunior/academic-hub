Tópico 4 · Algoritmos de ordenação

Ordenar é reorganizar uma sequência para que a[0] ≤ a[1] ≤ … ≤ a[n−1]. É um problema central: sem ordem, busca binária, detecção de duplicados, junção de dados e quase todo relatório ficam caros. Por isso, ordenação é o terreno onde se aprendem as ideias de projeto de algoritmos: invariantes, divisão e conquista, partição e análise de pior caso.

Objetivos desta página. Ao final, você deve conseguir:

  • explicar, para cada algoritmo, o invariante que vale ao fim de cada passo;
  • calcular os custos de melhor, médio e pior caso, e o espaço auxiliar;
  • implementar bolha, seleção, inserção, quicksort, merge sort e contagem em C;
  • escolher um algoritmo considerando estabilidade, memória e distribuição dos dados.

Teoria: invariantes e critérios de escolha

Quase todo algoritmo de ordenação mantém um invariante: uma região do vetor já está correta, e a cada passo essa região cresce. Entender o invariante é entender o algoritmo. Na seleção, o prefixo a[0..i−1] contém os menores valores, já na posição final. Na inserção, o prefixo está ordenado, mas ainda não é o resultado final. Na bolha, o sufixo já contém os maiores.

Três critérios separam os algoritmos na prática. Estabilidade: elementos iguais mantêm a ordem relativa, o que importa ao ordenar por mais de uma chave. Espaço: in place usa O(1) ou O(log n) extra. Adaptatividade: o algoritmo fica rápido quando o vetor já está quase ordenado. Knuth (1998, v. 3) classifica os métodos com essa visão.

Algoritmo 1 · Bolha (bubble sort)

Percorre o vetor comparando vizinhos e troca os que estão fora de ordem. Ao fim da primeira passagem, o maior valor está na última posição, como uma bolha que sobe. A passagem p percorre n − 1 − p pares, e a soma dá n(n−1)/2 comparações: O(n²). A flag trocou permite parar cedo quando o vetor já está ordenado, o que dá O(n) no melhor caso.

Em C · 04-ordenacao.c · op:bolha

static void bolha(int a[], size_t n) {
    for (size_t p = 0; p + 1 < n; p++) {
        int trocou = 0;
        for (size_t j = 0; j + 1 < n - p; j++)
            if (a[j] > a[j + 1]) {
                trocar(&a[j], &a[j + 1]);
                trocou = 1;
            }
        if (!trocou) break;                 /* já ordenado: parada antecipada */
    }
}

Algoritmo 2 · Seleção

Em cada passagem, encontra o menor valor da parte não ordenada e o troca com a primeira posição dela. O custo é sempre n(n−1)/2 comparações, mesmo com o vetor já ordenado, porque o algoritmo não tem como saber disso sem olhar. Faz poucas trocas (no máximo n − 1), o que pode importar quando escrever é caro. A troca não preserva estabilidade: um valor pode passar por cima de um igual.

Em C · 04-ordenacao.c · op:selecao

static void selecao(int a[], size_t n) {
    for (size_t i = 0; i + 1 < n; i++) {
        size_t menor = i;
        for (size_t j = i + 1; j < n; j++)
            if (a[j] < a[menor]) menor = j;
        trocar(&a[i], &a[menor]);
    }
}

Algoritmo 3 · Inserção

É como organizar cartas na mão: pegamos a próxima e a encaixamos no lugar certo entre as já ordenadas, deslocando as maiores. No pior caso (ordem inversa), cada elemento atravessa toda a parte ordenada: O(n²). No melhor caso (já ordenado), cada elemento faz uma comparação: O(n). Por isso, a inserção é o algoritmo preferido para vetores pequenos ou quase ordenados, e é usada dentro de algoritmos mais rápidos, como o timsort, para blocos pequenos.

Em C · 04-ordenacao.c · op:insercao

static void insercao(int a[], size_t n) {
    for (size_t i = 1; i < n; i++) {
        int chave = a[i];
        size_t j = i;
        while (j > 0 && a[j - 1] > chave) {
            a[j] = a[j - 1];
            j--;
        }
        a[j] = chave;
    }
}

Algoritmo 4 · Quicksort

Escolhe um pivô, particiona o vetor em menores e maiores e aplica o mesmo processo a cada lado. A partição de Lomuto usada aqui coloca o pivô na posição definitiva. Se o pivô divide bem, a recursão tem altura O(log n) e cada nível custa O(n): total O(n log n). Se o pivô é sempre o extremo, a altura vira n e o total sobe para O(n²). Em média, com pivô escolhido ao acaso, o resultado é O(n log n) (HOARE, 1962). A animação mostra as partições.

Em C · 04-ordenacao.c · op:quicksort

static void quicksort(int a[], long lo, long hi) {
    if (lo >= hi) return;
    int pivo = a[hi];
    long i = lo;
    for (long j = lo; j < hi; j++)
        if (a[j] < pivo) {
            trocar(&a[i], &a[j]);
            i++;
        }
    trocar(&a[i], &a[hi]);
    quicksort(a, lo, i - 1);
    quicksort(a, i + 1, hi);
}

Por que o quicksort é tão usado na prática

O quicksort tem pior caso O(n²), mas quase nunca o atinge na prática. Três fatores explicam por que ele é um dos algoritmos mais usados do mundo: ele ordena in place (espaço extra O(log n) só na pilha de recursão), tem um laço interno muito simples e usa bem o cache, porque varre blocos contíguos de memória.

O pior caso depende do pivô. Se o pivô sempre cair no extremo, a recursão fica profunda e o custo vira O(n²). Por isso as implementações reais escolhem o pivô com cuidado:

  • Pivô aleatório: torna o pior caso improvável para qualquer entrada, inclusive as adversárias.
  • Mediana de três: compara o primeiro, o do meio e o último, e usa a mediana. Acerta muito bem vetores quase ordenados, que são comuns no dia a dia.
  • Corte para inserção: subvetores com menos de cerca de 10 elementos são ordenados por inserção, que tem constante muito baixa. O exemplo híbrido da seção de exemplos avançados faz isso.
  • Introsort: começa com quicksort e muda para heapsort se a profundidade passar de 2 log n. Garante O(n log n) no pior caso e é o padrão da biblioteca C++ (MUSSER, 1997).

Resumo: o quicksort vence na prática por ser in place e cache-friendly, enquanto o merge sort vence em garantia de tempo e em estabilidade. A escolha depende do que você mais precisa.

Algoritmo 5 · Merge sort

Divide o vetor ao meio, ordena as duas metades recursivamente e intercala as duas. A recorrência T(n) = 2T(n/2) + O(n) tem solução O(n log n) em todos os casos, sem exceção (CORMEN et al., 2022, cap. 2). O custo é espaço auxiliar O(n) e a intercalação é estável, desde que, em empate, o elemento da esquerda seja copiado primeiro. Este é o padrão divisão e conquista que aparece na página 11 e nos exercícios de inversões.

Em C · 04-ordenacao.c · op:mergesort

static void intercalar(int a[], int aux[], size_t lo, size_t mid, size_t hi) {
    size_t i = lo, j = mid, k = lo;
    while (i < mid && j < hi) aux[k++] = (a[i] <= a[j]) ? a[i++] : a[j++];
    while (i < mid) aux[k++] = a[i++];
    while (j < hi) aux[k++] = a[j++];
    memcpy(&a[lo], &aux[lo], (hi - lo) * sizeof *a);
}

static void merge_rec(int a[], int aux[], size_t lo, size_t hi) {
    if (hi - lo < 2) return;
    size_t mid = lo + (hi - lo) / 2;
    merge_rec(a, aux, lo, mid);
    merge_rec(a, aux, mid, hi);
    intercalar(a, aux, lo, mid, hi);
}

static int merge_sort(int a[], size_t n) {
    if (n < 2) return 1;
    int *aux = malloc(n * sizeof *aux);      /* O(n) de memória auxiliar */
    if (aux == NULL) return 0;
    merge_rec(a, aux, 0, n);
    free(aux);
    return 1;
}

Merge sort em detalhe: a intercalação passo a passo

O merge sort é o exemplo mais limpo de divisão e conquista, o padrão em que um problema é partido em subproblemas independentes, resolvidos e depois combinados. Aqui o trabalho pesado não está em dividir (isso é trivial, basta calcular o meio), mas em combinar: a intercalação de duas metades já ordenadas.

A intercalação é linear porque nunca volta atrás. Os ponteiros i (metade esquerda) e j (metade direita) começam no início de cada metade. Em cada passo, comparam-se a[i] e a[j]; o menor é copiado para a área auxiliar e o seu ponteiro avança. Como cada elemento é copiado uma vez por nível, a intercalação custa O(n) de trabalho.

Por que a área aux? Porque, ao escrever o resultado, sobrescreveríamos valores de a que ainda não foram lidos. Essa é uma troca consciente: o merge sort gasta O(n) de memória extra para garantir O(n log n) no pior caso.

A estabilidade vem de um detalhe: em empate (a[i] == a[j]), tiramos primeiro da metade da esquerda. Assim, elementos iguais mantêm a ordem em que apareceram originalmente, o que importa quando ordenamos por mais de uma chave.

A animação segue o algoritmo da linguagem C da seção anterior. O retângulo azul claro é o trecho que está sendo intercalado; as caixas de baixo são a área auxiliar aux. O contador conta as comparações.

Por que O(n log n)? A árvore de recursão

Desenhe as chamadas como uma árvore. O vetor de tamanho n se divide em dois de tamanho n/2, depois em quatro de n/4, e assim por diante, até tamanho 1. Há log₂ n níveis. Em cada nível, os subvetores somam n elementos, e a intercalação de cada um é proporcional ao seu tamanho. Logo, cada nível custa O(n) e o total é O(n · log n). É a aplicação direta do Teorema Mestre à recorrência T(n) = 2T(n/2) + n (CORMEN et al., 2022, cap. 4).

Onde o merge sort aparece de verdade

  • Python usa o timsort, um merge sort adaptativo que detecta trechos já ordenados. A função sorted() é timsort.
  • Java usa timsort para ordenar objetos em Collections.sort() e Arrays.sort() de objetos, porque ele é estável.
  • Listas encadeadas: não há acesso por índice, mas a intercalação só precisa avançar ponteiros. Aqui o merge sort é ideal e não precisa de área auxiliar grande.
  • Bancos de dados: o sort-merge join ordena duas tabelas pela chave de junção e as intercala, e a ordenação externa usa o mesmo princípio quando a tabela não cabe na memória.

Algoritmo 6 · Ordenação por contagem

Não compara elementos. Conta quantas vezes cada valor aparece e reescreve o vetor em ordem. Custa O(n + k), com k o intervalo de valores, e por isso só serve para inteiros em faixa pequena. Ele quebra a barreira de Ω(n log n) das ordenações por comparação, porque usa informação sobre os valores, não só a ordem entre eles.

Em C · 04-ordenacao.c · op:contagem

static void contagem(int a[], size_t n, int k) {   /* valores em 0..k-1 */
    size_t *freq = calloc((size_t)k, sizeof *freq);
    if (freq == NULL) return;
    for (size_t i = 0; i < n; i++) freq[a[i]]++;
    size_t pos = 0;
    for (int v = 0; v < k; v++)
        for (size_t c = 0; c < freq[v]; c++) a[pos++] = v;
    free(freq);
}

    for (size_t p = 0; p + 1 < n; p++) {
        int trocou = 0;
        for (size_t j = 0; j + 1 < n - p; j++)
            if (a[j] > a[j + 1]) {
                trocar(&a[j], &a[j + 1]);
                trocou = 1;
            }
        if (!trocou) break;                 /* já ordenado: parada antecipada */
    }
}

static void selecao(int a[], size_t n) {
    for (size_t i = 0; i + 1 < n; i++) {
        size_t menor = i;
        for (size_t j = i + 1; j < n; j++)
            if (a[j] < a[menor]) menor = j;
        trocar(&a[i], &a[menor]);
    }
}

static void insercao(int a[], size_t n) {
    for (size_t i = 1; i < n; i++) {
        int chave = a[i];
        size_t j = i;
        while (j > 0 && a[j - 1] > chave) {
            a[j] = a[j - 1];
            j--;
        }
        a[j] = chave;
    }
}

static void quicksort(int a[], long lo, long hi) {
    if (lo >= hi) return;
    int pivo = a[hi];
    long i = lo;
    for (long j = lo; j < hi; j++)
        if (a[j] < pivo) {
            trocar(&a[i], &a[j]);
            i++;
        }
    trocar(&a[i], &a[hi]);
    quicksort(a, lo, i - 1);
    quicksort(a, i + 1, hi);
}

static void intercalar(int a[], int aux[], size_t lo, size_t mid, size_t hi) {
    size_t i = lo, j = mid, k = lo;
    while (i < mid && j < hi) aux[k++] = (a[i] <= a[j]) ? a[i++] : a[j++];
    while (i < mid) aux[k++] = a[i++];
    while (j < hi) aux[k++] = a[j++];
    memcpy(&a[lo], &aux[lo], (hi - lo) * sizeof *a);
}

static void merge_rec(int a[], int aux[], size_t lo, size_t hi) {
    if (hi - lo < 2) return;
    size_t mid = lo + (hi - lo) / 2;
    merge_rec(a, aux, lo, mid);
    merge_rec(a, aux, mid, hi);
    intercalar(a, aux, lo, mid, hi);
}

static int merge_sort(int a[], size_t n) {
    if (n < 2) return 1;
    int *aux = malloc(n * sizeof *aux);      /* O(n) de memória auxiliar */
    if (aux == NULL) return 0;
    merge_rec(a, aux, 0, n);
    free(aux);
    return 1;
}

static void contagem(int a[], size_t n, int k) {   /* valores em 0..k-1 */
    size_t *freq = calloc((size_t)k, sizeof *freq);
    if (freq == NULL) return;
    for (size_t i = 0; i < n; i++) freq[a[i]]++;
    size_t pos = 0;
    for (int v = 0; v < k; v++)
        for (size_t c = 0; c < freq[v]; c++) a[pos++] = v;
    free(freq);
}

static int ordenado(const int a[], size_t n) {
    for (size_t i = 1; i < n; i++)
        if (a[i - 1] > a[i]) return 0;
    return 1;
}

static void imprimir(const char *rotulo, const int a[], size_t n) {
    printf("%-12s", rotulo);
    for (size_t i = 0; i < n; i++) printf(" %d", a[i]);
    printf("  [%s]\n", ordenado(a, n) ? "ok" : "ERRO");
}

static long contar_inv(int a[], int aux[], size_t lo, size_t hi) {
    if (hi - lo < 2) return 0;

    size_t i = lo, j = mid, k = lo;

        if (a[i] <= a[j]) {
            aux[k++] = a[i++];

    return c;
}

Padrões de resolução ligados à ordenação

Ordenar para simplificar

Ordenar custa O(n log n) e pode tornar um problema quadrático em O(n log n) ou O(n) (exercícios 1 e 3, e página 11).

Divisão e conquista

Dividir, resolver as metades e combinar. Merge sort combina por intercalação; a contagem de inversões combina contando cruzamentos.

Partição

Separar por um critério em O(n) e então agir sobre cada lado. Base do quicksort e da seleção do k-ésimo menor.

Ordenar por chave composta

Para ordenar por nome e depois por idade, use um algoritmo estável: ordene primeiro pela chave secundária e depois pela principal.

Exercícios resolvidos

Exercício 1: anagramas

Enunciado. Dois textos são anagramas se um é reordenação das letras do outro. Verifique se dois textos são anagramas.

Ideia. Se ordenarmos as letras dos dois textos, anagramas produzem sequências idênticas. A comparação final é linear. Para textos curtos, a inserção é suficiente. Um caminho alternativo, com contagem de letras, leva a O(n + 256) e é o que se usa em produção.

Complexidade: O(n²) com inserção (dominado pelas duas ordenações curtas); O(n) com contagem.

Exercício 2: contar inversões

Enunciado. Uma inversão é um par de índices i < j com a[i] > a[j]. Conte as inversões de um vetor em O(n log n).

Padrão: divisão e conquista, reaproveitando o merge sort. Inversões dentro de cada metade são contadas pela recursão. Inversões entre as metades aparecem na intercalação: quando a[j] (da direita) é menor que a[i] (da esquerda), ele forma uma inversão com todos os elementos restantes da metade esquerda, que são mid − i.

Exemplo: em {2, 4, 1, 3, 5}, as inversões são (2,1), (4,1) e (4,3): total 3.

Complexidade: O(n log n) de tempo, O(n) de espaço auxiliar.

Exercício 3: k-ésimo menor elemento

Enunciado. Encontre o k-ésimo menor valor (começando em zero) sem ordenar o vetor inteiro.

Ideia. Quickselect: particione em torno de um pivô. Se o pivô caiu exatamente na posição k, ele é a resposta. Se k está à esquerda, ignoramos a direita, e vice-versa. Cada passo descarta uma parte, então, em média, o custo é a soma n + n/2 + n/4 + … = O(n). No pior caso, como no quicksort, é O(n²).

Complexidade: O(n) médio, O(n²) pior caso, O(1) de espaço.

Em C · 04-ordenacao.c · ex:kesimo

static int kesimo(int a[], size_t n, size_t k) {  /* k começa em 0 */

                i++;

        trocar(&a[i], &a[hi]);
        if (k == i) return a[i];
        if (k < i) hi = i - 1;
        else lo = i + 1;

}

Exemplo B: Maior lacuna entre vizinhos

Depois de ordenar, a maior diferença entre elementos consecutivos é a resposta. O custo é O(n log n), dominado pela ordenação.

Em C · 04-mais-exemplos.c · ex-b

static int cmp_int(const void *x, const void *y) {
    int a = *(const int *)x, b = *(const int *)y;
    return (a > b) - (a < b);
}

static int maior_lacuna(int a[], size_t n) {
    if (n < 2) return 0;
    qsort(a, n, sizeof *a, cmp_int);
    int melhor = 0;
    for (size_t i = 1; i < n; i++)
        if (a[i] - a[i - 1] > melhor) melhor = a[i] - a[i - 1];
    return melhor;
}

static int cmp_concat(const void *x, const void *y) {

Por que nenhuma ordenação por comparação é mais rápida que n log n

Todo algoritmo que ordena apenas por comparações pode ser representado como uma árvore de decisão: cada nó interno é uma comparação entre dois elementos, cada folha é uma permutação possível da saída. Um vetor de n elementos tem n! permutações, e todas precisam aparecer como folhas, porque qualquer uma delas pode ser a resposta correta.

Uma árvore binária de altura h tem no máximo 2h folhas. Logo, 2h ≥ n!, e portanto h ≥ log₂(n!). Pela aproximação de Stirling, log₂(n!) ≈ n log₂ n − 1,44 n, que é Θ(n log n). Esse é o limite inferior para qualquer ordenação baseada em comparações: nenhum algoritmo desse tipo consegue fazer menos de n log n comparações no pior caso (KNUTH, 1998, v. 3, seção 5.3.1).

Exemplo pequeno: com n = 3, há 3! = 6 permutações. Como 2² = 4 < 6 ≤ 2³ = 8, são necessárias pelo menos 3 comparações. A inserção faz exatamente 3 no pior caso, então é ótima para esse tamanho.

Como escapar do limite? Não comparando. A ordenação por contagem e a radix sort (ordenar dígito a dígito) usam o conteúdo dos valores e chegam a O(n + k) ou O(d·(n + b)). Essa é a razão de a contagem aparecer no início da seção.

Estabilidade: quando a ordem anterior importa

Um algoritmo é estável se elementos com a mesma chave continuam na ordem relativa em que estavam antes. Parece um detalhe, mas é o que permite ordenar por várias colunas em sequência, como fazem as planilhas quando você clica em um cabeçalho.

Exemplo: uma lista de funcionários ordenada por nome. Queremos agrupá-la por departamento, mantendo os nomes em ordem alfabética dentro de cada departamento. Basta ordenar por departamento usando um algoritmo estável, aplicado à lista já ordenada por nome. A estabilidade garante que, dentro de cada departamento, os nomes continuem em ordem. Com um algoritmo instável (como a seleção), essa garantia se perde.

Exemplos avançados de ordenação em C

Quatro problemas reais que usam ordenação, cada um com uma técnica diferente. O arquivo 04-avancado.c compila com os mesmos avisos como erro e contém todas as funções.

Intercalar logs de vários servidores

Cada servidor grava seus logs em ordem de horário. Para analisar o incidente como um todo, intercalamos os k fluxos. Intercalar dois a dois, repetidamente, custa O(n · k) no total; uma fila de prioridade (heap) reduziria para O(n log k), e é o que sistemas de log fazem de verdade.

Em C · 04-avancado.c · ex-a

static size_t intercalar2(const int a[], size_t n, const int b[], size_t m, int out[]) {
        size_t i = 0, j = 0, k = 0;
        while (i < n && j < m) out[k++] = a[i] <= b[j] ? a[i++] : b[j++];
        while (i < n) out[k++] = a[i++];
        while (j < m) out[k++] = b[j++];
        return k;
    }
    
    /* Logs de k servidores, cada um já ordenado por horário. Intercala todos, dois a dois */
    static size_t intercalar_k(const int *listas[], const size_t tam[], size_t k, int out[]) {
        size_t total = 0;
        int *atual = malloc(sizeof(int) * 64), *prox = malloc(sizeof(int) * 64);
        if (!atual || !prox) exit(1);
        for (size_t i = 0; i < tam[0]; i++) atual[i] = listas[0][i];
        total = tam[0];
        for (size_t l = 1; l < k; l++) {
            total = intercalar2(atual, total, listas[l], tam[l], prox);
            int *t = atual; atual = prox; prox = t;
        }
        memcpy(out, atual, total * sizeof *out);
        free(atual);
        free(prox);
        return total;
    }

Ordenação externa simulada

Quando os dados não cabem na memória (um arquivo de 100 GB, por exemplo), o sistema lê blocos que cabem, ordena cada um e grava uma "corrida" ordenada no disco. Depois intercala as corridas. É assim que bancos de dados ordenam tabelas grandes (como o PostgreSQL faz em seus sorts). Aqui simulamos o processo em memória, com blocos de 8 itens.

Em C · 04-avancado.c · ex-b

static int cmp_int(const void *x, const void *y) {
        int a = *(const int *)x, b = *(const int *)y;
        return (a > b) - (a < b);
    }
    
    static size_t ordenacao_externa(const int dados[], size_t n, size_t bloco, int out[]) {
        size_t blocos = (n + bloco - 1) / bloco;
        size_t pos[32] = {0}, fim[32];
        for (size_t b = 0; b < blocos; b++) {
            size_t ini = b * bloco, cnt = (ini + bloco <= n) ? bloco : n - ini;
            memcpy(&out[ini], &dados[ini], cnt * sizeof *out);   /* "lê o bloco do disco" */
            qsort(&out[ini], cnt, sizeof *out, cmp_int);          /* ordena na memória */
            fim[b] = ini + cnt;
            pos[b] = ini;
        }
        int *res = malloc(n * sizeof *res);
        if (!res) exit(1);
        for (size_t k = 0; k < n; k++) {                          /* intercalação de k blocos */
            size_t melhor = (size_t)-1;
            for (size_t b = 0; b < blocos; b++)
                if (pos[b] < fim[b] && (melhor == (size_t)-1 || out[pos[b]] < out[pos[melhor]]))
                    melhor = b;
            res[k] = out[pos[melhor]++];
        }
        memcpy(out, res, n * sizeof *out);
        free(res);
        return blocos;
    }

Remover duplicados de um cadastro

Depois de ordenar, valores repetidos ficam vizinhos, então basta comparar cada um com o anterior. É a base de desduplicação de contatos, e-mails ou produtos. Custo O(n log n), dominado pela ordenação.

Em C · 04-avancado.c · ex-c

static size_t remover_duplicados(int a[], size_t n, size_t *repetidos) {
        qsort(a, n, sizeof *a, cmp_int);
        size_t w = 0;
        *repetidos = 0;
        for (size_t r = 0; r < n; r++) {
            if (w > 0 && a[w - 1] == a[r]) { (*repetidos)++; continue; }
            a[w++] = a[r];
        }
        return w;
    }

Quicksort híbrido de produção

Mediana de três como pivô, partição sobre o menor lado (para limitar a profundidade da pilha) e insertion sort nos subvetores pequenos. Essas três escolhas juntas são o que torna quicksorts reais tão rápidos quanto o teórico sugere.

static void insercao(int a[], long lo, long hi) {
        for (long i = lo + 1; i <= hi; i++) {
            int chave = a[i];
            long j = i - 1;
            while (j >= lo && a[j] > chave) { a[j + 1] = a[j]; j--; }
            a[j + 1] = chave;
        }
    }
    
    static void trocar(int *x, int *y) { int t = *x; *x = *y; *y = t; }
    
    static void quick_hibrido(int a[], long lo, long hi) {
        while (hi - lo >= 8) {                       /* subvetor grande: particiona */
            long mid = lo + (hi - lo) / 2;
            if (a[mid] < a[lo]) trocar(&a[mid], &a[lo]);
            if (a[hi] < a[lo]) trocar(&a[hi], &a[lo]);
            if (a[hi] < a[mid]) trocar(&a[hi], &a[mid]);
            trocar(&a[mid], &a[hi - 1]);             /* mediana de três vai para hi-1 */
            int pivo = a[hi - 1];
            long i = lo, j = hi - 1;
            for (;;) {
                while (a[++i] < pivo) { }
                while (a[--j] > pivo) { }
                if (i >= j) break;
                trocar(&a[i], &a[j]);
            }
            trocar(&a[i], &a[hi - 1]);
            if (i - lo < hi - i) { quick_hibrido(a, lo, i - 1); lo = i + 1; }
            else { quick_hibrido(a, i + 1, hi); hi = i - 1; }
        }
        insercao(a, lo, hi);                         /* subvetor pequeno: insertion é mais rápida */
    }

Onde a ordenação aparece no dia a dia

  • Lojas e buscadores: ordenar resultados por preço, avaliação ou relevância. Para mostrar só os 10 primeiros, não é preciso ordenar tudo: usa-se seleção parcial (quickselect ou heap).
  • Extratos e agendas: transações por data, compromissos por horário. A ordenação estável mantém a ordem de chegada entre eventos simultâneos.
  • Bancos de dados: toda cláusula ORDER BY é uma ordenação. Quando a tabela não cabe na memória, o banco usa ordenação externa; joins de tabelas grandes usam o sort-merge join.
  • Big data: no MapReduce (Hadoop), a fase de shuffle ordena as chaves intermediárias antes de entregá-las aos redutores. A intercalação de logs do exemplo A é o mesmo raciocínio em pequena escala.
  • Bibliotecas que você já usa: sorted() em Python é timsort; Collections.sort() em Java, para objetos, também. A qsort() da C padrão não garante estabilidade, e isso é um detalhe que costuma surpreender.
  • Deduplicação: limpar listas de contatos, detectar compras repetidas ou arquivos idênticos (comparando conteúdos ordenados ou hashes), como no exemplo C.
  • Interfaces: clicar no cabeçalho de uma tabela para ordenar por uma coluna depende de ordenação estável, para que a última ordenação não desfaça a anterior.

Exercícios propostos

P1. Você tem registros (nome, idade) e quer ordenar por idade, mantendo a ordem alfabética dos nomes dentro de cada idade. Qual algoritmo usar?

Resposta: ordene primeiro por nome e depois, com um algoritmo estável (inserção ou merge sort), por idade. Com seleção ou quicksort, a ordem por nome se perderia.

P2. Um vetor tem 10 milhões de inteiros entre 0 e 100. Qual algoritmo você escolhe?

Resposta: contagem. O(n + k) = O(10⁷ + 10²) é quase linear, enquanto um algoritmo por comparação precisa de cerca de n log n ≈ 2,3 · 10⁸ comparações.

Teste seus conhecimentos

Qual algoritmo garante O(n log n) em todos os casos?

Correto. A recorrência T(n) = 2T(n/2) + O(n) não depende da entrada. O quicksort só é O(n log n) em média.

Por que a inserção é O(n) no melhor caso?

Correto. O laço interno para na primeira comparação, então cada elemento custa O(1), e o total é O(n).

Qual é a principal desvantagem de contagem, apesar de sua velocidade?

Correto. O custo O(n + k) só é bom se k não for muito maior que n. Para valores de 64 bits, o vetor de contagem seria impraticável.

O que levar desta página

  • Cada algoritmo é um invariante: descubra qual região está correta a cada passo.
  • Bolha, seleção e inserção são O(n²) no pior caso; quicksort e merge sort são O(n log n) na média ou sempre.
  • Estabilidade, espaço e adaptatividade decidem a escolha, não só a velocidade.
  • Ordenar é uma ferramenta: muitos problemas ficam mais simples depois de ordenados.
