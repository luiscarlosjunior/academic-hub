Tópico 4 · Algoritmos de ordenação

Ordenar é reorganizar uma sequência para que a[0] ≤ a[1] ≤ … ≤ a[n−1]. É um problema central: sem ordem, busca binária, detecção de duplicados, junção de dados e quase todo relatório ficam caros. Por isso, ordenação é o terreno onde se aprendem as ideias de projeto de algoritmos: invariantes, divisão e conquista, partição e análise de pior caso.

Objetivos desta página. Ao final, você deve conseguir:

  • explicar, para cada algoritmo, o invariante que vale ao fim de cada passo;
  • calcular os custos de melhor, médio e pior caso, e o espaço auxiliar;
  • implementar bolha, seleção, inserção, quicksort, merge sort e contagem em C;
  • escolher um algoritmo considerando estabilidade, memória e distribuição dos dados.

Teoria: invariantes e critérios de escolha

Quase todo algoritmo de ordenação mantém um invariante: uma região do vetor já está correta, e a cada passo essa região cresce. Entender o invariante é entender o algoritmo. Na seleção, o prefixo a[0..i−1] contém os menores valores, já na posição final. Na inserção, o prefixo está ordenado, mas ainda não é o resultado final. Na bolha, o sufixo já contém os maiores.

Três critérios separam os algoritmos na prática. Estabilidade: elementos iguais mantêm a ordem relativa, o que importa ao ordenar por mais de uma chave. Espaço: in place usa O(1) ou O(log n) extra. Adaptatividade: o algoritmo fica rápido quando o vetor já está quase ordenado. Knuth (1998, v. 3) classifica os métodos com essa visão.

Algoritmo 1 · Bolha (bubble sort)

Percorre o vetor comparando vizinhos e troca os que estão fora de ordem. Ao fim da primeira passagem, o maior valor está na última posição, como uma bolha que sobe. A passagem p percorre n − 1 − p pares, e a soma dá n(n−1)/2 comparações: O(n²). A flag trocou permite parar cedo quando o vetor já está ordenado, o que dá O(n) no melhor caso.

Em C · 04-ordenacao.c · op:bolha

static void bolha(int a[], size_t n) {
    for (size_t p = 0; p + 1 < n; p++) {
        int trocou = 0;
        for (size_t j = 0; j + 1 < n - p; j++)
            if (a[j] > a[j + 1]) {
                trocar(&a[j], &a[j + 1]);
                trocou = 1;
            }
        if (!trocou) break;                 /* já ordenado: parada antecipada */
    }
}

Algoritmo 2 · Seleção

Em cada passagem, encontra o menor valor da parte não ordenada e o troca com a primeira posição dela. O custo é sempre n(n−1)/2 comparações, mesmo com o vetor já ordenado, porque o algoritmo não tem como saber disso sem olhar. Faz poucas trocas (no máximo n − 1), o que pode importar quando escrever é caro. A troca não preserva estabilidade: um valor pode passar por cima de um igual.

Em C · 04-ordenacao.c · op:selecao

static void selecao(int a[], size_t n) {
    for (size_t i = 0; i + 1 < n; i++) {
        size_t menor = i;
        for (size_t j = i + 1; j < n; j++)
            if (a[j] < a[menor]) menor = j;
        trocar(&a[i], &a[menor]);
    }
}

Algoritmo 3 · Inserção

É como organizar cartas na mão: pegamos a próxima e a encaixamos no lugar certo entre as já ordenadas, deslocando as maiores. No pior caso (ordem inversa), cada elemento atravessa toda a parte ordenada: O(n²). No melhor caso (já ordenado), cada elemento faz uma comparação: O(n). Por isso, a inserção é o algoritmo preferido para vetores pequenos ou quase ordenados, e é usada dentro de algoritmos mais rápidos, como o timsort, para blocos pequenos.

Em C · 04-ordenacao.c · op:insercao

static void insercao(int a[], size_t n) {
    for (size_t i = 1; i < n; i++) {
        int chave = a[i];
        size_t j = i;
        while (j > 0 && a[j - 1] > chave) {
            a[j] = a[j - 1];
            j--;
        }
        a[j] = chave;
    }
}

Algoritmo 4 · Quicksort

Escolhe um pivô, particiona o vetor em menores e maiores e aplica o mesmo processo a cada lado. A partição de Lomuto usada aqui coloca o pivô na posição definitiva. Se o pivô divide bem, a recursão tem altura O(log n) e cada nível custa O(n): total O(n log n). Se o pivô é sempre o extremo, a altura vira n e o total sobe para O(n²). Em média, com pivô escolhido ao acaso, o resultado é O(n log n) (HOARE, 1962). A animação mostra as partições.

Em C · 04-ordenacao.c · op:quicksort

static void quicksort(int a[], long lo, long hi) {
    if (lo >= hi) return;
    int pivo = a[hi];
    long i = lo;
    for (long j = lo; j < hi; j++)
        if (a[j] < pivo) {
            trocar(&a[i], &a[j]);
            i++;
        }
    trocar(&a[i], &a[hi]);
    quicksort(a, lo, i - 1);
    quicksort(a, i + 1, hi);
}

Algoritmo 5 · Merge sort

Divide o vetor ao meio, ordena as duas metades recursivamente e intercala as duas. A recorrência T(n) = 2T(n/2) + O(n) tem solução O(n log n) em todos os casos, sem exceção (CORMEN et al., 2022, cap. 2). O custo é espaço auxiliar O(n) e a intercalação é estável, desde que, em empate, o elemento da esquerda seja copiado primeiro. Este é o padrão divisão e conquista que aparece na página 11 e nos exercícios de inversões.

Em C · 04-ordenacao.c · op:mergesort

static void intercalar(int a[], int aux[], size_t lo, size_t mid, size_t hi) {
    size_t i = lo, j = mid, k = lo;
    while (i < mid && j < hi) aux[k++] = (a[i] <= a[j]) ? a[i++] : a[j++];
    while (i < mid) aux[k++] = a[i++];
    while (j < hi) aux[k++] = a[j++];
    memcpy(&a[lo], &aux[lo], (hi - lo) * sizeof *a);
}

static void merge_rec(int a[], int aux[], size_t lo, size_t hi) {
    if (hi - lo < 2) return;
    size_t mid = lo + (hi - lo) / 2;
    merge_rec(a, aux, lo, mid);
    merge_rec(a, aux, mid, hi);
    intercalar(a, aux, lo, mid, hi);
}

static int merge_sort(int a[], size_t n) {
    if (n < 2) return 1;
    int *aux = malloc(n * sizeof *aux);      /* O(n) de memória auxiliar */
    if (aux == NULL) return 0;
    merge_rec(a, aux, 0, n);
    free(aux);
    return 1;
}

Algoritmo 6 · Ordenação por contagem

Não compara elementos. Conta quantas vezes cada valor aparece e reescreve o vetor em ordem. Custa O(n + k), com k o intervalo de valores, e por isso só serve para inteiros em faixa pequena. Ele quebra a barreira de Ω(n log n) das ordenações por comparação, porque usa informação sobre os valores, não só a ordem entre eles.

Em C · 04-ordenacao.c · op:contagem

static void contagem(int a[], size_t n, int k) {   /* valores em 0..k-1 */
    size_t *freq = calloc((size_t)k, sizeof *freq);
    if (freq == NULL) return;
    for (size_t i = 0; i < n; i++) freq[a[i]]++;
    size_t pos = 0;
    for (int v = 0; v < k; v++)
        for (size_t c = 0; c < freq[v]; c++) a[pos++] = v;
    free(freq);
}

Padrões de resolução ligados à ordenação

Ordenar para simplificar

Ordenar custa O(n log n) e pode tornar um problema quadrático em O(n log n) ou O(n) (exercícios 1 e 3, e página 11).

Divisão e conquista

Dividir, resolver as metades e combinar. Merge sort combina por intercalação; a contagem de inversões combina contando cruzamentos.

Partição

Separar por um critério em O(n) e então agir sobre cada lado. Base do quicksort e da seleção do k-ésimo menor.

Ordenar por chave composta

Para ordenar por nome e depois por idade, use um algoritmo estável: ordene primeiro pela chave secundária e depois pela principal.

Exercícios resolvidos

Exercício 1: anagramas

Enunciado. Dois textos são anagramas se um é reordenação das letras do outro. Verifique se dois textos são anagramas.

Ideia. Se ordenarmos as letras dos dois textos, anagramas produzem sequências idênticas. A comparação final é linear. Para textos curtos, a inserção é suficiente. Um caminho alternativo, com contagem de letras, leva a O(n + 256) e é o que se usa em produção.

Complexidade: O(n²) com inserção (dominado pelas duas ordenações curtas); O(n) com contagem.

Em C · 04-ordenacao.c · ex:anagramas

static void ordenar_chars(char s[], size_t n) {
    for (size_t i = 1; i < n; i++) {
        char c = s[i];
        size_t j = i;
        while (j > 0 && s[j - 1] > c) {
            s[j] = s[j - 1];
            j--;
        }
        s[j] = c;
    }
}

static int anagramas(const char *x, const char *y) {
    size_t n = strlen(x);
    if (n != strlen(y) || n >= 64) return 0;   /* limite do exemplo */
    char a[64], b[64];
    memcpy(a, x, n);
    memcpy(b, y, n);
    ordenar_chars(a, n);
    ordenar_chars(b, n);
    return memcmp(a, b, n) == 0;
}

Exercício 2: contar inversões

Enunciado. Uma inversão é um par de índices i < j com a[i] > a[j]. Conte as inversões de um vetor em O(n log n).

Padrão: divisão e conquista, reaproveitando o merge sort. Inversões dentro de cada metade são contadas pela recursão. Inversões entre as metades aparecem na intercalação: quando a[j] (da direita) é menor que a[i] (da esquerda), ele forma uma inversão com todos os elementos restantes da metade esquerda, que são mid − i.

Exemplo: em {2, 4, 1, 3, 5}, as inversões são (2,1), (4,1) e (4,3): total 3.

Complexidade: O(n log n) de tempo, O(n) de espaço auxiliar.

Em C · 04-ordenacao.c · ex:inversoes

static long contar_inv(int a[], int aux[], size_t lo, size_t hi) {
    if (hi - lo < 2) return 0;
    size_t mid = lo + (hi - lo) / 2;
    long c = contar_inv(a, aux, lo, mid) + contar_inv(a, aux, mid, hi);
    size_t i = lo, j = mid, k = lo;
    while (i < mid && j < hi) {
        if (a[i] <= a[j]) {
            aux[k++] = a[i++];
        } else {
            aux[k++] = a[j++];
            c += (long)(mid - i);            /* a[j] é menor que todo o resto da metade esquerda */
        }
    }
    while (i < mid) aux[k++] = a[i++];
    while (j < hi) aux[k++] = a[j++];
    memcpy(&a[lo], &aux[lo], (hi - lo) * sizeof *a);
    return c;
}

static long inversoes(int a[], size_t n) {
    if (n < 2) return 0;
    int *aux = malloc(n * sizeof *aux);
    if (aux == NULL) return -1;
    long c = contar_inv(a, aux, 0, n);
    free(aux);
    return c;
}

Exercício 3: k-ésimo menor elemento

Enunciado. Encontre o k-ésimo menor valor (começando em zero) sem ordenar o vetor inteiro.

Ideia. Quickselect: particione em torno de um pivô. Se o pivô caiu exatamente na posição k, ele é a resposta. Se k está à esquerda, ignoramos a direita, e vice-versa. Cada passo descarta uma parte, então, em média, o custo é a soma n + n/2 + n/4 + … = O(n). No pior caso, como no quicksort, é O(n²).

Complexidade: O(n) médio, O(n²) pior caso, O(1) de espaço.

Em C · 04-ordenacao.c · ex:kesimo

static int kesimo(int a[], size_t n, size_t k) {  /* k começa em 0 */
    size_t lo = 0, hi = n - 1;
    while (lo < hi) {
        int pivo = a[hi];
        size_t i = lo;
        for (size_t j = lo; j < hi; j++)
            if (a[j] < pivo) {
                trocar(&a[i], &a[j]);
                i++;
            }
        trocar(&a[i], &a[hi]);
        if (k == i) return a[i];
        if (k < i) hi = i - 1;
        else lo = i + 1;
    }
    return a[lo];
}

Exercícios propostos

P1. Você tem registros (nome, idade) e quer ordenar por idade, mantendo a ordem alfabética dos nomes dentro de cada idade. Qual algoritmo usar?

Resposta: ordene primeiro por nome e depois, com um algoritmo estável (inserção ou merge sort), por idade. Com seleção ou quicksort, a ordem por nome se perderia.

P2. Um vetor tem 10 milhões de inteiros entre 0 e 100. Qual algoritmo você escolhe?

Resposta: contagem. O(n + k) = O(10⁷ + 10²) é quase linear, enquanto um algoritmo por comparação precisa de cerca de n log n ≈ 2,3 · 10⁸ comparações.

Teste seus conhecimentos

Qual algoritmo garante O(n log n) em todos os casos?

Correto. A recorrência T(n) = 2T(n/2) + O(n) não depende da entrada. O quicksort só é O(n log n) em média.

Por que a inserção é O(n) no melhor caso?

Correto. O laço interno para na primeira comparação, então cada elemento custa O(1), e o total é O(n).

Qual é a principal desvantagem de contagem, apesar de sua velocidade?

Correto. O custo O(n + k) só é bom se k não for muito maior que n. Para valores de 64 bits, o vetor de contagem seria impraticável.

O que levar desta página

  • Cada algoritmo é um invariante: descubra qual região está correta a cada passo.
  • Bolha, seleção e inserção são O(n²) no pior caso; quicksort e merge sort são O(n log n) na média ou sempre.
  • Estabilidade, espaço e adaptatividade decidem a escolha, não só a velocidade.
  • Ordenar é uma ferramenta: muitos problemas ficam mais simples depois de ordenados.
