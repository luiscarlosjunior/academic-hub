Tópico 1 · Complexidade: tempo, espaço e Big-O

Antes de escolher uma estrutura de dados, é preciso responder a uma pergunta: quanto isso custa quando os dados crescem? Medir em segundos é frágil, porque o resultado depende da máquina, do compilador e da carga do sistema. A análise de complexidade conta, em vez disso, quantas operações elementares o algoritmo executa em função do tamanho da entrada, n. Essa contagem é a mesma em qualquer computador e mostra como o custo cresce.

Objetivos desta página. Ao final, você deve conseguir:

  • definir Big-O, Ω e Θ e explicar o que significa “crescimento assintótico”;
  • calcular a complexidade temporal de laços, sequências e chamadas recursivas;
  • distinguir complexidade espacial (memória auxiliar) de temporal;
  • reconhecer pior caso, caso médio e custo amortizado;
  • medir operações num programa em C e comparar com a previsão teórica.

A notação assintótica

Dizemos que f(n) = O(g(n)) quando existem constantes c > 0 e n₀ tais que f(n) ≤ c · g(n) para todo n ≥ n₀. Em palavras: para entradas grandes, f cresce no máximo na proporção de g. A constante c absorve detalhes da máquina; o n₀ ignora o comportamento em entradas pequenas. Por isso Big-O descreve o crescimento, não um valor exato (CORMEN et al., 2022, cap. 3).

As notações irmãs são Ω (limite inferior: f(n) ≥ c · g(n)) e Θ (limite justo: vale Big-O e Ω ao mesmo tempo). Quando dizemos que a busca binária é O(log n), estamos dando um teto; quando dizemos que ela é Θ(log n) no pior caso, estamos afirmando que não há teto menor. A notação foi popularizada na computação por Knuth (1976).

Regras para calcular

  • Constantes saem: O(3n) = O(n).
  • Fica o termo dominante: O(n² + n + 10) = O(n²).
  • Sequências somam: um laço O(n) seguido de um laço O(n²) resulta em O(n²).
  • Aninhamentos multiplicam: um laço de n dentro de um laço de n dá O(n²).
  • Divisão ao meio repetida até chegar a 1 dá O(log n).

Complexidade temporal: contando operações

A complexidade temporal conta operações, não segundos. Para cada trecho de código, pergunte quantas vezes ele executa em função de n? Um comando isolado é O(1). Um laço que percorre a entrada é O(n). Um laço dentro de outro laço, ambos de n, é O(n²). Quando o tamanho da entrada é dividido ao meio a cada passo, o número de passos é O(log n).

Constante e linear

Ler a[0] custa o mesmo para qualquer n. Somar todos os elementos custa uma operação por elemento.

Em C · 01-complexidade.c · op:constante

static int primeiro(const int a[]) {
    ops++;
    return a[0];
}

Em C · 01-complexidade.c · op:linear

static long soma(const int a[], int n) {
    long s = 0;
    for (int i = 0; i < n; i++) {
        ops++;
        s += a[i];
    }
    return s;
}

Quadrática e logarítmica

Comparar cada par de elementos exige um laço dentro de outro: n × n operações. Já metades divide o intervalo por 2 a cada volta, então executa log₂ n vezes.

Em C · 01-complexidade.c · op:quadratico

static int pares_iguais(const int a[], int n) {
    int c = 0;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++) {
            ops++;
            if (a[i] == a[j]) c++;
        }
    return c;
}

Em C · 01-complexidade.c · op:logaritmico

static int metades(int n) {
    int k = 0;
    for (int m = n; m > 1; m /= 2) {
        ops++;
        k++;
    }
    return k;
}

Complexidade espacial: memória auxiliar

A complexidade espacial conta a memória extra usada além da entrada. Uma função que usa algumas variáveis locais é O(1). Uma recursão cria um quadro na pilha de execução para cada chamada pendente: se a profundidade é n, o espaço é O(n), mesmo que o tempo também seja O(n). Um vetor auxiliar de tamanho n também custa O(n). Não confunda: o espaço que a própria entrada já ocupa não entra na conta.

Em C · 01-complexidade.c · op:fatorial-rec

static unsigned long long fat_rec(unsigned n) {
    return n <= 1 ? 1 : n * fat_rec(n - 1);
}

Em C · 01-complexidade.c · op:fatorial-it

static unsigned long long fat_it(unsigned n) {
    unsigned long long r = 1;
    for (unsigned i = 2; i <= n; i++) r *= i;
    return r;
}

Padrão de resolução: como analisar um trecho de código

  1. Identifique o que cresce. Qual variável representa o tamanho da entrada? Ela pode aparecer em mais de um lugar (n, m, linhas, colunas).
  2. Conte os laços. Laço sobre a entrada: n. Laço dentro de laço: produto. Laço que divide ou multiplica o índice: log.
  3. Junte as partes. Sequências somam (fica o maior termo); aninhamentos multiplicam.
  4. Procure saídas antecipadas. Um break pode mudar o pior caso, mas não o melhor.
  5. Olhe a memória. Vetores auxiliares e recursão contam no espaço; variáveis escalares não.

Esse roteiro se repete em todas as páginas da disciplina.

Exercícios resolvidos

Exercício 1: laço triangular

Enunciado. Qual é a complexidade de triangular(n)?

Ideia. O laço interno roda i vezes, para i = 0, 1, …, n−1. A soma é 0 + 1 + … + (n−1) = n(n−1)/2. Esse termo tem n² como dominante, então a complexidade é O(n²). A constante 1/2 é descartada. O programa confirma: triangular(5) = 10 = 5·4/2.

Em C · 01-complexidade.c · ex:1

static long triangular(int n) {
    long c = 0;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < i; j++)
            c++;
    return c;
}

Exercício 2: laço com passo multiplicativo

Enunciado. Analise n_log_n(n).

Ideia. O laço externo multiplica i por 2: roda log₂ n vezes. Cada volta executa um laço interno de n passos. O total é n · log₂ n, ou seja, O(n log n). Para n = 8, o resultado é 24 = 8 · 3.

Em C · 01-complexidade.c · ex:2

static long n_log_n(int n) {
    long c = 0;
    for (int i = 1; i < n; i *= 2)
        for (int j = 0; j < n; j++)
            c++;
    return c;
}

Exercício 3: duas partes em sequência

Enunciado. Analise misto(n).

Ideia. Primeiro vem um laço de n passos (O(n)); depois um laço aninhado (O(n²)). Em sequência, os custos somam: n + n². Na soma, o termo de maior ordem domina, então o resultado é O(n²). Para n = 4: 4 + 16 = 20.

Em C · 01-complexidade.c · ex:3

static long misto(int n) {
    long c = 0;
    for (int i = 0; i < n; i++) c++;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            c++;
    return c;
}

Exercícios propostos

P1. Qual a complexidade de for (i = 1; i < n; i *= 2) for (j = 1; j < i; j++)?

Resposta: O(n). O laço interno roda i − 1 vezes; com i = 1, 2, 4, …, a soma é 0 + 1 + 3 + 7 + … ≈ 2n. A soma geométrica domina.

P2. Uma função chama a si mesma duas vezes com n − 1 a cada chamada, até n = 0. Qual o tempo e o espaço?

Resposta: tempo O(2ⁿ), porque a árvore de chamadas tem cerca de 2ⁿ nós. Espaço O(n), que é a profundidade máxima da pilha. Esse é um caso típico de problema que pede programação dinâmica para cair em O(n).

Teste seus conhecimentos

Um laço de n passos contém outro laço que percorre sempre 5 elementos fixos. Qual é a complexidade?

Correto. O laço interno tem custo constante (5 passos), então o total é 5n. A constante 5 é descartada e o resultado é O(n). O laço interno não cresce com n, por isso não há produto de dois termos variáveis.

Qual afirmação sobre o espaço da versão recursiva do fatorial é correta?

Correto. A profundidade da recursão é n, e cada chamada pendente ocupa um quadro na pilha de execução.

O que o pior caso de um algoritmo descreve?

Correto. É a garantia usada na prática: nenhuma entrada de tamanho n exige mais operações do que o pior caso.

O que levar desta página

  • Big-O descreve o crescimento no pior caso, descartando constantes e termos menores.
  • Laços em sequência somam; aninhados multiplicam; divisões ao meio dão log n.
  • A complexidade espacial conta memória auxiliar: recursão custa O(profundidade) e vetores auxiliares custam O(tamanho).
  • Meça com contadores no código para confirmar a análise, como no programa desta página.
